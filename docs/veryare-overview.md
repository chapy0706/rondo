# veryare 全体像（参照資料）

電車内での整理用。ADR 0020〜0029を1枚に凝縮した。

---

## 空間の構造

```
待機ルーム(約3.6m四方、8畳の目安、5人が手狭にならない広さ)
  └─ 鬼希望エリア(中央、円形)

ステージ(実際の隠れんぼの舞台。建物パーツで構成、issue-29)
```

待機ルームとステージは別空間。鬼は探索フェーズが始まるまでステージを一切見ない。これにより、鬼が隠れ場所を事前に把握してしまう(ADR 0028の禁止事項に触れる)ことを構造的に防げる。

## フェーズの流れ

```
全員: 待機ルームにいる
  │
  ▼
鬼選出フェーズ(10秒)
  全員: 待機ルーム内を移動。中央の鬼希望エリアに入れば立候補
  │  ← 立候補者がいればその中から、いなければ全員からランダムに1人選出
  ▼
  隠れ側: 待機ルームを出てステージへ移動
  鬼    : 待機ルームに残る
  │
準備移動フェーズ(20秒)
  隠れ側: ステージ上を自由移動して場所を決める
  鬼    : 待機ルーム内でペイント(暇つぶし、保存されない)
  │  ← ここで全員の座標が確定 → 被り判定(ADR 0026)
  ▼
ペイントフェーズ(20秒)
  隠れ側: 擬態ペイント（自分にしか見えない、ADR 0025）
  鬼    : 引き続き待機ルーム
  │  ← ここでストロークをサーバーに一括送信(ADR 0025)
  ▼
  鬼: 待機ルームを出てステージへ移動
  │
探索フェーズ(20秒単位・基本40秒・作成時に選択・一覧では非表示)
  隠れ側: 移動不可（ADR 0024）。見つかると観戦モードへ(ADR 0027)
  鬼    : ステージを自由移動、射撃(ADR 0022/issue-27)
  │
  ▼
終了
  「まだ隠れている」= 接続中かつ未発見、が0人 → 鬼の勝ち
  時間切れの時点で1人以上残っていれば     → 隠れ側の勝ち
  鬼が再接続猶予(10秒)を超えて切断        → 即座に隠れ側の勝ち
```

---

## 鬼の選出

待機ルーム中央に「鬼希望エリア」（禁止エリアとは別の、単純な円形範囲）を用意。鬼選出フェーズ(10秒)の間に立候補者を募り、いればその中から、いなければ全員からランダムに1人を選ぶ。

---

## 誰が何を知っているか(情報の権威)

| 役割 | 見えるもの | 見えないもの |
|---|---|---|
| 鬼 | 自分の視点、探索中の隠れ側(見つけたら) | 隠れ側全員の座標(常時) |
| 隠れ側(隠れ中) | 自分の視点、自分のペイント | 他の隠れ側の座標、鬼の視点 |
| 観戦者(見つかった後) | 鬼の視点(カメラ) | まだ隠れている全員の座標 |

これを実現するのが ADR 0021(プレイヤー限定メッセージ) / issue-23。既存のブロードキャスト配信(全員に同じもの)に、宛先を絞る配信を1種類だけ追加する形。

## 入力

ADR 0020 / issue-22。VirtualPad を2本に拡張。

```
useVirtualPad("move")  … 移動
useVirtualPad("look")  … 視点
```

既存ゲーム(テトリス等)は名前省略で今までどおり動く。

---

## 当たり判定

ADR 0022 / issue-27。**クライアント申告 + サーバー簡易検証**。

```
鬼クライアント: 「このプレイヤーに当てた」と申告
サーバー      : 距離が妥当か + リロード3秒経ってるか、だけ検証
```

厳密なレイキャスト(壁越しの判定など)はしない。身内発表会なので割り切り。

---

## 被り判定・禁止エリア

ADR 0026 / issue-26。

- **被り**: 準備移動フェーズ終了時、プレイヤー同士の球体が重なっていたら**両者失格**
- **禁止エリア**: オブジェクトのバウンディングボックスを自動生成 → 縮小(★何%か未決定、目安7〜8割)したものが禁止エリア
- 触れている間はカウントダウン表示、**5秒**で近くの固定候補地点(5〜6箇所)へ強制移動
- 床は寝そべるポーズのときだけ同様に許可、他は完全禁止

→ 素材が届く前に、仮の座標でテストだけ先に書ける(issue-26 段階1)。

## 品質基準(ADR 0028)

veryare の受け入れ条件は、これ一本だけ。

> 1. 鬼が隠れ側を意図せず操作・位置を教えること
> 2. 隠れ側が鬼に危害を加えること
> 3. その他チート行為とみなされる挙動

これに反しなければ合格。見た目の粗さ・カメラの乱れ・当たり判定の甘さは許容。

理由: 探索フェーズ中は隠れ側が動けない(ADR 0024)ので、鬼側の不具合が公平性を壊すことは構造的にない。

## 未決定事項

現時点でなし。今回のやり取りで最後の1つ(鬼選出フェーズの時間)も確定した。

決まっているもの(全体まとめ):
- 空間: 待機ルーム(約3.6m四方・8畳目安・5人収容)とステージは別空間。鬼は探索開始まで一切ステージを見ない
- 鬼選出フェーズ: 10秒。待機ルーム中央の鬼希望エリアへの立候補制、いなければ全員からランダム
- 探索フェーズ時間: 20秒単位・基本40秒・ルーム作成時に選択・一覧では非表示（ADR 0024）
- 時間切れ勝利条件: 隠れ側1人でも残れば隠れ側の勝ち（ADR 0024）
- 禁止エリアの縮小率: 80%固定（ADR 0026）
- ルーム定員: 5人（鬼1・隠れ4）、同時ルーム数: 最大3（ADR 0030）
- ルームの寿命: ホスト退出後も存続（ADR 0030）
- 鬼の切断: 再接続猶予を過ぎたら即座に隠れ側の勝ち（ADR 0024）
- 隠れ側の切断: 発見と同じ扱いで「まだ隠れている」集合から除く（ADR 0024）
- ルール説明: 簡易な資料をスナップショットとして使う方針

veryare の設計判断は、これで一通り出そろった。残るは実装（issue-22〜29）に進むだけ。
