# issue-46: 平屋ステージのクライアントの表示

## 背景

issue-44 で、平屋の固定ステージ（ADR 0039）のデータがサーバーに揃い、issue-29a のステージの通知で、平屋の地図のデータがクライアントに届く。クライアントの移動の規則（サーバーと同じ）、仮素材の表示（床と壁の箱）、襖の表示と開けるボタンは、issue-29c で、すべてのステージに共通の形で作る（ADR 0042）。本 issue では、それらを再利用し、平屋の glb の表示と、襖のノードの動き、屋根の切り替え、ステージの選択肢を足す。

平屋の glb（屋内本体・屋外の飾り・屋根と天井の3つ。`docs/assets.md`）は、公開リポジトリに入れない。issue-43 の素材配信で届いたものを読み込み、届かない・読めないときは、いまの仮の表示（箱と床）で動かす。

## スコープ

### このissueでやること

- 移動は、issue-29c のクライアントの移動の規則を、そのまま使う（ステージの通知の平屋の地図で動く。新しく作らない）
- 平屋の glb を読み込む
  - 屋内本体と屋外の飾りを、ステージの座標（glb の座標そのまま）に置く
  - 屋根と天井は、表示を切り替えられるようにする（TPS のカメラを遮るため、既定は隠す）
  - 戸・障子・欄間のノードを、戸の一覧の襖10組と対応づける
- 襖の開閉
  - サーバーから届く襖の開閉の状態に合わせて、襖のノードを開けた位置・閉じた位置に動かす（アニメーションの作り込みはしない）
  - 襖の近くで開ける操作（ボタン）は、issue-29c のものをそのまま使う
  - いつも開いている片開き戸は、開いた姿で置く
- 素材が無いときのフォールバック
  - glb が読めなければ、警告を出さずに、issue-29c の仮素材の表示（床と、壁の位置の箱）で動かす。移動の規則は同じ
- ステージの選択肢（ランダム間取り / 平屋）を、ロビーのルーム作成の設定に出す（通っていない機能は選択画面に出さないため、この issue で初めて出す）

### このissueでやらないこと

- 素材の配信の仕組みそのもの（issue-43）
- 家具の当たり（ADR 0039 で扱わないと決めた）
- 襖の開閉のアニメーションの作り込み、答え合わせタイムの演出の作り込み（issue-29 の範囲）
- 形の圧縮（量子化・meshopt）の組み込み（必要なら別 issue）

## 設計方針

- ADR 0034（TPS カメラ）・0035・0039 に従う
- 移動の規則は、サーバーと同じデータ・同じ規則を使う。規則は純粋関数にし、サーバーと同じテストの入力で確かめる
- 素材は公開リポジトリに入れない。テスト（`make verify`）は素材に頼らず、仮の表示で通す
- three.js の GLTFLoader（0.186.1）は、`EXT_texture_webp`・`EXT_mesh_gpu_instancing` に対応している。meshopt を使うときは MeshoptDecoder の設定が要る
- 受け入れの基準は ADR 0028 に従う

## 受け入れ条件

- 平屋を選んだルームで、平屋が表示され、壁と閉じた襖で移動が止まり、開いた襖・いつも開いている戸は通れる
- 襖の近くで開ける操作ができ、開いた襖は開けっぱなしになる。探索の開始で全部閉じ、答え合わせで全部開く（サーバーの状態に合わせて表示される）
- 屋根と天井の表示を切り替えられる（既定は隠す）
- 素材が無い環境でも、仮の表示で最後まで遊べる（同じ移動の規則）
- 平屋の地図で、issue-29c の移動の規則が、サーバーと同じテストの入力で一致する（平屋の入力を共有の見本に足して確認）
- ロビーで、ステージの選択肢（ランダム間取り / 平屋）が出る
- スマホの縦画面で動く
- `make verify` が通る（TS・Gleam 双方）

## 段階

1. 平屋の入力を、移動の規則の共有の見本に足し、issue-29c の規則で一致を確かめる
2. issue-29c の仮素材の表示で、平屋のステージを動かす
3. issue-43 の素材配信から平屋の glb を読み込み、屋根と天井の切り替えを付ける
4. 襖のノードを戸の一覧と対応づけ、開閉の状態に合わせて動かす。開ける操作を付ける
5. ロビーにステージの選択肢を出す
6. 確認手順を報告にまとめる
