# issue-29: veryare ステージ構築と統合

## 背景

これまでの issue-22〜28 で実装した各機能（入力・メッセージ配信・フェーズ・ペイント・被り判定・当たり判定・観戦モード）を、実際のステージ素材とキャラクターモデルの上で統合する。

## スコープ

### このissueでやること

- issue-26 で定義した骨格データ（10種類、部屋スロット付き）を、Three.js シーンとして描画する。廊下は骨格に沿って、部屋は割り当てられた部屋タイプの見た目で配置する
- 平屋(和風)の3Dモデル素材から、壁・床・建具のパーツを抽出し、廊下・各部屋タイプの構築に流用する
- **襖の実装**（ADR 0033）: 部屋スロットの出入り口に、開閉可能な襖を設置する。開けたら開けっぱなしとする（自動で閉じない）
- **フェーズ連動の襖リセット**: 探索フェーズ開始時に全襖を閉じる、答え合わせタイム開始時に全襖を開くイベントを実装する（room_actor 側のフェーズ通知は issue-24 で用意済み。ここではそれを受けて実際に襖を動かす）
- **答え合わせタイムの演出**: 答え合わせタイム開始時、隠れていた全プレイヤー（見つかった人・逃げ切った人の両方）を赤く点滅させる
- 待機ルーム（issue-24 で簡素に用意した空間）の作り込み。円柱形、目安半径2m（直径4m、床面積は8畳相当）、ステージとは別の空間として仕上げる
- **TPS視点のカメラ**（ADR 0034）: 自キャラを画面中央に固定し、視点パッドで周回する。距離の上限を設ける。壁へのめり込みは許容し、カメラを急に寄せたり跳ねさせたりしない（酔いの防止、ADR 0034・0035）
- **視点の切り替え**: 探索フェーズ中の隠れ側は、自分のTPSと鬼TPSを切り替えられる。見つかった後は鬼TPSのみ
- キャラクターモデル（Mixamo X Bot、glTF変換済み）の組み込み
- ポーズ（しゃがむ・寝そべる等）の切り替え
- Idle / Walk / Run のアニメーション切り替え（入力の強さに応じる）
- **ステージ選択機能**: GameManifest の roomOptions に、ステージを選ぶ項目を追加する（ADR 0031）。現時点での選択肢はランダム生成のみとする（内部で10種類の骨格からランダムに選ばれる、ADR 0032）
- 移動速度の調整: ステージのサイズと準備移動フェーズ(20秒)の時間内で、隠れ場所まで到達できる速度感を、実際に歩いて確認しながら調整する
- manifest.ts の作成と registry への登録。`launchScreen: "custom"` を設定する（issue-30 で定義した仕組みに乗る）
- **独自の起動画面**: 共通起動画面（issue-30、単純な「はじめる」ボタン）は経由せず、veryare 独自の起動画面を実装する。「サーバーを探す」「サーバーを作る」の2択とし、それぞれ既存のロビー機能（issue-11・issue-24 で実装済みのルーム一覧・新規作成）へ繋ぐ。新しいロジックは追加せず、見せ方（入口の顔）だけを veryare 専用にする
- BGM の組み込み（czz の既存アセットを流用する）

### このissueでやらないこと

- 骨格データ・部屋割り当てロジックそのもの（issue-26 で実装済み。ここではその描画のみ）
- 和風ステージなど、ランダム生成以外のステージ（将来の参考として構想のみ。今回は実装しない）
- ルール説明画面（簡易な資料をスナップショットとして使う方針。詳細は別途）

## 設計方針

- ゲーム名は veryare とする（ADR 0023）。games/veryare/ に配置する
- RealtimeGame として実装する（ADR 0004）
- 入力は issue-22 の2本パッド（移動・視点）を使う
- ステージ（迷路・待機ルームともに）は、人が違和感を覚えない現実的な縮尺とする（ADR 0031）
- BGM は czz の既存アセットをそのまま流用する。新規に作らない
- 受け入れの基準は ADR 0028 に従う

## 受け入れ条件

- ゲーム選択画面から veryare を選ぶと、共通起動画面ではなく独自の起動画面（サーバーを探す／作るの2択）が表示される
- 「サーバーを探す」「サーバーを作る」それぞれが、既存のロビー機能（ルーム一覧・新規作成）に正しく繋がる
- 骨格に沿った廊下と、割り当てられた部屋タイプが描画され、キャラクターが移動・視点操作でき、Idle/Walk/Run が切り替わる
- 壁に通り抜けできない（当たり判定が機能する）
- すべての視点がTPSで、カメラの動きが滑らかで、急な寄せや跳ねがない
- 探索フェーズ中の隠れ側が、自分のTPSと鬼TPSを切り替えられ、見つかった後は鬼TPSだけになる
- 襖が開閉でき、開けたら開けっぱなしになる
- 探索フェーズ開始時に全襖が閉じる
- 答え合わせタイム開始時に全襖が開き、隠れていた全プレイヤーが赤く点滅する
- ロビーでステージの選択肢（現状はランダムのみ）が表示される
- ペイント、被り判定、当たり判定、観戦モードが、ステージ上で一通り機能する
- 準備移動フェーズ(20秒)内で、隠れ場所まで到達できる移動速度になっている
- BGM が再生される
- ADR 0028 の基準に反する不具合がない
- `make verify` が通る

## 段階

1. manifest.ts を作り、`launchScreen: "custom"` を設定して registry に登録する（中身が空の状態でまず起動確認する）
2. 独自の起動画面（サーバーを探す／作るの2択）を実装し、既存のロビー機能に繋ぐ
3. 平屋モデルからパーツを抽出し、issue-26 の骨格データを、Three.js シーンとして描画する
4. 襖を実装し、探索フェーズ開始時の一斉クローズ、答え合わせタイム開始時の一斉オープン＋赤点滅を実装する
5. 待機ルームを作り込む
6. キャラクターモデルとポーズ・アニメーションを組み込む
7. GameManifest の roomOptions にステージ選択項目を追加する
8. issue-22〜28 の各機能をステージ上で統合する
9. 移動速度を、実際に歩いて確認しながら調整する
10. BGM を組み込む
11. 一連の流れ（起動画面→鬼選出→準備→ペイント→探索→答え合わせ→観戦→結果）を通しで確認する
