# issue-29: veryare ステージ構築と統合

## 背景

これまでの issue-22〜28 で実装した各機能（入力・メッセージ配信・フェーズ・ペイント・被り判定・当たり判定・観戦モード）を、実際のステージ素材とキャラクターモデルの上で統合する。

## スコープ

### このissueでやること

- Three.js シーンへのステージ素材（フリー素材）の配置
- 待機ルーム（issue-24 で簡素に用意した空間）の作り込み。目安8畳（約3.6m四方）、ステージとは別の空間として仕上げる
- キャラクターモデル（Mixamo X Bot、glTF変換済み）の組み込み
- ポーズ（しゃがむ・寝そべる等）の切り替え
- Idle / Walk / Run のアニメーション切り替え（入力の強さに応じる）
- manifest.ts の作成と registry への登録
- BGM の組み込み（czz の既存アセットを流用する）

### このissueでやらないこと

- ステージオブジェクトの新規モデリング（既存フリー素材をそのまま使う）
- ルール説明画面（簡易な資料をスナップショットとして使う方針。詳細は別途）

## 設計方針

- ゲーム名は veryare とする（ADR 0023）。games/veryare/ に配置する
- RealtimeGame として実装する（ADR 0004）
- 入力は issue-22 の2本パッド（移動・視点）を使う
- BGM は czz の既存アセットをそのまま流用する。新規に作らない
- 受け入れの基準は ADR 0028 に従う

## 受け入れ条件

- ゲーム選択画面から veryare が起動できる
- ステージ上でキャラクターが移動・視点操作でき、Idle/Walk/Run が切り替わる
- ペイント、被り判定、禁止エリア、当たり判定、観戦モードが、ステージ上で一通り機能する
- BGM が再生される
- ADR 0028 の基準に反する不具合がない
- `make verify` が通る

## 段階

1. manifest.ts を作り、registry に登録する（中身が空の状態でまず起動確認する）
2. ステージ素材とキャラクターモデルを組み込む
3. ポーズとアニメーション切り替えを実装する
4. issue-22〜28 の各機能をステージ上で統合する
5. BGM を組み込む
6. 一連の流れ（準備→ペイント→探索→観戦→結果）を通しで確認する
