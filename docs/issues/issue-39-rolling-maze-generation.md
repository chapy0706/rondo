# issue-39: rolling の迷路自動生成とお助け

## 背景

issue-36 で、Tilt Maze は rolling という名前になり、ステージが3つ、1人モードと対戦モードの選択に作り直される。

本 issue では、固定のステージを、毎回自動で生成される迷路に置き換える。あわせて、最短経路を使ったお助けを加える。目的は、発表会に来る IT 初心者に、「ゲームの裏側でアルゴリズムが動いている」ことを、見て分かる形で伝えることである。

優先度は低い。issue-36 が終わっていることを前提にする。遅れた場合は、切る順の最初の段階で切ってよい。

## スコープ

### このissueでやること

- 迷路の自動生成
  - 難易度を小・中・大の3段階とし、サイズで差をつける
  - ユニオンファインド（クラスカル法）で生成する。全てのマスがつながり、必ずゴールに着ける迷路になる
  - 乱数の種（seed）を指定でき、同じ種なら同じ迷路になる
- 最短経路
  - 幅優先探索で、スタートからゴールまでの最短経路を求める
- お助けボタン
  - 1回目から3回目は、次に進むべきマスを1つ示す
  - 4回目以降は、ボタンが「答えを見る」に変わる
  - 「答えを見る」を押すと、最短経路を0.5秒間隔で1マスずつ示していく
  - ボールを自動で動かすかどうかは、既存の物理の実装を読んで、現実的な方を提案する
  - お助けの使用回数は、結果に表示する
- 結果の表示
  - クリア後に、最短経路のマス数と、自分が通ったマス数を並べて表示する
- アルゴリズムの見せ方
  - 画面の隅に、使っているアルゴリズムの名前を小さく表示する（例: 幅優先探索）

### このissueでやらないこと

- 対戦モード、サーバー側の変更、契約の変更、game-ended の送出
- 探索が波のように広がる演出（余裕があれば別issue）
- 物理挙動や操作感の変更

## 設計方針

- 迷路の生成、最短経路の探索は、画面から切り離した純粋な関数にする。乱数は注入できるようにする
- 生成と探索は、テストファーストで書く
- 内部の gameType（tilt-maze）は変えない
- 既存の rolling の画面の枠組みに足す形で作る。新しい基盤は作らない
- 通っていない機能は選択画面に出さない

## 受け入れ条件

- 生成された迷路で、全てのマスがつながっている（テストで確認）
- 同じ seed で、同じ迷路になる（テストで確認）
- 最短経路が、手で確かめた小さな迷路の答えと一致する（テストで確認）
- お助けが3回目まで次のマスを示し、4回目から「答えを見る」に変わる
- 「答えを見る」で、最短経路が0.5秒間隔で示される
- 難易度を切り替えて、最後まで遊べる
- `make verify` が通る（TS・Gleam 双方）

## 段階

1. 既存の rolling の物理と画面の構成を読み、ボールの自動移動の可否を確認する
2. 迷路の生成を、テストを先に書いて実装する
3. 最短経路の探索を、テストを先に書いて実装する
4. 難易度と迷路生成を、ゲームに組み込む
5. お助けボタンを実装する
6. 結果の表示とアルゴリズム名の表示を実装する
7. 確認手順を報告にまとめる
