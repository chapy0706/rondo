# issue-05: 基盤UI TOP画面

## 背景

TOP画面はプラットフォームの入口である。発表会で最初に見せる画面であり、選択画面（issue-06）と並んで優先度が高い。ADR 0029 により、選択画面をコンソール風の横スクロールシェルフとして作り直す方針が決まったため、TOP画面もその視覚的方向性（rondo 独自の配色・アイコンの質感・フォント、装飾を絞ったミニマルな構成）に合わせる。

## スコープ

apps/web に TOP画面を実装する。

### このissueでやること

- TOP画面のUI（rondo のロゴ・名称、選択画面への導線）
- ADR 0029 の視覚的方向性（配色・アイコン・フォント）の土台をここで定める。以降の選択画面（issue-06）や各ゲーム UI が参照できるようにする
- 起動時のローディング表現（軽量であることが伝わる、簡潔なもの）

### このissueでやらないこと

- ゲームロジック
- ルーム・ロビー
- 選択画面そのもの（issue-06）

## 設計方針

- スマホの縦画面・タッチ操作を基本ターゲットとする（ADR 0012）。ランドスケープへの転換は行わない
- コンソール風の質感を、rondo 独自の配色・アイコン・フォントで表現する。特定の製品の配色やロゴ的要素には寄せない（ADR 0029）
- 画面に常時表示する要素は最小限に絞る。ロゴ・名称・選択画面への導線程度にとどめ、余計な装飾は削る
- 起動が速く軽いこと。気軽に立ち寄れる入口にする

## 受け入れ条件

- TOP画面が表示される
- ゲーム選択画面へ遷移できる
- 縦画面・タッチで操作できる
- 配色・アイコン・フォントが、特定の製品ではなく rondo 独自のものとして定義されている
- `make verify` が通る

## 段階

1. rondo 独自の配色・アイコンの質感・フォントを、CSS 変数やテーマ定義として定める
2. TOP画面のUI（ロゴ・名称）を実装する
3. 選択画面への遷移を繋ぐ
4. 起動時のローディング表現を実装する
