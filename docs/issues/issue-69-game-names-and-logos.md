# issue-69: ゲームの日本語名とロゴ（ゲームパッケージ）

## 背景

rondo は、複数のゲームから、遊ぶものを選ぶ作りである。選択画面のカードは、英語の名前（veryare、czz、rolling、link など）が、そのまま出ている。IT 初心者の来場者が、どんなゲームか分かりやすいよう、日本語の名前と、ゲームごとのロゴ（パッケージ）を付ける。

- 表示名を、日本語にする。内部の識別子（gameType、ファイルの名前、契約）は、変えない
- czz には、昔作った、スマホのホーム画面に追加したときのアイコンがある。それを、ロゴとして使う
- ほかのゲームは、新しくロゴを作る（簡単な図形の、統一したスタイル）

## スコープ

### このissueでやること

- 表示名（日本語）
  - 現在登録されているゲームの一覧を、識別子、いまの表示名、日本語名の案、の表にする（実装の前に、確認を取る）
  - 決まっている名前: veryare → 「めっちゃアレ」、czz → 「指示厨ゲーム」
  - ほかの案（確認を取る）: rolling → 「ころころ迷路」、link → 「二角消去」、chess → 「ミニチェス」、テトリスに似たゲーム → 商標への配慮から、別名（例:「ブロックおとし」）を提案する
  - 表示名は、ゲームの登録（manifest.ts）の 1 か所に持つ。選択画面、ロビー、ゲーム画面、結果画面、ページの題名、共通の起動画面が、そこから引く
  - 表示名の変更で、画面の文言を探すテスト（E2E、ボット）が壊れないよう、画面の部品は、表示名ではなく、識別子の属性（data-testid や data-game など）で探す形に直す
- ロゴ（ゲームパッケージ）
  - 形式は、SVG を基本にする（小さく、拡大しても崩れない）。正方形（512 × 512 の枠）で、角を丸めた四角の中に収まる図柄。ゲームごとに、背景の色と、図柄が違う。統一したスタイル（平らな図形、1 色の差し色、白か生成り色）
  - czz: 既存のアイコンを探し（.reference/czz/ や、czz の元のファイル）、SVG または PNG として、そのまま使う。形式と大きさが合わなければ、整える
  - ほかのゲーム: 図柄の案を提案して確認を取ってから、SVG を作る（案: めっちゃアレ = 襖の隙間からのぞく目、ころころ迷路 = 迷路の上の球、二角消去 = 麻雀牌ふうの 2 枚と折れ線、ミニチェス = ナイトと 5 × 5 の盤、ブロックおとし = 階段状のブロック）
  - 自作の絵（画像生成や、ほかの道具で作ったもの）を使うときは、決まった場所に置くだけで表示される形にする（形式と大きさの決まりを、docs に書く）
  - 置き場所: apps/web/public/games/<識別子>/ の下（自作のロゴは、公開リポジトリに入れてよい。第三者の素材は、入れない）
  - ロゴがないゲームは、背景の色と、名前の頭文字の仮のタイルで表示する（壊れた画像を出さない）
- 表示する場所
  - 選択画面のカード（ロゴ、日本語名、1 行の説明）
  - ロビーの見出し、共通の起動画面、ゲーム画面の退出ボタンの近く（小さく）、結果画面
  - 画像は、遅延読み込みにし、大きさを指定して、画面がずれないようにする。代替の文字（alt）は、日本語名
- rondo 自体のホーム画面のアイコン（任意。提案して確認する）
  - スマホのホーム画面に追加したとき、rondo のアイコンと名前が出る（manifest、apple-touch-icon）。czz のアイコンとは別に、rondo 用のロゴを作る案を出す

### このissueでやらないこと

- 内部の識別子（gameType、ファイル名、契約、サーバー）の変更
- ゲーム画面の中の絵（キャラクター、ステージ）の変更
- 動くロゴ（アニメーション）、音
- 商標の判断（名前の、権利上の確認は、人が行う）

## 設計方針

- 表示名とロゴは、ゲームの登録（manifest.ts）に、まとめて持つ。画面は、そこから引くだけ。新しいゲームを足すとき、登録に書けば、選択画面に出る
- 純粋関数（表示名の取得、ロゴのパスの決め方、ロゴがないときの仮のタイルの色と頭文字）は、テストを先に書く
- ロゴの図柄は、第三者の絵を、写さない（自作、または、利用条件の確かめられたものだけ）。駒や牌の形も、一般的な図形だけで描く
- 暗い画面と明るい画面の、どちらでも見える（背景の色を、ロゴの側に持つ）
- 受け入れの基準は ADR 0028 に従う

## 受け入れ条件

- すべてのゲームが、日本語の表示名で、選択画面とロビーに出る。内部の識別子は、変わらない（既存のテストが通る）
- E2E とボットが、表示名に依らず、動く（識別子の属性で探す）。表示名を変えても、壊れない（テストで確認）
- czz のロゴが、既存のアイコンで出る
- ほかのゲームのロゴが、選択画面のカードに出る。ロゴの画像が読めないとき、仮のタイルが出て、画面が崩れない（テストで確認）
- ロゴの大きさと形式の決まりが、docs にある
- 暗い画面と明るい画面で、カードが見やすい（目視）
- スマホの縦画面で、カードが並び、読みやすい（目視）
- `make verify` が通る

## 段階

1. ゲームの一覧と、いまの表示名、czz のアイコンの場所と形式、画面の部品の探し方（E2E とボット）を調べ、日本語名と図柄の案を提案して、一度止まる
2. 表示名とロゴの持ち方（登録の形）と、仮のタイルを、テストを先に書いて実装する
3. 画面（選択画面、ロビー、起動画面、結果画面）を、登録から引く形に直す。E2E とボットを、識別子の属性で探す形に直す
4. czz のロゴを組み込み、ほかのゲームのロゴ（SVG）を作る
5. 目視で確かめる項目を、報告にまとめる
