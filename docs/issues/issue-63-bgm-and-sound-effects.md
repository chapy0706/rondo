# issue-63: BGM と効果音（6 つだけ。ほかは無音）

## 背景

いまのゲームには、音がない。雰囲気と手応えを出すために、BGM と効果音を足す。ただし、数は絞る。鳴らすのは、次の 6 つだけで、ほかの場面は、無音にする。

BGM（2 つ）

- bgm-lobby: トップ画面（選択画面）から、待機ルームまで
- bgm-stage: ステージに移ってから（準備移動、ペイント、探索、答え合わせ）

効果音（4 つ）

- se-shoot: 射撃したとき
- se-count: 鬼選出の 10 秒のカウントダウン
- se-decide: 決着したとき
- se-paint: ペイントで塗っているとき

音の素材は、人が探して取り込む。本 issue では、素材が届く前に、音の仕組みと差し込み口を作り、素材が届いたら、置き換えるだけで鳴る形にする。素材がない、または読み込めないときは、無音で、ゲームは変わらず動く。

## スコープ

### このissueでやること

- 音の仕組み（クライアントのみ。サーバーと契約は変更しない）
  - Web Audio API を使う。BGM 用と効果音用の 2 つの系統（バス）を持ち、全体の音量とミュートを持つ
  - スマホのブラウザは、利用者の操作（タップ）の前に、音を鳴らせない。最初のタップ（選択画面のカード、ロビーのボタンなど）で、音の準備（AudioContext の再開）をする。準備前は、鳴らさず、エラーも出さない。そのため、BGM が始まるのは、最初のタップのあとになる
  - 設定の画面（先に実装した、画面の隅の設定ボタン）に、「音」の項目を足す: BGM の音量、効果音の音量、全部のミュート。選んだ値は、その端末に覚えさせる（localStorage は try/catch で囲み、使えなくても動く）
  - 画面が見えなくなったとき（タブを切り替えたとき、アプリが後ろへ行ったとき）は、BGM を止める。戻ったら、再開する
  - 既定の音量は、BGM は小さめ、効果音は中くらい（発表会の会場の騒がしさを考えて、ミュートに、すぐ手が届くこと）。数値は定数
- BGM の切り替え
  - 選択画面、ロビー、待機ルーム（鬼選出を含む）: bgm-lobby
  - ステージに移ったとき（準備移動の開始）: bgm-lobby から bgm-stage へ、1 秒ほど（定数）で混ぜて切り替える
  - 結果画面: bgm-stage を、1 秒ほどで小さくして止める。結果画面は、無音。結果画面を出て、ロビーや選択画面へ戻ったら、bgm-lobby が、再び始まる
  - 同じ BGM が続くときは、途切れず続ける
  - bgm-stage は、待機ルームにいる間に、背景で先に読んでおく（切り替えのとき、待たない）
  - 場面と BGM の対応は、純粋関数にして、データ 1 か所に持つ
- 効果音（クライアントの状態の変化から決める。サーバーに、新しい通知は足さない）
  - se-shoot: 自分が「撃つ」を押したとき（受け付けられた申告だけ。間隔の中で無効のときは、鳴らさない）。自分にだけ鳴らす
  - se-count: 鬼選出のカウントダウン（カウントが始まってから、残り 1 秒ごとに 1 回。残り 3、2、1 は、同じ音を、少し高く（再生の速さを上げて）鳴らす。素材は、1 つだけ）。全員に鳴る（カウントは、全員が見ている）。カウントが始まる前と、終わったあとは、鳴らさない。途中参加・再接続でも、二重に鳴らさない
  - se-decide: 勝敗が決まって、結果が確定したとき（答え合わせの開始。「答え合わせ・○○の勝ち」の帯が出るとき）に、1 回。全員に鳴る。不成立のときは、鳴らさない（結果がないため）。勝ち負けで、音は分けない
  - se-paint: ペイントで体を塗っている間、短い音を、一定の間隔（100 ms 程度。定数）で、少しだけ高さを変えて（再生の速さを ±5% の範囲でばらつかせて）鳴らす。指を離す、または体の外へ出たら止まる。自分にだけ鳴らす
- 他の人に聞かせてはいけない情報を、音で漏らさない
  - se-shoot と se-paint は、自分にだけ鳴らす。他の人の画面で、鳴らさない（サーバーも、これらを通知しない）
- 素材の扱い
  - 音の素材は、issue-43 の素材の配信から読む（manifest の key で指す。ゲームのコードに、ファイル名を直接書かない）。音のファイルを読み込めるように、ローダーを広げる（glb 以外のファイルの種類）。実装の前に、方式を提案して、確認を取る
  - 形式は、iPhone の Safari で確実に鳴るもの（AAC や MP3 など）。繰り返す BGM は、継ぎ目で、音が途切れないことを確かめる（形式の選び方を含めて、実装の前に提案する）
  - 読み込みは、最初の操作のあとに始める。効果音は、小さいので先に読む。bgm-lobby を先に、bgm-stage は、待機ルームの間に読む
  - 素材がない、読めない、壊れているときは、無音で動く。警告は出さない（開発中だけ、Console に理由を出す）
  - 開発中だけ（NEXT_PUBLIC_VERYARE_HIRAYA が有効、または ?roof=1）、素材がないとき、コードで作った簡単な音（短いビープ）を鳴らして、仕組みを確かめられるようにする。本番の既定では、無効
- 音の素材を整える道具（tools/）
  - 音量をそろえる（BGM と効果音で、目標の音量を決める）、長さの確認、形式の変換、manifest への追加。ffmpeg が使えるときだけ動く道具でよい。元のファイルは assets-src の下に置き、コミットしない
- 権利
  - 素材ごとに、入手先、規約の URL、取得した日、利用条件（商用の可否、表記（クレジット）の要否、再配布の禁止）を、docs/licenses/README.md に要約で書く。規約の全文は、assets-src/licenses/ に保存する（公開リポジトリには入れない）
  - 表記が必要な素材があるときは、画面の隅の設定から開ける「クレジット」の表示を足す

### このissueでやらないこと

- 上の 6 つ以外の音（画面の操作、足音、襖、当たり・外れ、フェーズの切り替え、結果の勝ち負けの曲、など）。基本は無音
- サーバーと契約の変更
- 声（ボイス）、BGM の動的な切り替え、壁越しの音のこもり
- 音の素材の作成（人が探して取り込む）
- 音楽の著作権の判断（素材ごとの規約の確認は、人が行う）

## 設計方針

- 素材（音のファイル）は、公開リポジトリに入れない（ADR 0040、`docs/assets.md`）。変換の手順と、manifest の作り方だけを、リポジトリに入れる
- 純粋関数（場面と BGM の対応、状態の変化から効果音を決める、カウントダウンの音の高さ、塗るときの間隔と高さのばらつき、設定の読み書き）は、テストを先に書く。音を鳴らす部分（Web Audio）は、偽の AudioContext で、呼び出しを確かめる。乱数は、注入できる形にする
- 音は、見た目の補助で、ゲームの進行や判定に影響しない。音の失敗が、ゲームを止めないこと
- 同時に鳴らす音の数に上限を設ける（4 程度。定数）
- 音の大きさは、利用者が、すぐ下げられる・消せること（発表会の場、公共の場での配慮）

## 受け入れ条件

- 音の素材がないとき、無音で最後まで遊べ、Console に赤いエラーが出ない（テストで確認）
- 利用者の操作の前に、音を鳴らそうとしても、エラーが出ず、操作のあとに鳴る（偽の AudioContext で確認）
- BGM が、場面（選択画面からロビー・待機ルーム、ステージ、結果画面、結果のあと）で、決めたとおりに切り替わる。同じ BGM が続くときは、途切れず続く（テストで確認）
- 効果音 4 つが、決めた状態の変化で、1 回ずつ鳴り、二重に鳴らない。カウントダウンは、残り 1 秒ごとに 1 回で、カウントの前後と、再接続で、鳴らない。不成立では、se-decide が鳴らない（テストで確認）
- se-shoot と se-paint が、他の人の画面で鳴らない（テストで確認。サーバーに、通知を足していないこと）
- 設定（BGM、効果音、ミュート）が、その端末に覚えられ、再び開いても戻る。localStorage が使えなくても動く（テストで確認）
- 画面が見えなくなると BGM が止まり、戻ると再開する（偽の可視状態で確認）
- 同時に鳴らす音の数が、上限を超えない（テストで確認）
- 素材の大きさの合計を、報告に書く（目標: 全部で 3 MB 以下）
- 目視（聴感）: スマホ（iPhone の Safari を含む）で、最初のタップのあとに、BGM が鳴る。BGM の繰り返しの継ぎ目で、途切れない。ステージへの切り替えが自然。効果音が BGM に埋もれない。ミュートがすぐ効く
- `make verify` が通る（素材に頼らない）

## 段階

1. 音の仕組み、素材のローダーの広げ方、形式、BGM の継ぎ目の扱い、場面と BGM の対応、効果音の鳴らす条件を提案して、一度止まる
2. 純粋関数を、テストを先に書いて実装する
3. 音の仕組み（Web Audio、バス、再開、画面が見えなくなったとき、同時数の上限）を、偽の AudioContext のテストとあわせて実装する
4. 設定の画面に「音」の項目を足す
5. ローダーを広げ、manifest の key で、音の素材を指す。素材がないときの無音を、テストで確かめる
6. 開発中だけのビープ音を足す
7. 素材を整える道具と、docs/assets.md、docs/licenses/README.md の項目を書く
8. 目視（聴感）で確かめる項目を、報告にまとめる

| 鍵 | 種類 | 長さの目安 | 雰囲気・条件 |

| bgm-lobby | BGM（繰り返す） | 1〜2 分 | 和風、穏やか、明るめ。ループの継ぎ目が自然なもの |
| bgm-stage | BGM（繰り返す） | 1〜2 分 | 少し緊張感のある和風。探索の長い間、聞いていても疲れないもの |

| se-paint | 効果音 | 0.05〜0.2 秒 | 塗る音（筆、スプレー、ペンのこすれる音）。連続で鳴らしても耳障りにならないもの |
