# issue-63: BGM と効果音（7 つだけ。ほかは無音）

## 背景

いまのゲームには、音がない。雰囲気と手応えを出すために、BGM と効果音を足す。ただし、数は絞る。鳴らすのは、次の 7 つだけで、ほかの場面は、無音にする。

素材は、人が探して取り込み、届いている（2026-10-22）。元のファイルは `assets-src/audio/`（コミットしない）に置く。

BGM（2 つ）

- top.mp3: 開始画面（選択画面）から、待機ルームまで
- game.mp3: ステージに移ってから（準備移動、ペイント、探索、答え合わせ）

効果音（5 つ）

- hit.mp3: 当たったとき
- miss.mp3: 外れたとき
- count.mp3: 鬼選出の 10 秒のカウントダウン
- start.mp3: カウントが 0 になって、ゲームが始まるとき（準備移動の始まり）
- paint.mp3: ペイントで塗っているとき

前の案の、射撃の音（撃ったとき）と、決着の音（答え合わせの始まり）は、なくす。

素材がない、または読み込めないときは、無音で、ゲームは変わらず動く。

## スコープ

### このissueでやること

- 音の仕組み（クライアントのみ。サーバーと契約は変更しない）
  - Web Audio API を使う。BGM 用と効果音用の 2 つの系統（バス）を持ち、全体の音量とミュートを持つ
  - BGM は、ページをまたいで続くので、音の入口は、アプリ全体で 1 つにする
  - スマホのブラウザは、利用者の操作（タップ）の前に、音を鳴らせない。最初のタップ（選択画面のカード、ロビーのボタンなど）で、音の準備（AudioContext の再開）をする。準備前は、鳴らさず、エラーも出さない。そのため、BGM が始まるのは、最初のタップのあとになる
  - 設定の画面（先に実装した、画面の隅の設定ボタン）に、「音」の項目を足す: BGM の音量、効果音の音量、全部のミュート。選んだ値は、その端末に覚えさせる（localStorage は try/catch で囲み、使えなくても動く）
  - 画面が見えなくなったとき（タブを切り替えたとき、アプリが後ろへ行ったとき）は、BGM を止める。戻ったら、再開する
  - 既定の音量は、BGM は小さめ、効果音は中くらい（発表会の会場の騒がしさを考えて、ミュートに、すぐ手が届くこと）。数値は定数
- BGM の切り替え
  - 開始画面（選択画面）、ロビー、待機ルーム（鬼選出を含む）: top.mp3
  - ステージに移ったとき（準備移動の開始）: top.mp3 から game.mp3 へ切り替える。start.mp3 と、同じ瞬間に起きる
  - 結果画面: game.mp3 を、1 秒ほど（定数）で小さくして止める。結果画面は、無音。結果画面を出て、ロビーや選択画面へ戻ったら、top.mp3 が、再び始まる
  - 同じ BGM が続くときは、途切れず続ける
  - game.mp3 は、待機ルームにいる間に、背景で先に読んでおく（切り替えのとき、待たない）
  - 場面と BGM の対応は、純粋関数にして、データ 1 か所に持つ
- 効果音（クライアントがすでに持っている状態の変化から決める。サーバーに、新しい通知は足さない）
  - hit.mp3: 当たったとき。撃った本人と、見つかった本人にだけ鳴らす
  - miss.mp3: 外れたとき。撃った本人にだけ鳴らす
    - 当たりと外れの見分けは、既存の外れの理由の推定（shotHint）と同じ、結果の見方（隠れ中の一覧の変化。約 0.5 秒の窓）を使う
    - 当たりと外れは、同時に鳴らない。撃つ間隔の中で受け付けられなかった「撃つ」では、どちらも鳴らさない
  - count.mp3: 鬼選出の 10 秒のカウントダウンが始まったとき
    - 素材の長さ（秒）で、鳴らし方を決める純粋関数にする
    - 8 秒以上なら、始まりに 1 回だけ鳴らし、素材の終わりが、カウントの 0 秒にそろうようにする。途中から入った人（途中参加・再接続）は、残りに合わせて、素材の途中から鳴らす
    - 短い音なら、残り 1 秒ごとに鳴らす
    - カウントが取り消されたら（カウントが 0 にならずに終わったら）止める。二重に鳴らさない
    - 全員に鳴る（カウントは、全員が見ている）
  - start.mp3: カウントが 0 になって、ゲームが始まるとき（準備移動の始まり）に、1 回。全員に鳴る
  - paint.mp3: ペイントで体を塗っている間
    - 素材の長さで、鳴らし方を決める純粋関数にする
    - 0.5 秒未満なら、0.1 秒（定数）ごとに、再生の速さを ±5% の範囲でばらつかせて鳴らす
    - 長ければ、塗っている間だけ繰り返し、指を離す、または体の外へ出たら、小さくして止める
    - 自分にだけ鳴らす
- 他の人に聞かせてはいけない情報を、音で漏らさない
  - miss.mp3 と paint.mp3 は、自分にだけ鳴らす
  - hit.mp3 は、撃った本人と、見つかった本人にだけ鳴らす
  - start.mp3 と count.mp3 は、全員に鳴らす
  - 観戦者は、BGM と start.mp3 だけを鳴らす
  - サーバーは、これらの音のための通知を送らない
- 素材の扱い
  - 音の素材は、issue-43 の素材の配信から読む（manifest の key で指す。ゲームのコードに、ファイル名を直接書かない）。音のファイルを読み込めるように、ローダーを広げる（glb 以外のファイルの種類）。manifest には、key、種類（BGM か効果音か）、長さ、倍率（gain）を持たせる
  - 形式は、iPhone の Safari と Chrome で確実に鳴るもの。繰り返す BGM は、継ぎ目で、音が途切れないことを確かめる（継ぎ目の扱いを含めて、実装の前に提案する）
  - 読み込みは、最初の操作のあとに始める。効果音は、小さいので先に読む。top.mp3 を先に、game.mp3 は、待機ルームの間に読む
  - 素材がない、読めない、壊れているときは、無音で動く。警告は出さない（開発中だけ、Console に理由を出す）
  - 開発中だけ（NEXT_PUBLIC_VERYARE_HIRAYA が有効、または ?roof=1）、素材がないとき、コードで作った簡単な音（短いビープ）を鳴らして、仕組みを確かめられるようにする。本番の既定では、無効
- 音の素材を整える道具（tools/）
  - 音量をそろえる（BGM と効果音で、目標の音量を決める）、長さの確認、manifest への追加。ffmpeg が使えるときだけ動く道具でよい。元のファイルは assets-src の下に置き、コミットしない
- 権利
  - 規約: こんとどぅふぇ（BGM）と、効果音ラボ（効果音）。どちらも、無料、商用利用可、表記は任意
  - 再配布は禁止（音源ファイルそのものを配る、素材集にする、効果音を自由に鳴らせるアプリにする、は禁止）。アプリへの組み込みは許可
  - 素材（mp3）は、公開リポジトリに入れない。変換した物も入れない
  - 素材を鳴らして試せる画面は、本番に出さない
  - 素材ごとに、入手先、規約の URL、取得した日、利用条件（商用の可否、表記の要否、再配布の禁止）を、docs/licenses/README.md に要約で書く。規約の全文は、assets-src/licenses/ に保存する（公開リポジトリには入れない）
  - 表記は任意。設定の「クレジット」に、次の 2 行を足すかは、段階 1 の提案で決める
    - BGM: こんとどぅふぇ https://conte-de-fees.com/
    - 効果音: 効果音ラボ https://soundeffect-lab.info/

### このissueでやらないこと

- 上の 7 つ以外の音（画面の操作、足音、襖、射撃、決着、フェーズの切り替え、結果の勝ち負けの曲、など）。基本は無音
- サーバーと契約の変更
- 声（ボイス）、BGM の動的な切り替え、壁越しの音のこもり
- 音の素材の作成と、探し直し
- 音楽の著作権の判断（素材ごとの規約の確認は、人が行う）

## 設計方針

- 素材（音のファイル）と、それを変換した物は、公開リポジトリに入れない（ADR 0040、`docs/assets.md`）。整える手順と、manifest の作り方だけを、リポジトリに入れる
- 純粋関数（場面と BGM の対応、状態の変化から効果音を決める、当たりと外れの見分け、カウントダウンの鳴らし方、塗るときの鳴らし方、設定の読み書き）は、テストを先に書く。音を鳴らす部分（Web Audio）は、偽の AudioContext で、呼び出しを確かめる。乱数は、注入できる形にする
- 音は、見た目の補助で、ゲームの進行や判定に影響しない。音の失敗が、ゲームを止めないこと
- 同時に鳴らす音の数に上限を設ける（4 程度。定数）
- 音の大きさは、利用者が、すぐ下げられる・消せること（発表会の場、公共の場での配慮）

## 受け入れ条件

- 音の素材がないとき、無音で最後まで遊べ、Console に赤いエラーが出ない（テストで確認）
- 利用者の操作の前に、音を鳴らそうとしても、エラーが出ず、操作のあとに鳴る（偽の AudioContext で確認）
- BGM が、場面（選択画面からロビー・待機ルーム、ステージ、結果画面、結果のあと）で、決めたとおりに切り替わる。同じ BGM が続くときは、途切れず続く（テストで確認）
- 効果音 5 つが、決めた状態の変化で、1 回ずつ鳴り、二重に鳴らない。当たりと外れは同時に鳴らない。カウントダウンは、素材の長さに合わせた鳴らし方で、途中参加・再接続では残りに合わせ、取り消しで止まる（テストで確認）
- miss.mp3 と paint.mp3 が、他の人の画面で鳴らない。hit.mp3 が、撃った本人と見つかった本人の画面だけで鳴る。観戦者の画面では、BGM と start.mp3 だけが鳴る（テストで確認。サーバーに、通知を足していないこと）
- 設定（BGM、効果音、ミュート）が、その端末に覚えられ、再び開いても戻る。localStorage が使えなくても動く（テストで確認）
- 画面が見えなくなると BGM が止まり、戻ると再開する（偽の可視状態で確認）
- 同時に鳴らす音の数が、上限を超えない（テストで確認）
- 素材を鳴らして試せる画面が、本番のビルドに含まれない（確かめ方を報告に書く）
- 素材の大きさの合計を、報告に書く（目標: 全部で 3 MB 以下）
- 目視（聴感）: スマホ（iPhone の Safari と Chrome を含む）で、最初のタップのあとに、BGM が鳴る。BGM の繰り返しの継ぎ目が自然。ステージへの切り替えが自然。効果音が BGM に埋もれない。ミュートがすぐ効く
- `make verify` が通る（素材に頼らない）

## 段階

1. 素材の実測、音の仕組み、素材のローダーの広げ方、manifest の形、BGM の継ぎ目の扱い、場面と BGM の対応、効果音の鳴らす条件を提案して、一度止まる
2. 純粋関数を、テストを先に書いて実装する
3. 音の仕組み（Web Audio、バス、再開、画面が見えなくなったとき、同時数の上限）を、偽の AudioContext のテストとあわせて実装する
4. 設定の画面に「音」の項目を足す
5. ローダーを広げ、manifest の key で、音の素材を指す。素材がないときの無音を、テストで確かめる
6. 開発中だけのビープ音を足す
7. 素材を整える道具と、docs/assets.md、docs/licenses/README.md の項目を書く
8. 目視（聴感）で確かめる項目を、報告にまとめる
