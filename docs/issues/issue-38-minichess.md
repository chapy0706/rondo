# issue-38: チェス（5×5・CPU対戦、表示名は chess）

## 背景

issue-16〜18 の置き換えとして、暇つぶし用の1人用ゲームを作る。チェスは通常の8×8だと規模が大きいため、5×5 の縮小盤にする。

サーバーを使わず、ブラウザの中だけで完結する。対戦相手は CPU で、まずは合法手の中からほぼランダムに選ぶ単純なものにする。過去の棋譜から学習する CPU は、棋譜の保存場所と引く仕組みが別に必要になるため、このissueでは作らない。

優先度は低い。気が向いたときに作れる規模にする。切る順の最初に置く。

## スコープ

### このissueでやること

- 盤とルール
  - 盤は5×5とする。駒の配置は、5×5 の縮小チェスとして知られる配置（ルーク、ナイト、ビショップ、クイーン、キングの列と、ポーン5枚）を基本とする。決める前に、配置案を提示して確認を取る
  - 駒の動きは通常のチェスに従う
  - ポーンの二歩前進、アンパッサン、キャスリングは作らない（盤が小さいため）
  - ポーンが最奥段に着いたら、クイーンに昇格する（選択はさせない）
  - 王手、詰み、ステイルメイト（引き分け）を判定する
  - 引き分けとして、ポーンの動きも駒の取りもない手が50手続いた場合も扱う
- CPU
  - 合法手を全て列挙し、次の優先順で手を選ぶ
    1. 1手で詰ませられる手があれば、それを指す
    2. 駒を取れる手があれば、価値の高い駒を取る手を指す
    3. それ以外は、合法手からランダムに選ぶ
  - 手の選び方は、差し替え可能なインターフェースとして定義する。将来、棋譜から学習する CPU に入れ替えられるようにする
- お助けボタン
  - 回数の制限なしで、何度でも押せる
  - 押すと、CPU と同じ手の選び方で選んだ手を、次の一手として示す（移動元と移動先を強調表示する）
  - 使用回数は、結果に表示する
- 画面
  - 自分は白番とする。駒をタップすると動かせるマスが強調され、移動先をタップして指す
  - 手番、王手、勝敗の表示を出す
  - やり直しボタンを置く
  - 縦画面のスマホで遊べるサイズと操作にする

### このissueでやらないこと

- 棋譜を使って学習する CPU（別issueにする）
- 対人対戦、サーバー通信、契約の変更
- 難易度の切り替え、持ち時間、棋譜の保存、アンドゥ
- 駒の画像素材の作成（文字や記号の表示でよい）

## 設計方針

- 盤面、合法手の生成、王手・詰みの判定は、画面から切り離した純粋な関数にする
- ルールの判定はテストファーストで書く。駒ごとの動き、動いた結果として自分の王に王手がかかる手の除外、詰み、ステイルメイト、昇格を含める
- CPU は「盤面を受け取り、手を返す」関数として切り離し、乱数は注入できるようにする
- 既存の1人用ゲームの登録の仕方、画面の枠組み、結果の扱いを踏襲する。新しい基盤は作らない
- 規模が1つのissueに収まらなさそうなら、盤面や駒数を減らしてよい。その場合は理由を報告に書く

## 受け入れ条件

- お助けが回数の制限なく使え、示した手が合法手である（テストで確認）
- 全ての駒が通常の動きで動き、自分の王に王手がかかる手は指せない（テストで確認）
- 詰み、ステイルメイト、50手引き分けが正しく判定される（テストで確認）
- ポーンが最奥段に着くとクイーンになる（テストで確認）
- CPU が常に合法手を指し、1手詰めと駒取りを優先する（テストで確認）
- CPU の手の選び方が差し替え可能な形になっている
- スマホの縦画面で、最後まで遊べる
- `make verify` が通る

## 段階

5. 盤面の画面と操作を実装する
6. 勝敗の表示とやり直しを実装する
7. 選択画面に載せる
8. 確認手順を報告にまとめる
