# issue-29d: 答え合わせの演出、歩く速さの調整、マイルストーン1の通し

## 背景

issue-29（ステージ統合）を4本に分けたうちの4本目。issue-29a〜29c で、ステージの座標・襖・射撃の見通し・仮素材の表示が揃う。

本 issue で、答え合わせタイムの演出を足し、歩く速さを調整し、マイルストーン1を2〜3タブで通す。

マイルストーン1: 鬼選出 → 準備移動 → 探索（撃つ）→ 答え合わせ → 結果が、2〜3タブで通る。ペイントは仮の色のまま、観戦はいまの挙動のまま。

## スコープ

### このissueでやること

- 答え合わせタイムの演出（ADR 0033）
  - 襖が全部開いて見える（サーバーの襖の通知に合わせる。サーバー側は issue-29b で済み）
  - 隠れていた全員（見つかった人・逃げ切った人の両方）を、赤く点滅させる。点滅させる相手と点滅の明るさの計算は純粋関数にする
- 歩く速さの調整
  - 準備移動（20 秒）のうちに、玄関から隠れ場所まで歩けるか、実際に歩いて確かめ、速さ（定数）を決める
  - 決めた速さと、その根拠（骨格の大きさ、玄関から遠い部屋までの距離）を報告に書く
- E2E（issue-48）の更新
  - ステージの通知と襖の通知がフレームに出ることを確かめる
  - 開ける報告を注入すると、2つのタブの両方で襖の状態が変わることを確かめる（画面の特定用の属性を足してよい）
  - シナリオ5（結果まで）が、新しいステージで通ることを確かめる
- ボット（`make bots`）が全シナリオ通ることを確かめる
- 2〜3タブでの通しの確認
  - 手順を `docs/e2e.md` の手作業の確認項目に足す

### このissueでやらないこと

- ペイントの作り込み（issue-25）。マイルストーン1ではペイントは仮の色のまま
- 観戦の作り込み（issue-28 のいまの挙動のまま）
- 答え合わせタイムの視点の切り替えといいね（issue-32）
- ポーズ・アニメーション・BGM・待機ルームの磨き（issue-53）

## 設計方針

- ADR 0028・0033・0034・0035 に従う
- 待ち時間は秒数ではなく、画面の状態（属性）や通知で待つ（issue-48 の方針）
- 演出の判断（点滅させる相手、明るさ）は純粋関数にし、テストを先に書く

## 受け入れ条件

### 自動で確かめること

- 答え合わせの点滅: 点滅させる相手が、隠れていた全員（見つかった人を含む）である。明るさが時間で周期的に変わる（純粋関数のテスト）
- `make e2e`（シナリオ1〜4と、襖の通知・開ける報告の確認）が通る
- `make e2e/result`（シナリオ5）が、新しいステージで通る
- `make bots` で全シナリオが通る
- `make verify` が通る（TS・Gleam 双方）

E2E とボットはサーバーとブラウザの起動を伴うので、報告に、実行するコマンドと、失敗したときに貼ってほしい出力の範囲を書く。

### 目視でしか確かめられないこと

- 答え合わせタイムで、襖が全部開いて見え、隠れていた全員が赤く点滅する
- 準備移動の 20 秒のうちに、玄関から隠れ場所まで歩ける（速さの手触り）
- マイルストーン1の通し: 2〜3タブで、鬼選出 → 準備移動 → 探索（撃つ）→ 答え合わせ → 結果まで進む
- スマホの縦画面で通る

## 段階

1. 点滅の判断を、テストを先に書いて実装し、答え合わせの演出をつなぐ
2. 歩いて速さを決める
3. E2E を更新する
4. 2〜3タブで通し、手作業の確認項目を `docs/e2e.md` に足す
5. 実行するコマンドと確認手順を報告にまとめる
