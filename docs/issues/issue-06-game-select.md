# issue-06: 基盤UI ゲーム選択画面（コンソール風シェルフ）

## 背景

ゲーム選択画面は、registry に集約されたマニフェストから自動生成される。ここがプラグイン機構の表側の要であり、ゲームを増やしても基盤側を触らずに選択肢が増える状態を実現する。

発表会で最初に見せる画面であり、優先度が高い。ADR 0029 により、選択画面をコンソール風の横スクロールシェルフ（横一列に並んだカードを選び、選択中を拡大・強調する動き）として作り直す。ゲーム本体がまだ実装途中でも、この画面自体は独立して仕上げられる。

## スコープ

apps/web に、registry を読んで選択画面を組み立てる仕組みを実装する。

### このissueでやること

- registry からマニフェスト一覧を読み込む
- マニフェストから、横スクロールのカード（シェルフ）を動的に生成する
- 選択中のカードを拡大・強調する動き
- 画面に常時表示する要素をゲームアイコン（カード）と設定アイコンに絞る。それ以外の装飾は削る
- 選んだゲームの起動（ゲームホストへの導線）
- サムネイル画像が無いゲーム（現状すべてのゲームに実体がない）向けの、簡潔なフォールバック表示

### このissueでやらないこと

- registry に載るゲーム本体（issue-07 以降）
- ルーム・ロビー（issue-11）
- ランドスケープ（横持ち）への対応
- 設定画面の中身（アイコンの導線のみ用意する）

## 設計方針

- ゲームはプラグインとして扱い、選択画面はマニフェストから自動生成する（ADR 0003）
- 基盤の UI・ルーティングにゲーム固有の記述を持たない
- 横スクロールのカルーセルという構造を採用する。配色・アイコンの質感・フォントは issue-05 で定めた rondo 独自のものを使う。特定の製品の配色やロゴには寄せない（ADR 0029）
- 画面はポートレート（縦持ち）のまま、横スクロールのシェルフを画面内に置く。ランドスケープへの転換は行わない
- スマホのタッチ操作でスクロール・選択が快適に行えることを優先する

## 受け入れ条件

- registry にマニフェストを追加すると、選択画面のシェルフに選択肢が増える
- 選択肢を増やす際に基盤側のコードを変更する必要がない
- 横スクロールで各ゲームを選べ、選択中のカードが拡大・強調される
- 画面に常時表示されるのはゲームアイコン(カード)と設定アイコン程度で、他の装飾がない
- サムネイル画像が無いゲームも、フォールバック表示で違和感なく並ぶ
- 選んだゲームを起動できる
- 縦画面のタッチ操作で快適にスクロール・選択できる
- `make verify` が通る

## 段階

1. registry の読み込みを実装する
2. マニフェストから横スクロールのカード(シェルフ)を生成する
3. 選択中のカードを拡大・強調する動きを実装する
4. サムネイル未設定時のフォールバック表示を実装する
5. 設定アイコンの導線（遷移先は空でよい）を追加する
6. ゲーム起動の導線を繋ぐ
