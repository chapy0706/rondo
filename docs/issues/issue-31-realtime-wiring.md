# issue-31: Gleam サーバーとクライアントの実接続の配線

## 背景

ここまでの実装で、Gleam サーバー側にはルーム（room_actor）、ルーム台帳（room_directory）、限定配信（send_to）、veryare のフェーズ状態機械とステージ生成が揃い、いずれもユニットテストで検証されている。クライアント側も、ロビー・ゲーム画面・モック・WebSocketAdapter が揃っている。

しかし、この2つは**まだ WebSocket で繋がっていない**。現在、ブラウザ上のゲームはすべて MockWebSocketAdapter で動いており、本番の rondo-ws は issue-08 時点の echo のままである。JSON への変換（gleam_json）、ソケットごとの接続アクターとルームアクターの結線、プレイヤー識別、再接続猶予の実タイマーは、いずれもどの issue にも含まれていなかった。

「リアルタイム対戦を楽しんでもらう」が veryare と Tilt Maze の核であるため、本 issue は発表までの最重要項目のひとつとして扱う。

## スコープ

### このissueでやること

**サーバー（Gleam）**

- mist による WebSocket エンドポイントを実装する（ソケット1本 = 接続アクター1つ、ADR 0006・0007）
- 契約（packages/contracts/src/messages.ts）のメッセージを、gleam_json で JSON に変換する encode / decode を実装する。対象は contracts に定義されている全メッセージ種別とする（実装前に一覧を作り、報告に含める）
- 接続時にプレイヤー識別子をサーバーが発行し、表示名（ADR 0015）を受け取る
- 接続アクターと room_directory / room_actor を結線する
  - ルーム一覧の取得、作成（roomOptions の settings を含む）、参加、退出
  - ルーム一覧には探索フェーズの時間を含めない（ADR 0024）
  - 参加時に room_actor.subscribe で送信先（outbox）を登録し、限定配信（send_to）がソケットまで届くようにする
  - 定員・同時ルーム数の上限（ADR 0030）が実接続でも効く
- 再接続猶予を実タイマーで実装する（ADR 0013）
  - ソケットが切れたら10秒の猶予を開始する。猶予内に同じプレイヤー識別子で再接続すれば復帰する
  - 猶予を過ぎたら room_actor へ Leave を通知する（現状の「Leave を受けた時点を猶予切れとみなす」という仮の扱いをこれで置き換える）
- 既存の Tilt Maze と veryare が、同じ汎用プロトコルで動くことを確認する。ゲーム固有のロジックには手を入れない

**クライアント（TypeScript）**

- WebSocketAdapter の実接続モードを、上記サーバーに対して検証し、不足があれば直す。接続先は従来どおり `NEXT_PUBLIC_RONDO_WS_URL`（未設定ならモック）で切り替える
- 切断時の再接続（同じプレイヤー識別子での復帰）を実装する

**検証**

- TypeScript の契約と Gleam の型・JSON の対応を守るテスト（ADR 0009）
- Gleam 側で、2クライアントを模した結合テスト（作成 → 参加 → フェーズ通知 → 限定配信 → 切断 → 猶予内復帰 / 猶予切れ）
- ローカルで2つのブラウザタブから veryare のルームを作成・参加し、フェーズ通知が両方に届くことの確認手順を、報告に含める

### このissueでやらないこと

- ゲーム固有のロジックの変更（フェーズ、ステージ、当たり判定など）
- 認証・永続アカウント（ADR 0015）
- デプロイの切り替え作業そのもの（Coolify での再ビルド、Traefik の設定、`NEXT_PUBLIC_RONDO_WS_URL` の設定は手作業。手順を報告に含める）

## 設計方針

- 契約は TypeScript を正とし、Gleam 側をそれに対応させる（ADR 0009）
- 接続アクターは1ソケットにつき1つ。状態をプロセスに閉じ込める（ADR 0006）
- 隠すべき情報は、そもそも該当しない接続に送らない（ADR 0021）。ソケット層でも、宛先でない接続へは送信しないことをテストで守る
- モックでの開発は今後も維持する。実接続は環境変数で切り替える
- 受け入れの基準は ADR 0028 の考え方に沿い、情報漏れと進行停止を最優先で守る

## 受け入れ条件

- ローカルで Gleam サーバーを起動し、2つのブラウザから同じ veryare ルームに入り、フェーズ通知が両方に届く
- 限定配信が、宛先のソケットにだけ届く（結合テストで確認）
- ソケットを切って10秒以内に再接続すると、同じルームに復帰する。10秒を過ぎると離脱が確定する
- ルーム一覧に探索フェーズの時間が含まれない
- 定員（5人）と同時ルーム数（3）が実接続でも効く
- Tilt Maze が変更なしで動く
- TypeScript の契約と Gleam の JSON の対応テストが通る
- `make verify` が通る（TS・Gleam 双方）

## 段階

1. contracts のメッセージ種別を一覧にし、Gleam 側の型と JSON の対応表を作る
2. gleam_json による encode / decode を、テストファーストで実装する
3. mist の WebSocket エンドポイントと、接続アクターを実装する
4. プレイヤー識別子の発行と、表示名の受け取りを実装する
5. ルーム一覧・作成・参加・退出を room_directory / room_actor に結線する（outbox の登録を含む）
6. 再接続猶予を実タイマーで実装する
7. クライアントの実接続モードを検証し、再接続を実装する
8. 結合テストと契約対応テストを書く
9. ローカルでの2タブ確認手順と、デプロイ切り替え手順を報告にまとめる
