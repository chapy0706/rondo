# issue-26: veryare 被り判定と禁止エリア

## 背景

隠れ側同士の「被り」判定と、ステージオブジェクトへの過度なめり込みを防ぐ仕組みを実装する（ADR 0026）。

## スコープ

### このissueでやること

- プレイヤーへの球体コリジョンの実装
- 準備移動フェーズ終了時、全員の座標から被りをサーバーが判定し、重なっていたプレイヤーを失格にする
- ステージオブジェクトのバウンディングボックスからの禁止エリア自動生成
- 禁止エリアに触れている間のカウントダウン(5秒)表示
- 5秒経過時、近傍の固定候補地点(5〜6箇所)への強制移動
- 床は寝そべるポーズの間のみ、同様のめり込み許可とする
- **ステージ整合性の静的テスト**: 実際のステージ素材が届く前に、仮の座標データ（箱の位置・サイズ、固定候補地点の座標）でテストを先に書く。以下を検算する
  - 禁止エリア同士が重なっていないか
  - 固定候補地点が、すべての禁止エリアの外にあるか
  - 固定候補地点が、ステージの範囲内にあるか
- **エッジケースのテスト**: プレイヤーの動きを想定した境界条件をテストで検証する
  - ステージ端で禁止エリアに触れたとき、押し出し先がステージ範囲外にならないか
  - 2つの禁止エリアが近接し、同時に触れている状態でカウントダウンが二重に走らないか
  - 現在地から複数の固定候補地点が同着（同距離）の場合の挙動が一意に定まるか
  - 準備移動フェーズ終了時、ほぼ同座標に複数人がいる場合、全員が被り判定に含まれるか（2人だけでなく3人以上のケースも）

これらのテストは、本物のステージ素材が届く前に仮の座標データで先に書き、実装のロジックを固めておく。素材が届いた後は、座標を実データに差し替えるだけで、ロジック自体の再検証は最小限で済む。

### このissueでやらないこと

- 当たり判定（issue-27。射撃時の命中判定は別の仕組み）
- ステージ素材そのものの用意（issue-29）

## 設計方針

- 被り判定・禁止エリアの方式は ADR 0026 に従う
- 被り判定はサーバー権威（各プレイヤーの座標をサーバーが持つ）で行う
- 禁止エリアは、オブジェクトの位置を変えずに Box3.setFromObject 相当の外接箱を縮小して生成する
- 受け入れの基準は ADR 0028 に従う

## 受け入れ条件

- 準備移動フェーズ終了時、球体が重なっていたプレイヤー全員が失格になる
- ステージのオブジェクトごとに禁止エリアが自動生成される（手作業での配置をしない）
- 禁止エリアに触れるとカウントダウンが表示され、離れると解除される
- 5秒経過すると、近傍の固定候補地点へ強制移動する
- 寝そべるポーズの間は、床へのめり込みが同様に許可される
- 仮の座標データによるステージ整合性テスト（禁止エリアの重なり、固定候補地点の位置）が通る
- エッジケースのテスト（ステージ端、禁止エリアの近接、同着距離、3人以上の被り）が通る
- `make verify` が通る

## 段階

1. 仮の座標データで、ステージ整合性のテスト（禁止エリアの重なり、固定候補地点の位置）を先に書く
2. プレイヤーの球体コリジョンを実装する
3. 準備移動フェーズ終了時の被り判定をサーバーに実装する（エッジケース：3人以上の同時被りを含めてテストする）
4. ステージ読み込み時のバウンディングボックス自動生成を実装する
5. 禁止エリアのカウントダウンと固定候補地点への強制移動を実装する（エッジケース：ステージ端、禁止エリアの近接、同着距離を含めてテストする）
6. 床の特例（寝そべるポーズのみ許可）を実装する
7. 実際のステージ素材が届いたら、仮データを実データに差し替えて、ステージ整合性テストを再実行する
