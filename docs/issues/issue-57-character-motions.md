# issue-57: キャラクターの動き（待機・歩く・走る）

## 背景

issue-56 で、体は素材の人型になり、ポーズは「骨の姿勢の表」から、静止した姿勢として当てている。いまは、歩いても走っても、体は同じ姿勢のまま、滑るように動く。

本 issue では、動いている間の体に、動き（アニメーション）を付ける。使う動きは、Mixamo の次の3つ。

- 待機: Idle
- 歩く: Walking
- 走る: Medium Run

issue-56 の調査で、23 本のポーズ素材の体と骨は、同じ（65 本、mixamorig:）と確かめてある。動きも、同じ骨の名前で当てられる見込みである。

優先度は、issue-56 の目視確認の後。遅れた場合は、静止した姿勢のまま出す。

## スコープ

### このissueでやること

- 動きの素材を作る（実装の前に、元の FBX の中身を確かめ、方針を提案して、確認を取る）
  - assets-src/characters/ の Idle、Walking、Medium Run の FBX が、動きの全コマを持っているかを確かめる（issue-56 では、1 コマのポーズとして使った）
  - 動きだけを取り出し、体のメッシュを含まない小さな glb（character-motions）にする。manifest の key で指す
  - 根の動き（前へ進む動き）を取り除く（Hips の水平方向の移動。上下の動きは残す）。進む動きは、ゲームの位置が決めるため
  - 繰り返しの継ぎ目がなめらかか確かめる（最初と最後の姿勢の差を測る）。必要なら調整する
  - 大きさを小さくする（コマ数の間引き、量子化、圧縮）。目標は、3 つ合わせて 300 KB 前後。実測して報告する
  - 歩幅（1 周期で進む距離）を測り、動きの標準の速さ（m/秒）を、素材の情報として持つ
- 動きを当てる
  - 体の骨に、動きを当てる（AnimationMixer。体は骨ごと複製しているので、体ごとに1つ）
  - 状態: 待機、歩く、走る。状態の切り替えは、速さから決める純粋関数にする（待機 → 歩く → 走るのしきい値と、ばたつかないための余裕（ヒステリシス）は定数）
  - 動きの切り替えは、短い時間（0.15〜0.2 秒。定数）で、なめらかに混ぜる
  - 再生の速さを、実際の速さに合わせる（足が地面を滑らないように。標準の速さとの比）
- どの体に当てるか（実装の前に提案して、確認を取る）
  - 動ける間の、遊ぶ人の体（待機ルーム、準備移動、鬼の探索）。速さは、実際に進んだ距離から求める（壁で止まれば、待機に戻る）
  - 他の人の画面の、鬼の体。速さは、補間した位置の変化から求める。鬼 CPU も同じ
  - 隠れ側は、ペイントフェーズに入ったら、選んだポーズの静止した姿勢にする（動きは付けない）。動かないのが、隠れる遊びの前提のため
  - 鬼の画面に出る隠れ側の体は、静止した姿勢のまま
- 動きの素材が読めないとき: 静止した姿勢（issue-56 のポーズの表の idle）のまま動く。警告は出さない。仮のカプセルは、動きなし
- 足もとの高さ: 待機の動きの足もとの最低点を基準にして、床につける（動きの途中の細かい上下は、許容する）

### このissueでやらないこと

- 他の動き（跳ぶ、振り向き、しゃがみ歩きなど）、足の位置合わせ（IK）、根の動き
- 隠れ側の動き（歩いて隠れる様子を、他の人に見せる）。ペイントフェーズの前に、他の人の画面へ位置を送る仕組みがないため
- サーバーと契約の変更（動きは、見た目だけで、クライアントの中で決まる）
- ポーズの選び方の変更（issue-56 のまま）

### ポーズの変更を、確定の前なら、いつでもできる

- 使える時期: 準備移動と、ペイントフェーズ（隠れ側だけ）。確定の電文を送る前まで。待機ルームには、ボタンを出さない（役割が決まる前のため）。探索の開始以降は、変えられない（契約とサーバーは変えない）
- 動いているとき: ボタンは、選ぶポーズを変える。体は、歩く・走るの動きのまま。止まって一定の時間（定数。0.3 秒程度）がたつと、選んだポーズへ移る（0.2 秒の混ぜ）。動き出すと、歩く・走るに戻る。ポーズを選んでいない人は、待機（Idle）の動き
- 止まっているとき: ボタンを押すと、すぐに新しいポーズへ移る
- ボタンを押したとき、選んだポーズの表示名を、1 秒ほど短く出す（動いていて、体がすぐ変わらないときの目印）
- ペイントフェーズに入ったときと、確定したあとは、選んだポーズ（なければ idle のポーズ）の静止した姿勢にする
- 送るのは、いまのまま、フェーズの終わりの 2 秒前か「塗り終わり」で一度だけ。ポーズを変えていれば、塗っていなくても送る
- 状態の切り替え（待機、歩く、走る、ポーズ）は、純粋関数にして、テストを先に書く。確かめること: 動いている間は、ポーズに移らない。止まって一定時間たつと、ポーズへ移る。動き出すと、ポーズから歩く・走るに戻る。ボタンを押すたびに、選ぶポーズだけが変わる。ポーズを選んでいない人は、待機に戻る

## 設計方針

- 素材（動きの glb）は、公開リポジトリに入れない（ADR 0040、`docs/assets.md`）。ゲームのコードに、素材のファイル名を直接書かない。manifest の key で指す
- 純粋関数（状態の遷移、速さの計算、再生の速さ）は、テストを先に書く。時間は注入できる形にする
- 素材が無いときの動き（静止した姿勢、仮のカプセル）が基準で、動きは上乗せとする。`make verify` は素材に頼らない
- 描画の軽さを守る。動きを更新する体は、見えている体だけ。同時に最大 5 つ
- 素材の規約: Mixamo の利用規約と FAQ の写しを、`assets-src/licenses/` に保存してから配信する（元の FBX は配らない。配るのは、加工した glb だけ）

## 受け入れ条件

- 動きの素材の検査（テストで確認。素材の読み込みは、Node で行い、素材のファイルはテストに入れない）
  - 3 つの動きの、骨の名前が、体の骨にすべて含まれる
  - 根の水平方向の移動が、取り除かれている（範囲が、小さい値以内）
  - 最初と最後の姿勢の差が、小さい（継ぎ目）
  - 大きさが、目標以内（超える場合は、報告に、実測値と理由）
- 状態の切り替えが、速さのしきい値どおりに動き、しきい値の近くで、ばたつかない（テストで確認）
- 再生の速さが、速さに合わせて変わる（テストで確認）
- 動きの素材が読めないとき、静止した姿勢で動く（テストで確認）
- 目視: 待機で息づかいのような動き、歩くと歩く動き、走ると走る動きが出る。足が、地面を大きく滑らない。切り替わりが、ぎこちなくない。ペイントフェーズで、選んだポーズに、自然に移る。壁で止まったとき、待機に戻る
- スマホの縦画面で、動きを付けても、重くない（目視）
- `make verify` が通る

## 段階

1. 元の FBX の中身（コマ数、長さ、根の動き）を調べ、素材の作り方と、体への当て方を提案して、一度止まる
2. 動きの素材を作る道具（tools/）を足し、検査をテストにする。manifest に載せる
3. 状態の切り替えと、再生の速さの純粋関数を、テストを先に書いて実装する
4. 体に動きを当てる。issue-46 の素材の入口に、動きの差し替え口を足す
5. どの体に当てるかを実装する（遊ぶ人、他の人の画面の鬼、鬼 CPU）
6. 素材が無いときの動きを、テストで確かめる
7. 目視で確かめる項目を、報告にまとめる
