# issue-56: キャラクターの素材への差し替えと、ポーズのランダム変更

## 背景

いま、遊ぶ人と CPU の体は、仮のカプセル（円柱）で描かれている。issue-25 で、体の描き込み面（胴1本の円柱）と、体を作る口（差し替え用の口）は作ってあり、同じシェーダーが素材の体にも使える形になっている。issue-46 で、素材の入口（assetSlots.ts）も1か所にまとまった。

素材のほうは、変換が済んでいる。

- 基準姿勢の人型（X Bot、腕を広げた姿勢）: 1.8 MB、ボーン 65 本、メッシュ 2 つ（胴と関節）
- 姿勢つきの人型 23 本（立つ、しゃがむ、座る、寝る、踊る、走るなど）: 1 本あたり約 1.7 MB。どれも同じ体と同じ骨で、ポーズだけが違う（骨の姿勢として書き出してあり、アニメーションなし）

本 issue では、仮のカプセルを素材の体に差し替え、隠れ側が自分のポーズを選べるようにする。ポーズは、全種類を並べて選ぶ画面は作らず、「ポーズ」ボタンを押すたびに、ランダムに変わる形にする（23種類から探す手間を、避けるため）。

ペイントは、簡略版（胴1本の円柱）のまま変えない。5本の円柱（腕・脚を分ける）は issue-54。

優先度は、平屋の表示（issue-46）の次。遅れた場合は、仮のカプセルのまま出す。

## スコープ

### このissueでやること

- 体の作り方を決める（実装の前に提案して、確認を取る）
  - 案A: ポーズごとの glb（約 1.7 MB）を、選ばれたものだけ読み込む
  - 案B（推奨の見込み）: 体の glb を1つだけ配り、ポーズは「骨の姿勢の表」（23 種類 × 65 本。数 KB）として配る。実行時に、体の骨へ姿勢を当てる。ポーズボタンを押したとき、読み込みを待たずに、すぐ変わる。issue-46 の家具の箱と同じく、小さな glb の extras に入れて配る形にすれば、ローダーを増やさずに済む
  - 前提の確認: 23 本のポーズの glb が、同じ体・同じ骨の名前（mixamorig:）か。X Bot の体と、同じ骨の構成か
- 体を作る口に、素材を渡す
  - 足もとが床につくように置く。大きさは、立ち姿の基準（足もとから頭までの高さ）で決め、ポーズごとの外接箱では決めない（寝る・座る姿勢が、拡大されないため）。足もとの高さは、issue-46 の床の高さの追従と、同じ仕組みを使う
  - 描き込みのシェーダーを、スキンつきのメッシュで動かす。ペイントが、ポーズをとった体について行くこと（描き込み面の座標は、基準姿勢の頂点位置から求める）
  - 胴と関節の2つのメッシュの両方に、描き込みを適用する
  - ペイント画面でタップした位置の、描き込み面の座標は、当たった面の基準姿勢の位置から求める（どのポーズでも、同じ場所に塗れる。方式は、実装の前に提案する）
- ポーズのランダム変更
  - ペイント画面に、「ポーズ」ボタンを足す。押すたびに、いまのポーズとは違うポーズを、ランダムに選び、自分の体にすぐ反映する
  - 選んだポーズは、ペイントの確定と同じ時点（フェーズの終わりの2秒前、または「塗り終わり」）で、一度だけサーバーに送る。何も塗っていなくても、ポーズを変えていれば送る
  - サーバーは、探索の開始の一括配信に、人間の隠れ側のポーズも載せる（いまは null）。ポーズが届かない人（送らなかった人）は、既定の立ち姿
  - ポーズの値は、決まった一覧（識別子の一覧）の中だけを受け付ける。一覧にない値は、無視して null と同じ扱い。一覧は、TS とサーバー（CPU のポーズと同じもの）で、共有の見本（fixtures）にして、両方で読む（ADR 0009）
  - 契約の変更は、veryare の payload だけ。外側の電文は変えない。ペイントフェーズの間は、誰にも通知しない（他の人に見えない。ADR 0025・0035）
- 隠れ CPU と鬼の体
  - 隠れ CPU のポーズ（サーバーが送る値）を、素材のポーズに対応づける
  - 鬼の体（赤い体）は、素材の体に赤みをつけ、立ち姿に固定する
- 読み込み
  - issue-43 のローダーと、issue-46 の素材の入口（assetSlots.ts）を使い、待機ルームの間に、仮のカプセルから差し替える
  - 読み込めない、または壊れているときは、仮のカプセルのまま動く（警告は出さない）。ポーズボタンは、素材がないときは出さない
- 鬼の画面の、隠れ側の体の表示（探索の開始に届くペイントとポーズ）と、答え合わせの赤い点滅が、素材の体でも動く

### このissueでやらないこと

- 5本の円柱、スキンの重みによる部位の割り当て（issue-54）
- ポーズを一覧から選ぶ画面（ポーズの名前と見た目の一覧。必要なら別 issue）
- アニメーション（歩く、走る）
- 素材の追加・加工の作り直し
- 素材の配信の仕組みそのもの（issue-43）

## 設計方針

- 素材（glb、骨の姿勢の表）は公開リポジトリに入れない（ADR 0040、`docs/assets.md`）。ゲームのコードに、素材のファイル名を直接書かない。manifest の key で指す
- 純粋関数（正規化、ポーズの識別子と素材の対応、フォールバックの判断、ランダム選び）は、テストを先に書く。ランダム選びは、乱数を注入できる形にし、「いまと同じポーズを選ばない」「一覧のすべてが選ばれうる」を確かめる
- 素材が無いときの動き（仮のカプセル）が基準で、素材は上乗せとする。`make verify` は素材に頼らない
- 描画の軽さを守る。同時に描く体は最大 5 つ。素材の頂点数（胴 約 1.4 万、関節 約 1 万）で、スマホの描画が重くならないことを、目視で確かめる
- ポーズが、隠れやすさに影響する（寝る姿勢は低く見える、など）。ここでは調整せず、リハーサルで確かめる
- 素材の規約: Mixamo の規約の写しを、`assets-src/licenses/` に保存してから配信する
- ポーズの識別子（英数字のみ）と、表示名（日本語）は、別に持つ。識別子は、素材のファイル名から作るが、ゲームのコードには、識別子だけを書く

## 受け入れ条件

- 素材が読み込めるとき、遊ぶ人、CPU、鬼の体が、素材の人型で描かれる（目視）
- 素材が読み込めないとき、仮のカプセルで最後まで遊べる（テストで確認）
- 「ポーズ」ボタンを押すたびに、ポーズが変わり、同じポーズが続けて出ない。23 種類のすべてが出うる（テストで確認）
- ペイントが、素材の体に映り、ポーズをとった体について行く。継ぎ目をまたいでも切れない。ポーズを変えたあとでも、同じ場所に塗れる（目視）
- 選んだポーズが、探索の開始に、鬼と他の隠れ側の画面へ届く。ペイントフェーズの間は、他の人に届かない（サーバーのテストで確認）。一覧にない値は、無視される（テストで確認）
- ポーズの一覧が、TS・サーバー・共有の見本で一致する（テストで確認）
- 鬼の画面で、隠れ側の体が、塗った色とポーズで見える。答え合わせの赤い点滅が、素材の体の上に重なる（目視）
- 寝る・座る姿勢で、体が床に沈まず、浮かない（目視。純粋関数で、足もとの高さの計算をテストで確認）
- 隠れ CPU のポーズの値が、すべて素材に対応づく。未知の値は、既定の立ち姿になる（テストで確認）
- スマホの縦画面で、5 人ぶんの体を描いても、重くない（目視）
- `make verify` が通る

## 段階

1. 素材の一覧（assets-src/converted/characters/）と、サーバーが送るポーズの値を確かめ、体の作り方（案A・案B）、ポーズの識別子の一覧、ペイントの座標の方式を提案して、一度止まる
2. 正規化、ポーズの対応、ランダム選びを、テストを先に書いて実装する
3. 素材の変換（体の glb の圧縮、ポーズの表の作成）の道具を、tools/ に足す。manifest に載せる
4. 体を作る口に素材を渡す。描き込みのシェーダーを、スキンつきのメッシュで動かす
5. ポーズのランダム変更（ボタン、サーバーの受け付け、一括配信への追加、共有の見本）を実装する
6. issue-43 のローダーで、読み込みと差し替えを組み込む。失敗のときの仮のカプセルを、テストで確かめる
7. bots のシナリオに、ポーズの確定と一括配信（ペイントのシナリオと同じ形）を足す
8. 素材を配信に置く手順を docs/assets.md に書き、目視で確かめる項目を、報告にまとめる

## 進捗

- 2026-10-12: 段階 1 の提案（案B、識別子の一覧、基準姿勢の位置から (u, v) を求める方式、足もとの計算、確定の電文への pose の追加）が確認された。段階 2〜8 を実装した
  - 体の高さを 1.6 m にそろえた（仮のカプセルも）。目の高さ・狙いの当たりの円柱・描き込み面の範囲は `bodySize.ts` から決める。カメラの高さの上限 `CAMERA_MAX_HEIGHT`（足もとから 1.85 m）を入れた（入れないと和室B で襖の板の上端を越えるため）
  - 素材の道具 `tools/character_assets.mjs`（体の glb とポーズの表の glb）。manifest の key は `character-body`・`character-poses`
  - 契約: ペイントの確定に `pose` を足し、`paint` を null にできる形。サーバーは一覧の識別子だけを受け付け、探索の開始の一括配信に載せる。ボットに「ポーズの確定と一括配信」を足した
  - Mixamo の規約の写しの保存と、配信への配置は、人の作業として残る
