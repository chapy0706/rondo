# issue-40: ロビーからゲーム画面への導線

## 背景

issue-31 で、Gleam サーバーとクライアントが WebSocket で繋がった。ルームを作成した側は、ゲーム画面で遊べる。しかし、ロビーで一覧から参加した側には、ゲーム画面へ入る導線がない。参加は成立していても、画面はロビーのままである。

このため、2人目以降がゲーム画面で遊ぶ形の確認ができていない。10/10〜12 のマイルストーン1（鬼選出から結果まで、2〜3タブで通る）の前提になる。

## スコープ

### このissueでやること

- ロビーでルームに参加できた（room-joined を受け取った）ら、そのゲームの画面へ遷移する
- 作成した側と同じゲーム画面を使い、参加済みのルームに対して画面を開く
- 遷移した時点で、サーバーがすでに送った現在の状態（フェーズ、エリアの色など）を、画面が表示できる
  - 途中参加の人に今の状態を送る仕組みは、issue-31 前半で実装済み
  - 遷移前に届いた通知を、画面が取りこぼさないようにする
- ゲーム画面から退出したら、ロビーに戻れる
- 再接続で復帰したとき（issue-31 後半）に、正しい画面にいる
- モックでも同じ導線が動く

### このissueでやらないこと

- ゲーム固有のロジックの変更
- ロビーの見た目の作り込み
- Tilt Maze（rolling）の実接続
- 契約と Gleam 側の変更（必要になった場合は、理由を報告して止まる）

## 設計方針

- 遷移先の決め方と、ルームの状態の保持場所（アダプタか画面か）は、既存の実装を読んで提案する
- ゲームの種類ごとの分岐は、ゲーム登録（registry）の側に寄せ、ロビーはゲームの中身を知らない形を保つ
- 通っていない機能は選択画面に出さない

## 受け入れ条件

- 2つのタブで、タブ A がルームを作成し、タブ B がロビーから参加すると、タブ B もゲーム画面に入る
- タブ B の画面にも、円の色の変化（赤・緑・青）が表示される
- タブ B が退出すると、ロビーに戻る
- 参加後にタブ B をリロードまたは切断しても、猶予内なら元の画面に戻れる
- モックでも導線が動く
- `make verify` が通る

## 段階

1. ロビー、ゲーム画面、アダプタ、registry の現状を読み、遷移の方式を提案する
2. 遷移を、テストを先に書いて実装する
3. 遷移直後の状態表示を確認する
4. 退出と戻りを実装する
5. 再接続時の画面を確認する
6. 2タブでの確認手順を報告にまとめる
