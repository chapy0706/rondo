# issue-53: veryare の仕上げ（ポーズ、アニメーション、BGM、待機ルーム）

## 背景

issue-29（ステージ統合）を分けたとき、マイルストーン1（鬼選出から結果まで、2〜3タブで通る）に要らない見た目の仕上げを、本 issue に集めた。マイルストーン1の後に着手する。遅れたら切る（切っても、ゲームは遊べる）。

キャラクターのモデル（Mixamo の X Bot）の組み込みは issue-25 で扱う。

## スコープ

### このissueでやること

- ポーズ（立つ・しゃがむ・寝そべる / issue-33 の仮の3種類）の切り替えの操作と、見た目
- Idle / Walk / Run のアニメーションの切り替え（入力の強さに応じる）
- BGM の組み込み（czz の既存の素材を流用する。新しく作らない）
- 待機ルームの作り込み（円柱形、半径の目安 2 m、ステージとは別の空間として仕上げる）

### このissueでやらないこと

- キャラクターのモデルの組み込み（issue-25）
- ステージの表示（issue-29c、平屋は issue-46）
- 答え合わせタイムの演出（issue-29d）

## 設計方針

- ADR 0028・0034・0035 に従う
- 判断（入力の強さからアニメーションを選ぶ、ポーズの切り替えの条件）は純粋関数にし、テストを先に書く
- 素材は公開リポジトリに入れない（`docs/assets.md`）。BGM は czz で使っている素材の扱いに合わせる

## 受け入れ条件

### 自動で確かめること

- 入力の強さから Idle / Walk / Run を選ぶ判断が、しきい値の前後で切り替わる（純粋関数のテスト）
- ポーズの切り替えが、切り替えられるフェーズ・役割のときだけ通る（純粋関数のテスト）
- `make verify` が通る（TS・Gleam 双方）

### 目視でしか確かめられないこと

- ポーズとアニメーションの見た目と、切り替えの滑らかさ
- BGM が流れ、音量が大きすぎない。スマホで音が出る
- 待機ルームの見た目（ステージとは別の空間に見える）

## 段階

1. アニメーションとポーズの判断を、テストを先に書いて実装する
2. 見た目につなぐ
3. BGM を組み込む
4. 待機ルームを作り込む
5. 確認手順を報告にまとめる
