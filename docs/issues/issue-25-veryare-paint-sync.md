# issue-25: veryare ペイント（5本円柱投影）と状態の一括配信

簡略版（胴1本の円柱）を実装済み。残りは issue-54 に移す。

## 背景

隠れ側が擬態のために体へ施すペイントを実装し、フェーズ終了時に一括で同期する（ADR 0025）。描き方は、5本の円柱（胴・左右の腕・左右の脚）へ描いて体へ投影する方式とする（ADR 0037）。あわせて、探索フェーズ開始時に、隠れ側全員の状態を全員へ一括配信する（ADR 0025・0035）。

## 前提（人手作業）

- Mixamo の X Bot を glTF（.glb）に変換したものを用意しておく。頂点の部位割り当てにスキン情報（ボーンの重み）を使うため、ポーズ付きのモデルではなく、基準姿勢（腕を広げた直立）のモデルが必要になる。変換の手順は Claude Code では実行できないため、ユーザーが Blender で行う

## スコープ

### このissueでやること

- 描き込み面: 5部位（胴・左腕・右腕・左脚・右脚）を領域として並べた1枚のキャンバス
- 体への反映: シェーダーで、頂点の基準姿勢での位置から、割り当てた部位の円柱上の位置を求め、描き込み面を参照する。UV は使わない
- 頂点の部位割り当て: スキンの重みが最も大きい部位に割り当てる。モデル読み込み時に計算する
- ペイント画面: 基準姿勢で表示し、タップを円柱への交差判定で描き込み面の座標に変換して描く。色はグラデーション全色とスポイト、ブラシの大きさ。描き終えたら選んだポーズで表示する
- ストロークの保持（描き込み面の座標）。ペイントフェーズ中はローカル状態のみで完結させる
- フェーズ終了時、ストロークを一度だけサーバーへ送る
- 探索フェーズ開始時、サーバーが、まだ隠れている隠れ側全員の状態（位置・向き・ポーズ・確定したペイント）を、全員へ同じ内容で一括配信する。クライアントは受信したペイントを、同じ体シェーダーで描画する
- 導入は段階的でよい。まず胴の円柱だけで一通り動かし、次に腕・脚を分ける。ある部位の設定が難しければ、胴の円柱で代用して先に進む

### このissueでやらないこと

- ペイントの逐次同期（ADR 0025）
- 被り判定（issue-26）
- 頭の専用円柱、手や足先の細かい塗り分け

## 設計方針

- ADR 0025・0035・0037 に従う
- ペイントフェーズ中は他プレイヤーに自分のペイントを見せない（ゲームの面白さのため。ADR 0035 で維持するもの）
- ストロークと描き込み面の型は packages/contracts に定義する
- 受け入れの基準は ADR 0028 に従う

## 受け入れ条件

- グラデーション全色から色を選び、スポイトで既存の色を拾える
- 胴・腕・脚を塗り分けられ（段階的導入の途中の状態を除く）、塗った内容がリアルタイムに体へ映る
- ポーズを変えても、塗りが体の同じ部位に付いてくる
- ペイントフェーズ中、他プレイヤーには自分のペイントが見えない
- フェーズ終了時に一度だけストロークが送信される（逐次送信されないことをテストで確認する）
- 探索フェーズ開始の瞬間に、隠れ側全員の位置・向き・ポーズ・ペイントが全員へ届き、受信側で同じ見た目に描画される
- `make verify` が通る

## 段階

1. contracts に、ストロークと描き込み面の型を定義する
2. 頂点の部位割り当てと、円柱座標の計算を、純粋関数としてテストファーストで実装する
3. 体シェーダーで、描き込み面を体へ反映する（まず胴の円柱のみ）
4. ペイント画面（タップ → 円柱交差 → 描画、色選択・スポイト・ブラシ）を実装する
5. フェーズ終了時の一括送信と、探索開始時の全員宛ての一括配信を実装する
6. 受信側の描画を実装する
7. 腕・脚の円柱を分ける
