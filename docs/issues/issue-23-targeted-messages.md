# issue-23: プレイヤー限定メッセージの実装

## 背景

めっちゃカメレオン風ゲームでは、鬼に隠れ側の位置を送らない、観戦者にまだ隠れている全員の位置を送らないなど、プレイヤーごとに異なる内容を配信する必要がある。この issue はサーバー側（server/）と契約（packages/contracts）に閉じており、issue-22（クライアント側の入力拡張）とは独立して着手できる。

## スコープ

### このissueでやること

- `packages/contracts` の `ServerMessage` に、宛先プレイヤーIDを持つメッセージ種別（targeted message）を追加する
- `server/src/protocol/message.gleam` に対応する型を追加する
- room_actor が、宛先を選んで配信できるようにする（該当しないプレイヤーの接続には送信しない）
- `packages/game-sdk` の `useRealtimeGame` が、限定配信メッセージも既存のブロードキャスト型と同様に受け取れるようにする

### このissueでやらないこと

- カメレオン風ゲーム本体の実装（後続issue）
- 既存のブロードキャスト型メッセージ（`game-state`）の変更

## 設計方針

- 既存のブロードキャスト配信は変更しない。追加のみで対応する（ADR 0021）
- 隠すべき情報は、そもそも該当しないプレイヤーの接続に送信しない。クライアント側でのフィルタでは実現しない（ネットワーク上に情報が漏れるため）
- ゲームコードからは、ブロードキャストか限定配信かの違いを意識させない型にする

## 受け入れ条件

- サーバーが特定のプレイヤーIDにのみメッセージを配信できる
- 宛先でないプレイヤーの接続には、該当メッセージが一切送信されないことがテストで確認できる
- `useRealtimeGame` の `on` で、限定配信メッセージも受け取れる
- `make verify` が通る（TS・Gleam 双方）

## 段階

1. `packages/contracts` に targeted message の型を追加する
2. `server/src/protocol/message.gleam` に対応する型を追加する
3. room_actor に、宛先を選んで配信するロジックを実装する
4. `useRealtimeGame` 側の受信処理を対応させる
5. 「宛先でない接続には送信されない」ことをテストで確認する

## 関連

- ADR: 0021 / 0008（サーバー権威はゲームごと）
- 独立: issue-22（同時並行で着手可能）
- 後続: カメレオン風ゲーム本体の各issue（当たり判定、観戦モード等）
