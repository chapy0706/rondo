# issue-21: czz の既存 UI 資産の移植

## 背景

issue-20 で czz が最小構成で遊べる状態になった。本 issue では、czz 本体が持つ UI 資産を段階的に移植し、発表会で見せられる完成度に引き上げる。

調査（docs/czz-inventory.md）によれば、CommandBuilder は認証を import せず task / userId? を props で受け取るだけで、結合点は実質 `evaluateClient.ts` の fetch 1か所である。その fetch は issue-20 でローカル呼び出しに置き換わっているため、UI 側は比較的素直に持ち出せる。

ただし UI 群は20以上のファイルに加えて zustand・Tailwind・音声資産を伴うため、一度にではなく部分ごとに移す。

## スコープ

### このissueでやること

- CommandBuilder を中心とした既存 UI の移植
- 付随する状態管理（zustand）の移植、または rondo 側の状態管理への置き換え
- スタイル（Tailwind）の適合
- 音声資産の移植（必要と判断した場合）

### このissueでやらないこと

- 進捗保存・アカウント機能
- お題の追加・編集機能（admin 相当）

## 設計方針

- 移植は部分ごとに行い、各段階で動作する状態を保つ。一度に全部を入れ替えない
- 認証・DB への依存を持ち込まない。props で渡す形を維持する
- czz 側の状態管理をそのまま持ち込むか、rondo の既存の作法に寄せるかは、移植量を見て判断する
- スマホの縦画面・タッチ操作で成立することを確認する（ADR 0012）
- 音声資産は容量と読み込み時間に影響するため、必要性を見て取捨する（rondo の非機能要件「起動が速く軽いこと」）

## 受け入れ条件

- CommandBuilder による操作で問題が解ける
- 各移植段階の完了時点で、ゲームが動作する状態が保たれている
- 認証・DB への依存が持ち込まれていない
- スマホの縦画面で操作できる
- `make verify` が通る

## 段階

1. CommandBuilder とその直接の依存を移植する
2. 状態管理を移植、または rondo 側の作法に置き換える
3. スタイルを適合させる
4. 音声資産の要否を判断し、必要なら移植する
5. スマホ実機で操作性を確認する
