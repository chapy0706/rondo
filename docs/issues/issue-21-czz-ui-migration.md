# issue-21: czz の磨き込み（既存UI資産を必要な分だけ移す）

## 背景

issue-20 で、czz が最小構成で遊べる状態になった。本 issue では、発表会で見せられる完成度に近づけるため、czz 本体が持つ UI 資産のうち必要な分だけを移す。

調査の結果、CommandBuilder をほぼ全部移す案は、13〜16 ファイルに加えて zustand の追加と 104 か所のテーマ用クラスの置き換えが必要で、書き換える量が多い割に得るものが少ないと分かった。そのため「丸ごと移植」は行わない。以下の候補から、優先度の高い順に、1つずつ独立して入れる。

各候補は互いに独立しており、途中で止まっても、遊べる状態が保たれるようにする。

## スコープ

### このissueでやること（候補。上から優先）

1. マスコット・キャラクター演出: czz が持つ、初心者向けページで使われていたマスコットを取り込む。既存アセットをそのまま使い、新規に作らない
2. BGM・効果音: czz の既存音声アセットをそのまま組み込む。command-builder には絡んでおらず、独立して追加できる
3. UNIX 表記の表示: 組み立てた命令列を、`cat input.csv | sort -n | head -n 1` のような1行で、読み取り専用に表示する。issue-20 のカタログにある UNIX 表記のデータを使う
4. 並べ替えと3段お題: 命令の並べ替え（上下ボタン程度。czz 本体にもドラッグ操作は無い）を入れ、命令が3段のお題（T16〜T20）を出題対象に加える
5. 初心者向けと UNIX 表記の切り替え: 切り替えはメモリ上だけで持ち、保存しない
6. 結果表示: 基盤の結果画面との整合

優先1・2は、既に動作実績のある既存アセットをそのまま持ち込むだけであり、実装コストは小さい。IT初心者が9割を占める発表会の想定（見た目・音の手触りを先に作る）に合わせ、機能面（3〜5）より先に着手する。

### このissueでやらないこと

- CommandBuilder の丸ごと移植
- zustand、zustand persist、localStorage による保存（ADR 0019）
- Runner I/O ルール（採点に含めない方針を維持する）
- 進捗保存・お題の追加編集機能（admin 相当）

## 設計方針

- 1つの候補ごとに、動作する状態で完結させる。途中で止まっても遊べる状態を保つ
- 認証・DB・fetch への依存を持ち込まない
- スタイルは rondo の Tailwind v4（slate 系）で書き、基盤側に定義を足さない
- スマホの縦画面・タッチ操作で成立することを確認する（ADR 0012）
- 音声は rondo の非機能要件「起動が速く軽いこと」に照らして取捨する

## 受け入れ条件

- 実施した候補ごとに、遊べる状態が保たれている
- 認証・DB・外部通信への依存が持ち込まれていない
- スマホの縦画面で操作できる
- `make verify` が通る

## 段階

1. 候補1（UNIX 表記の表示）を実装する
2. 候補2（並べ替えと3段お題）を実装する
3. 時間と状況を見て、候補3〜5 から選んで実装する
4. 作業がすべて済んだら、.reference/czz/ を削除する。Claude Code は rm -rf が禁止されているため、ユーザーが自分のターミナルで手動で行う
