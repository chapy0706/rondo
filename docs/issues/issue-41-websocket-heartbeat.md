# issue-41: WebSocket のハートビート

## 背景

Cloudflare は、通信のない WebSocket 接続を、一定時間で切ることがある。目安として100秒前後という数字が、issue-31 の報告に挙がっている。数字は、実装前に公式ドキュメントで確かめる。

veryare の待機ルームのように、誰も動かず通知も出ない時間が続くと、接続が切れる場合がある。切れても再接続の仕組み（ADR 0013、10秒の猶予）はあるが、復帰が猶予内に間に合わなければ、離脱扱いになる。

発表会では待ち時間が普通に発生するため、無通信で切れないようにする。

## スコープ

### このissueでやること

- Cloudflare の無通信切断の条件を、公式ドキュメントで確認する（報告に出典と数値を含める）
- 無通信でも接続が維持されるよう、定期的に小さな通信を流す仕組みを入れる
  - 方式は、WebSocket のプロトコル上の ping/pong フレームを優先して検討する。契約（messages）の変更が不要になるため
  - mist が ping/pong をどこまで扱えるか確認し、方式を提案する。アプリ層の電文が必要な場合は、契約の変更として ADR 0009 に従う
  - 間隔は、切断条件の半分程度を目安に、設定で変えられるようにする
- 応答のない接続を検知する
  - 一定時間 pong または通信がなければ、切断として扱い、再接続の猶予（10秒）に入る
- 間隔と待ち時間は、テストで差し替えられるようにする

### このissueでやらないこと

- ゲーム固有のロジックの変更
- 猶予の長さ（10秒）の変更
- 実際の Cloudflare 経由での長時間確認の自動化（手動の確認手順を報告に含める）

## 設計方針

- 接続アクターの中に閉じ込め、ルームアクターやゲームには影響させない
- 時間はすべて注入可能にし、テストファーストで書く
- 送るデータは小さく保つ。通信量と電池への影響を意識する
- ハートビートの停止が、ゲームの進行に影響しないことを確認する

## 受け入れ条件

- 無通信の接続に、設定した間隔で ping が送られる（テストで確認）
- クライアントの応答がなければ、一定時間後に切断として扱われ、猶予に入る（テストで確認）
- 通信のあるときに、余計なハートビートで問題が起きない
- 本番で2〜3分、誰も操作しない待機ルームが維持されることを確かめる手順が、報告に含まれている
- `make verify` が通る

## 段階

1. Cloudflare の無通信切断の条件を確認する
2. mist の ping/pong の扱いを確認し、方式を提案する
3. サーバー側の送信と、応答なしの検知を、テストを先に書いて実装する
4. クライアント側が、pong を返せることを確認する（ブラウザは通常、自動で返す）
5. 本番での確認手順を報告にまとめる
