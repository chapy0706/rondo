# issue-29c: クライアントの仮素材のステージ表示と移動、襖を開けるボタン

## 背景

issue-29（ステージ統合）を4本に分けたうちの3本目。issue-29a・29b で、サーバーが、選ばれたステージの地図（ステージの通知）と襖の状態（襖の通知）を配り、同じ移動の規則で位置を確かめるようになる。

いまのクライアントのステージは、仮の ±5 m の床で、サーバーの地図とは関係が無い。本 issue で、クライアントは、ステージの通知から床と壁を箱で組み（画像や glb は使わない）、サーバーと同じ移動の規則で自分の移動を止める。

本素材版（平屋の glb）は issue-46 で扱う。本 issue の箱の表示は、issue-46 で素材が届かないときの表示（フォールバック）としても使う。

## スコープ

### このissueでやること

- ステージの通知・襖の通知を、境で検証して読む（形の違うものは捨てる）
- 仮素材の表示（three.js。箱と床だけ）
  - 歩けるマスごとに床。領域（廊下・部屋・縁側・玄関）と部屋の割り当てで色を分ける
  - 異なる領域どうしの境（戸のある境を除く）に、薄い壁の箱
  - 襖は、襖の境に立つ板の箱。開いている襖は表示しない（または開いた位置へずらす）
  - 地図から箱の一覧を作るところは純粋関数にし、three.js の組み立てと分ける
  - いまの ±5 m の床をやめる
- 移動
  - サーバーと同じ移動の規則を TS で持ち、自分の移動を手元で止めて、境に沿って滑らせる
  - ステージへ移るとき、ステージの通知のリスポーン位置（玄関）から始める
- 襖を開けるボタン
  - 閉じた襖の境から 1.5 m 以内にいるとき、いちばん近い閉じた襖を開けるボタンを出す（どの襖を出すかは純粋関数）
  - 押すと、開ける報告を送る。開いたかどうかは、襖の通知で表示を変える
- カメラ（TPS / ADR 0034）・入力（2本のパッド）・射撃（issue-27）の操作は変えない

### このissueでやらないこと

- 答え合わせタイムの演出（issue-29d）
- 歩く速さの調整（issue-29d）
- 平屋の glb・屋根の切り替え・ステージの選択肢（issue-46）
- キャラクターのモデル（issue-25）、ポーズ・アニメーション（issue-53）

## 設計方針

- ADR 0034・0035・0042（下書き）に従う
- 移動の規則は、サーバーと同じ入力で同じ結果になることを、issue-29a の共有の見本で確かめる
- 判定（箱の一覧、ボタンを出す襖、通知の読み取り、移動の規則）は純粋関数にし、テストファーストで進める
- 受け入れの基準は ADR 0028 に従う

## 受け入れ条件

### 自動で確かめること

- 移動の規則が、issue-29a の共有の見本（移動の前後の位置 → 止まる位置）をすべて期待どおりに通る（Gleam と同じ見本を読む）
- ステージの通知・襖の通知の読み取りが、共有の見本の valid を受け付け、invalid を捨てる
- 地図から作る箱の一覧
  - 歩けるマスの数だけ床がある
  - 壁は、異なる領域どうしの境にだけあり、戸のある境には無い
  - 襖の板は、閉じている襖にだけある
- 開けるボタンを出す襖の判断: 閉じた襖の境から 1.5 m 以内でだけ出る。いちばん近い襖を選ぶ。開いている襖には出ない
- `make verify` が通る（TS・Gleam 双方）

### 目視でしか確かめられないこと

- 床・壁・襖の箱の見た目（部屋と廊下の見分けがつく、壁の位置がサーバーの地図と合う）
- 壁と閉じた襖で移動が止まり、壁に沿って滑る手触り
- 玄関から始まる
- 襖の近くでボタンが出て、押すと2つのタブの両方で襖が開く
- スマホの縦画面で操作できる

## 段階

1. ステージの通知・襖の通知の読み取りを、テストを先に書いて実装する
2. 移動の規則を TS に写し、共有の見本で確かめる
3. 箱の一覧を作る純粋関数を、テストを先に書いて実装し、three.js で組む
4. 移動をステージの規則に切り替え、玄関から始める
5. 襖を開けるボタンを付ける
6. 2タブでの確認手順を報告にまとめる
