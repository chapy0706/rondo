# issue-33: CPU の基盤と隠れ CPU

## 背景

CPU プレイヤー（ADR 0038）の土台と、実装の簡単な隠れ CPU を作る。1台でも遊べるようにし、開発中の動作確認も楽にする。

## スコープ

### このissueでやること

- ルーム作成時の選択肢（roomOptions）に「CPU：なし／隠れ側 CPU 1〜3体／鬼 CPU」を追加する（contracts と、ロビーのプルダウン）
- CPU を、識別子 `cpu-N`、表示名「CPU N」の参加者としてルームに加える。定員（5人）と最小人数（2人）の判定に数える
- クライアントが、CPU を通常のプレイヤーと同じように扱えることを確認する
- 鬼 CPU を選んだ場合は、鬼選出フェーズを省いて CPU を鬼にする（鬼 CPU 自体の動きは issue-34）。隠れ側 CPU は、鬼選出に立候補せず、抽選の対象にもならない
- **色の表**: 部屋タイプごとの代表色を、データとして持つ。隠れ側のペイントの平均色との差を 0〜1 に正規化する純粋関数を実装する（issue-34 でも使う）
- **隠れ CPU**: 準備移動の間に、部屋スロット内のマスから、他の隠れ側と被らないようにランダムに位置を選ぶ。ポーズをランダムに選ぶ。ペイントは、その場の代表色で全面を1色に塗る。準備移動の終了時点で状態を確定させ、人間の隠れ側と同じ経路で配信されるようにする
- 乱数は種を引数に取る。種を固定したテストを書く
- CPU が置く座標は骨格のマス座標とする。game.gleam の仮の移動範囲（中心から ±5m）が障害になる場合は、骨格の範囲に合わせる

### このissueでやらないこと

- 鬼 CPU の動き（issue-34）
- 色の表の値を、実際のモデルの平均色に合わせる作業（モデルが揃った後に調整する。最初は仮の値でよい）

## 設計方針

- ADR 0038・0035・0028 に従う
- CPU は勝敗と「まだ隠れている」集合に、通常のプレイヤーと同じように入る
- CPU 固有の分岐を、ゲームの状態機械に増やしすぎない。参加者の一種として扱う

## 受け入れ条件

- ルーム作成時に CPU の選択肢が選べ、選んだ構成で CPU が参加する
- CPU を含めて最小人数に達し、1人の人間と CPU だけで対戦を開始できる
- 隠れ CPU が、他の隠れ側と被らない位置に、ポーズとペイント付きで確定する
- 隠れ CPU の状態が、探索開始時の一括配信に載る
- 鬼 CPU を選ぶと、鬼選出フェーズが省かれる
- 色の差の関数が、同色で 0、最も離れた色で 1 になることをテストで確認する
- `make verify` が通る（TS・Gleam 双方）

## 段階

1. contracts に CPU の選択肢を追加し、ロビーに出す
2. CPU 参加者の追加と、定員・最小人数への算入をテストファーストで実装する
3. 鬼選出の扱い（鬼 CPU の場合の省略、隠れ側 CPU の除外）を実装する
4. 色の表と、色の差の純粋関数を実装する
5. 隠れ CPU の配置・ポーズ・ペイントを実装する
6. クライアントでの表示を確認する
