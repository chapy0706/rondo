# issue-72: ランダム間取りの和室に、平屋の小物を置く（第1段階: 低い小物だけ）

## 背景

ランダム間取りは、床・壁・襖を、箱と材質で組んだ、がらんとした部屋で、遊ぶと、少し寂しい。平屋のモデルには、座卓、座布団、タンス、掛け軸、行灯などの小物がある。その一部を、ランダム間取りの和室に置いて、和風の部屋らしくする。

ただし、小物を置くと、ゲームの判定とぶつかる所がある。

- 判定（移動、見通し、射撃）は、地図の壁と戸だけを見ている。家具は判定にない（ADR 0039）。体は、小物をすり抜けて歩ける
- 背の高い家具は、見えない所を作る。ところが、狙いの当たり（タップした点から線を引いて、体に当てる）は、家具を遮る物として見ていない。見えない隠れ側を撃てる食い違いが生まれる
- カメラの守りは、家具の箱を知らない（平屋では、家具の箱の一覧を使っている）

そこで、本 issue（第1段階）では、**低い小物だけ**を置く。背が低い物は、見えない所を作らず、狙いの食い違いも、カメラの守りの変更も、要らない。見た目だけの追加として、判定には触れない。背の高い家具（第2段階）は、発表会のあとの、別の issue とする。

優先度は、実機の確認と、観戦ルーム（issue-67）の後。凍結（10/23）までに入らなければ、発表会のあとに回す。

## スコープ

### このissueでやること

- 小物のキットを作る（tools/、素材は assets-src の下。コミットしない）
  - 平屋の元の glb（assets-src/house/ の下）の、葉のメッシュから、低い小物を、1 つずつ取り出す（座卓、座布団、花瓶、低い箱など。候補は、調べて決める）
  - 足もとの中心を原点にそろえ、まとめた glb（key: room-props）にする。meshopt で圧縮する。小物ごとのノードに、extras として、幅・奥行き・高さ（メートル）を持たせる
  - 高さの上限は、定数（初期値 0.5 m）。寝る姿勢の体の高さ（0.33〜0.55 m）を超える物は、見えない所を作りうるので、上限を超える物は、第 1 段階に入れない。調べた結果で、上限を決め直してよい（根拠を報告に書く）
  - 大きさの目標は、2 MB 以下。manifest に載せる（tools/make_manifest.mjs）
- 置き方を決める純粋関数（クライアント。サーバーと契約は変えない）
  - 入力: 部屋（スロット）の矩形、襖の向き、部屋の種類（和室系）、乱数の種（地図の文字列から作る）
  - 出力: 置く小物の一覧（小物の種類、位置、向き）
  - 同じ地図なら、全員の画面で、同じ置き方になる（決定的）
  - 型を 2〜3 通り持ち、種で選ぶ（襖の反対側を奥とする）
  - 守る条件: 部屋の内側に収まる（壁から一定の余白）。小物どうしが重ならない。襖から部屋の中央までの通り道（幅 0.9 m）を、ふさがない
  - 置く場所: 和室系の、大きなスロットだけ。押し入れ、廊下、縁側、玄関には置かない。平屋には置かない（すでにある）
- 描画（クライアント）
  - 小物の種類ごとに、1 つの InstancedMesh にまとめて描く（描画の呼び出しの数を、小物の種類の数に抑える）
  - 素材の入口（assetSlots.ts）に、room-props の差し替え口を足す。ランダム間取りのときだけ読み、待機ルームの間に 1 回だけ受け取る。読めない、または形が違うときは、小物なしで動く（警告は出さない）
  - 旗 PROPS_READY（既定 false）の裏に置く。旗が false のとき、何も読まず、何も出さない。開発用の合図（NEXT_PUBLIC_VERYARE_HIRAYA、または ?roof=1）のときだけ、旗に関わらず出せる
  - 小物は、判定にも、カメラの守りにも、狙いにも、入れない（見た目だけ）。ペイントのスポイト（見えている一番手前の面の色）は、小物の色も拾ってよい（既存の仕組みのまま）
- 描画の重さを測る（10 種の最大の骨格と、広い屋敷の骨格で）: 小物の数、三角形の数の増え、描画の呼び出しの数。目標: 三角形の増えは、全体で 3 万以下。実機（iPhone）で、重くならないこと
- ADR（番号は最新の次。下書き）: ランダム間取りの小物は、見た目だけで、判定に入れない（ADR 0039 の考えの延長）。第 2 段階の条件（背の高い家具は、狙いの遮りとカメラの守りが要る）を書く

### このissueでやらないこと（第2段階。発表会のあとの別 issue）

- 背の高い家具（タンス、屏風など）。狙いの線を、家具の箱で遮る変更、カメラの守りへの箱の追加、ゲームバランス（物陰が増える）の確認が要る
- 壁に掛ける物（掛け軸）の置き方
- 小物の当たり判定（体が、小物をすり抜けなくなること）
- 平屋の小物の置き方の変更

## 設計方針

- 小物は、見た目だけ。サーバー、契約、勝敗の判定、移動の規則、見通し、狙い、カメラの守りは、変えない。変えないことを、既存のテストで確かめる
- 素材（小物の glb）は、公開リポジトリに入れない（ADR 0040）。平屋の規約（2025-10-11）は、組み込みを許し、素材の二次配布を禁じている。キットも、変換した glb として、リポジトリに入れない（docs/licenses/ の要約に、小物のキットを、平屋の派生として、1 行足す）
- 置き方は、純粋関数にして、テストを先に書く。決定的であること（同じ入力、同じ出力）
- 素材なし、旗が false のときの動きが、基準。make verify は、素材に頼らない
- 受け入れの基準は ADR 0028 に従う

## 受け入れ条件

- 置き方の関数が、すべての骨格（10 種と広い屋敷 30 種）の、すべての和室系のスロットで、部屋の内側に収まり、小物どうしが重ならず、襖から部屋の中央までの通り道を、ふさがない（テストで確認）
- 同じ地図と種で、同じ置き方になる。種が違えば、型が変わりうる（テストで確認）
- キットの検査: 小物の名前、原点が足もとの中心、高さが上限以下、大きさが 2 MB 以下（手元に素材があるときだけ。無ければ飛ばす）
- 旗が false のとき、何も読まれず、何も描かれない（テストで確認）。素材が読めないとき、小物なしで、最後まで遊べる（テストで確認）
- 小物が、移動、見通し、射撃、カメラの守りに、影響しない（既存のテストが、変更なしで通る）
- 描画の重さの測定結果（三角形、描画の呼び出し、実機の滑らかさ）が、報告にある
- 目視: 和室に、座卓などが置かれ、部屋らしく見える。通り道が、ふさがれていない。体が、小物をすり抜けても、不自然に見えすぎない。スマホの縦画面で、重くない
- `make verify` が通る

## 段階

1. 小物の候補、高さ、三角形の数、キットの大きさの見込み、置き方の型の案を、調べて、提案する（読むだけ。止まって、確認を待つ）
2. キットを作る道具（tools/room_props.mjs）と、キットの検査を、テストを先に書いて作る
3. 置き方の純粋関数を、テストを先に書いて実装する
4. 素材の入口、旗、描画（InstancedMesh）を実装する
5. 描画の重さを測り、目視で確かめる項目を、報告にまとめる。ADR（下書き）を書く
