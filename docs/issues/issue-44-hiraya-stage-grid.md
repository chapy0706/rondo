# issue-44: 平屋ステージの表現と、歩ける格子（サーバー）

## 背景

平屋を固定ステージとして足す（ADR 0039）。平屋は、和室A・B・C とダイニングが襖で直接つながる田の字型で、ADR 0032 の骨格（1マス 1 m、廊下に面したスロットごとに襖1つ）では表せない。また、いまのステージの移動範囲は中心から ±5 m の仮の正方形で、壁や閉じた襖で移動が止まる仕組みが無い。

本 issue では、サーバー側に、0.3 m の格子と戸の一覧（3種類）を持つステージの表現と、壁・閉じた襖で止まる移動の規則を作る。ステージのデータは `docs/stage-hiraya-proposal.md` の文字地図と戸の一覧を元にする。

マイルストーン1（10/10〜12）の後に着手する。それまではランダム間取りの10種で通す。

## スコープ

### このissueでやること

- ステージのデータの形を決める
  - 1マスの大きさ、原点、文字地図、領域の記号の意味（スロット・通り道・玄関・庭）、戸の一覧（隣り合う2マスの境と、種類: 襖・いつも開いている・いつも閉じている）、リスポーン位置
  - サーバーとクライアントが同じデータを使えるよう、1つの定義を正とする形式を決める（候補: contracts に置く JSON を正とし、Gleam 側は同じ内容の生成されたモジュール、または同じファイルを読むテストで食い違いを防ぐ。決める前に人間に確認する）
- 平屋の文字地図と戸の一覧を書き起こす（`docs/stage-hiraya-proposal.md` の下書きを元にする）
- 歩ける格子と、辺の通れる・通れない
  - 同じ領域どうしの辺は通れる。異なる領域どうしの辺は通れない。戸の一覧にある辺は、いつも開いている戸と、開いている襖なら通れる
  - 縁側と庭の境は、見えない壁として通れない
- 移動の規則（純粋関数）
  - 位置（点）から次の位置への移動で、通れない辺を越えるなら、越える手前で止める（辺に沿って滑らせる）。マスの角をちょうど通るときは、両脇がどちらも通れる場合だけ通す
  - `game.move` の範囲の丸め（`stage_half` の正方形）を、ステージの歩けるマスとこの規則に置き換える（固定ステージのとき）
- 襖の開閉の状態
  - 襖を開ける報告（どの襖か）を受け、近くにいるか（例: 襖の辺から 1.5 m 以内）を確かめて開ける。開けた襖は開けっぱなし
  - 探索フェーズの開始で全部閉じ、答え合わせタイムの開始で全部開く（ADR 0033）
  - 襖の開閉の状態を全員へ配信する（形を contracts に足す）
- リスポーン: 鬼（探索の開始）と隠れ側（準備移動の開始）を、玄関の (4.7, 11.3) に置く
- ステージの選び方の受け口（ルーム作成時の設定で、ランダム間取りか平屋か。選択肢をロビーに出すのは issue-46）

### このissueでやらないこと

- 見通しと鬼 CPU・隠れ CPU の一般化（issue-45）
- クライアントの表示・移動（issue-46）
- 家具の当たり（ADR 0039 で扱わないと決めた）
- ランダム間取りの10種への当たりの適用（移動の規則は同じ形で使えるようにしておくが、骨格の当たりは別 issue にする）

## 設計方針

- ADR 0039 に従う。ADR 0032 の3つの規則は、固定ステージには当てはめない。ランダム間取りの検算はそのまま残す
- 判定はすべて純粋関数で書き、テストファーストで進める
- 境（外部入力）では、襖を開ける報告の unknown を検証してから扱う
- ステージのデータは素材ではないのでリポジトリに入れる。glb などの素材は入れない
- 性善説（ADR 0035）。移動の報告を確かめるのは、誠実なクライアントとの食い違いを防ぐため
- 受け入れの基準は ADR 0028 に従う

## 受け入れ条件

- 平屋の文字地図と戸の一覧が、決めた形式で定義されている
- 襖を全部開けたとき、玄関から歩けるすべてのマスに着ける。全部閉じたときは、玄関・東の廊下・洗面所・風呂・トイレだけに着ける（テストで確認）
- 襖は10組で、どの戸も2つの異なる領域の境にある。片開き戸・玄関の戸・勝手口は襖でない（テストで確認）
- 各戸の範囲が、`doors-fbx.tsv` の開口（中心と幅）と 0.3 m 以内で合っている（テストの入力として、開口の値をテストの中に書き写す。素材のファイルは読まない）
- 壁と閉じた襖を越える移動は、越える手前で止まる。開いた襖と、いつも開いている戸は通れる。縁側から庭へは出られない（テストで確認）
- 歩けるマスの中心が、床の矩形（建物の床・縁側・掃き出し窓の開口）の内側にある（テストで確認）
- 探索の開始で全部の襖が閉じ、答え合わせの開始で全部開く。襖の開閉の状態が配信される（テストで確認）
- 鬼と隠れ側が、玄関の (4.7, 11.3) に現れる（テストで確認）
- ランダム間取りの既存のテストが、そのまま通る
- `make verify` が通る（TS・Gleam 双方）

## 段階

1. ステージのデータの形と、サーバー・クライアントで同じ定義を使う形式を提案し、人間に確認する
2. 平屋の文字地図と戸の一覧を書き起こし、データの検算（地図の形、戸、到達、開口との一致）のテストを先に書く
3. 歩ける格子と、辺の通れる・通れないを実装する
4. 移動の規則（止める・滑らせる・角の扱い）を、テストを先に書いて実装し、`game.move` につなぐ
5. 襖の開閉の状態（開ける報告、探索の開始で閉じる、答え合わせで開く、配信）を実装する
6. リスポーンと、ステージの選び方の受け口を実装する
