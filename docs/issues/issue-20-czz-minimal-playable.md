# issue-20: czz を最小構成で遊べる状態にする

## 背景

issue-19 で、採点エンジン（grade）とお題20問を apps/web/src/games/czz/ に取り込んだ。本 issue では、これを使ってソロゲームとして最小構成で成立させる。

.reference/czz/ の読み取り調査により、czz にはコマンドを文字で打ち込む入力欄が存在しないことが分かった。プレイヤーは「命令ボタンをタップして並べ、数値だけをフォームで入れる」ことで DslProgram を組み立てる。当初の「コマンド入力欄」という前提は、この実態に合わせて「コマンド選択UI」に改める。

また、既存の CommandBuilder をほぼ全部持ってくると、13〜16 ファイルに加えて zustand の追加と、104 か所のテーマ用クラスの置き換えが必要になる。最小構成なら新規 5〜6 ファイルで済み、追加依存もない。まず最小構成で遊べる状態を作り、既存 UI 資産のうち必要な分は issue-21 に回す。

## スコープ

### このissueでやること

- manifest.ts の作成と registry への登録（registry 配列と gameComponents の2か所）
- ui/catalog.ts: czz の catalog から、初心者向けラベルと数値パラメータ定義だけを抜いた純粋なデータ
- ui/program.ts: 命令列の追加・削除・値の設定・クリア・DslProgram への直列化を、純粋関数として実装する。テストを先に書く
- Czz.tsx: ゲーム本体（出題 → 命令を並べる → 採点 → 次の問題 → 終了時に reportResult）
- パラメータ入力UI（ui/ParamSheet.tsx、またはインライン展開）
- 1セッション3問

### このissueでやらないこと

- 既存の CommandBuilder・zustand・音声・PipelinePanel・GesturePad の移植（必要な分は issue-21）
- UNIX 表記の表示、並べ替え、初心者向け/UNIX 表記の切り替え（issue-21）
- 命令が3段になるお題（T16〜T20）の出題（並べ替えができるようになってから）
- Runner I/O ルール（入力 cat input.csv・出力 >> output.csv の設定を求める学習用の追加ルール）。採点には含めない
- 進捗保存・localStorage・zustand persist（ADR 0019）
- 基盤側（platform/、registry の構造、tailwind 設定、globals.css）の変更

## 設計方針

- SoloGame として実装し、リアルタイム接続を受け取らない（ADR 0004）
- 入力は独自のコマンド選択UIとする。VirtualPad は使わない。ADR 0018 は入力元の抽象化を求めるもので、独自の入力UIを禁じるものではない（Minesweeper と同様の扱い）
- 採点は issue-19 の grade を直接呼ぶ。fetch・API 往復は行わない
- 状態は useReducer と純粋関数で持つ。zustand を追加しない
- スタイルは rondo の Tailwind v4（slate 系）で書く。czz のテーマ用クラス（bg-card など）は持ち込まない。基盤側に定義を足さない
- 表記は初心者向けラベルに固定する（モード切替は保存できないため、ADR 0019）
- 出題対象は、模範解答の命令数が2以下のお題とする。1セッションで3問を選ぶ。選び方は純粋関数にして、乱数は外から渡せるようにする
- 不正解のときは、組み直して再採点できる。「次へ」で先に進むこともできる。スコアは正解した問題数
- 追加直後の命令の値は空文字になる（czz 由来）。全命令のパラメータがカタログのスキーマを満たすまで、「採点」ボタンを無効にする
- カタログの整合をテストで保証する。出題対象のお題すべてについて、模範解答が使う命令がカタログにあることを確認する。czz の catalog には FILTER_NOT_EQUALS が無い（スキーマは13命令、catalog は12命令）。出題対象のお題が使う場合のみカタログに追加し、使わない場合は追加しない
- reportResult の形式はテトリスの呼び出し箇所と同じにする（PlayResult）
- スマホの縦画面・タッチ操作を前提にする（ADR 0012）
  - タップ対象は高さ 44px 以上にする
  - 数値入力は inputMode="numeric" にする
  - ソフトウェアキーボードが出ても、入力欄が隠れないようにする。下から出るシートを使う場合は特に確認する。インライン展開でもよい
  - 命令列は縦の行表示のみとし、横スクロールを作らない

## 受け入れ条件

- ゲーム選択画面から起動して遊べる
- 命令ボタンをタップして命令列を組み立て、数値を入れて採点できる
- 値が空の命令が残っている間は、採点ボタンが押せない
- 採点結果（正解・不正解）が表示され、不正解なら組み直して再採点できる
- 3問で終了し、正解数が reportResult で基盤に返る
- 採点時に外部への通信が発生せず、localStorage も使っていない
- program.ts のテストと、カタログ整合のテストが通る
- 基盤側のコードを変更していない。zustand などの依存を追加していない
- タップ対象が 44px 以上で、数値入力が numeric キーボードになり、キーボード表示中も入力欄が見える
- `make verify` が通る

## 段階

1. manifest.ts と registry 登録（2か所）を行い、中身が空のコンポーネントで、選択画面からの起動を確認する
2. catalog.ts と program.ts を、テストファーストで実装する
3. 出題対象の絞り込みと、カタログ整合のテストを実装する
4. Czz.tsx に、出題・パレット・命令列・パラメータ入力・採点ボタンを実装する
5. 採点結果の表示、3問での終了、reportResult を繋ぐ
6. スマホ縦画面で操作性を確認する（実機、または DevTools）
