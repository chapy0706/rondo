# issue-20: czz を最小構成で遊べる状態にする

## 背景

issue-19 で取り込んだ採点エンジンとお題データを使い、rondo のソロゲームとして最小構成で成立させる。

czz の既存 UI は CommandBuilder を中心に20以上のファイル・zustand・Tailwind・音声資産を伴う。これらを一度に移植すると、途中で止まったときに何も動かない状態が残る。本 issue ではまず簡素な入力 UI で「1問解けて結果が返る」ところまでを通し、既存 UI の移植は後続 issue に分ける。

この順序により、時間切れになっても「動く czz」が手元に残る。

## スコープ

### このissueでやること

- czz をソロゲームとして games 配下に配置する
- manifest.ts の作成と registry への登録（2か所）
- 簡素な入力 UI（コマンド入力欄と結果表示）
- お題の出題と、採点結果の表示
- 結果の基盤への返却（reportResult）

### このissueでやらないこと

- czz の既存 UI 資産（CommandBuilder・zustand・音声）の移植（issue-21）
- 進捗保存・ランキング

## 設計方針

- SoloGame として実装し、リアルタイム接続を受け取らない（ADR 0004）
- 採点は issue-19 で取り込んだ純粋関数をブラウザ内で直接呼ぶ。API 往復を行わない
- 入力はコマンド文字列であり、方向入力（VirtualPad）は用いない。独自の入力 UI を持つ点は Minesweeper と同様の扱いとする（ADR 0018 は入力元の抽象化を求めるものであり、独自 UI を禁じるものではない）
- マニフェストで自己記述し、registry に登録する（ADR 0003）
- 追加にあたり基盤側のコードには手を入れない
- 1セッションの長さは rondo の目安（2〜3分）に収まるよう、出題数を絞る

## 受け入れ条件

- ゲーム選択画面から起動して遊べる
- お題が表示され、コマンドを入力すると採点結果が返る
- セッション終了時に結果が基盤に返る（reportResult）
- 採点時に外部への通信が発生しない
- 追加にあたり基盤側のコードを変更していない
- `make verify` が通る

## 段階

1. manifest.ts を作り、registry の2か所（registry 配列・gameComponents）に登録する
2. 中身が空のコンポーネントで、選択画面からの起動を確認する
3. お題の表示とコマンド入力欄を実装する
4. issue-19 の採点関数を呼び、結果を表示する
5. セッション終了時の reportResult を繋ぐ
