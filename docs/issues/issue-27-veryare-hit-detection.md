# issue-27: veryare 当たり判定（射撃・リロード）

## 背景

鬼が隠れ側を撃って当てたかどうかを判定する。ADR 0022 の方針（クライアント申告＋サーバー簡易検証）を実装する。issue-24（フェーズ管理）を前提とする。

## スコープ

### このissueでやること

- 鬼クライアントの射撃操作と、対象プレイヤーIDを含む射撃申告メッセージ
- サーバーでの簡易検証（申告時点での鬼と対象の距離、直前の射撃からの経過時間）
- リロード時間(3秒)の実装。サーバーが射撃イベントの受信時刻を記録し、3秒未満の再申告を無効とする
- 命中と判定された隠れ側を「見つかった」状態にし、観戦モード（issue-28）へ遷移させる

### このissueでやらないこと

- 3D空間での厳密なレイキャスト・遮蔽判定（壁越しの誤判定は許容する、ADR 0022）
- 観戦モードの実装そのもの（issue-28）

## 設計方針

- 当たり判定は ADR 0022 に従う
- リロードの検証は、サーバー受信順を権威とする既存の考え方（ADR 0014）の延長で行う
- 受け入れの基準は ADR 0028 に従う。特に「隠れ側が鬼に危害を加えること」はここでは扱わない（鬼は探索フェーズで一方的に攻撃する側であり、逆方向の攻撃手段を持たない）

## 受け入れ条件

- 鬼が対象を指定して射撃を申告すると、距離が妥当なら命中として扱われる
- 距離が大きく離れた相手への申告は、命中として扱われない
- 直前の射撃から3秒未満の申告は無効になる
- 命中した隠れ側は「見つかった」状態になる
- `make verify` が通る

## 段階

1. 射撃申告メッセージの型を contracts に定義する
2. 鬼クライアントの射撃操作を実装する
3. サーバーでの距離検証を実装する
4. リロード時間の検証（受信時刻の記録と3秒判定）を実装する
5. 命中時の状態遷移（見つかった状態へ）を実装する
