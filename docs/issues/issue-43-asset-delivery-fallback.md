# issue-43: 素材の配信とフォールバック

## 背景

GitHub のリポジトリは公開である。ステージ（平屋）とキャラクターの素材は、再配布が制限されているため、リポジトリに入れない（元データも、変換後の glb も）。

そのため、本番では素材を別の場所から配信し、アプリが URL で読み込む。素材が読み込めない環境（公開リポジトリを clone した人、素材配信の障害時）でも、仮素材版（箱とカプセル）でゲームが動く形にする。

issue-29（ステージ統合）の本素材版の前提となる。

## スコープ

### このissueでやること

**配信（インフラ）**

- A1 に、素材を配信する小さなコンテナを追加する
  - コンテナ名は rondo-assets に固定する（issue-35 と同じ方式）
  - nginx または Caddy。ホストの素材ディレクトリを読み取り専用でマウントする
  - docker-compose.assets.prod.yml と、Traefik の動的設定の見本（docs/ops/）を作る
  - 配信するドメインは assets-rondo.chapy0706.com とする
- CORS を設定する
  - 素材は別オリジンから読むため、アプリのオリジン（rondo.chapy0706.com）を許可する
  - ローカル開発用のオリジンは、設定で追加できるようにする
- キャッシュを設定する
  - バージョン付きのパス（例: /v1/...）を使い、長期キャッシュ（immutable）にする
  - Cloudflare を経由した場合に glb がキャッシュされるかは、公式ドキュメントで確認し、必要ならルールの手順を書く
- 素材のアップロード手順を docs/assets.md に書く（手元から A1 のディレクトリへ、rsync など）

**クライアント（TypeScript）**

- 素材の基準 URL を、ビルド時の環境変数 NEXT_PUBLIC_ASSET_BASE_URL で受け取る。未設定なら、仮素材のみで動く
- 素材の一覧（manifest.json）を配信側に置き、アプリが最初に取得する
  - 各素材のパス、バージョン、サイズ、品質（512 / 1024）を持つ
  - 取得に失敗したら、仮素材で続ける
- 読み込みは、ゲームの開始を待たせない
  - 仮素材で先に始め、本素材が読み込めたら差し替える
  - 差し替えは、見た目が急に変わらない時点（待機ルームの間など）に限る。間に合わなければ、そのゲームでは仮素材のままにする
- 品質は既定で 512 とする。1024 を選ぶ手段は、必要になった時に別途検討する
- 読み込みの失敗（404、壊れたファイル、タイムアウト）は、利用者に警告を出さず、仮素材へ切り替える。エラーで止めない。原因は console に記録する

### このissueでやらないこと

- ステージの統合、襖の演出、サーバーの移動範囲（issue-29）
- 素材の作成・変換（tools/ で別に行う）
- 認証付きの配信、CDN の契約、素材の暗号化
- 素材の取り出しを完全に防ぐこと（ブラウザに届く以上、できない。ホットリンクの簡易な抑止は任意）

## 設計方針

- 素材の有無で、機能が変わらない。仮素材版が基準で、本素材は上乗せとする
- make verify は素材に依存しない。テストは素材なしで通る
- 読み込みの失敗のテストをテストファーストで書く（404、不正な glb、タイムアウト、manifest の欠落）
- 素材の基準 URL は、WebSocket の URL と同じく、ビルド時の環境変数として扱う。docs/deploy.md の手順と揃える
- 判断は ADR に残す。ADR は書き換えず、最新番号の次を新規に採番する（素材は公開リポジトリに入れない、本素材版は骨格1種に限る、の2点）

## 受け入れ条件

- NEXT_PUBLIC_ASSET_BASE_URL を設定しないとき、仮素材だけでゲームが最後まで動く
- 設定したとき、本素材が読み込まれ、待機ルームの間に差し替わる
- 素材配信を止めても（404、接続不可）、ゲームは止まらず、仮素材で続く
- CORS が効き、アプリのオリジンからだけ読み込める
- 素材のファイルがリポジトリに含まれていない（git ls-files で確認）
- `make verify` が通る（TS・Gleam 双方）
