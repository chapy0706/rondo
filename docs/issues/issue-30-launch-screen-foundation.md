# issue-30: GameManifest の起動画面拡張と基盤共通の起動画面

## 背景

パッケージゲームのように、ゲーム選択画面でアイコンをタップした後、いきなり本編に入るのではなく、起動画面（ロゴ・タイトル・「はじめる」操作）を挟みたい。押しても押さなくても展開は変わらないが、操作した満足感を得られる、という位置づけの画面である（エレベーターの「閉」ボタンと同じ）。

ゲームによって、起動画面の持ち方は2通りに分かれる。

- **共通**: 基盤が用意する、シンプルな「はじめる」ボタンだけの画面。Tilt Maze・テトリスなど、起動前の特別な選択が要らないゲームが使う
- **独自**: ゲーム自身が起動画面を持つ。czz（5ヶ月かけて作り込んだ本家の起動画面。issue-21）、veryare（「サーバーを探す」「サーバーを作る」の2択。issue-29）が該当する

本 issue は、この使い分けを実現するための土台（GameManifest の拡張と、共通起動画面の実装）を作る。issue-21・issue-29 は、ここで定義するフィールドを前提にしている。

## スコープ

### このissueでやること

- `packages/contracts` の `GameManifest` に、次のフィールドを追加する
  - `launchScreen: "shared" | "custom"` — 起動画面を基盤共通のものにするか、ゲーム自身が持つかを宣言する
  - `tagline?: string` — キャッチコピー的な一文
  - `howToPlay?: string[]` — 遊び方の要点（箇条書き）
  - `titleScreenImage?: string` — 起動画面用のビジュアル（thumbnail より高解像度な想定。画像の実体が無い場合のフォールバックも用意する）
- 基盤共通の起動画面コンポーネントを実装する。`launchScreen: "shared"` のゲームは、選択画面からの遷移時にこの画面を経由する。ロゴ・タイトル・タグライン・遊び方・「はじめる」ボタンを表示し、操作を待ってから本編（ゲームホスト）へ進む
- ゲームホスト（play ルート）で、マニフェストの `launchScreen` を見て、`"shared"` なら共通起動画面を、`"custom"` ならそのままゲーム自身のコンポーネント（内部で自前の起動画面を持つ）に委ねる分岐を実装する
- テトリス・Tilt Maze のマニフェストに `launchScreen: "shared"` を設定し、タグライン・遊び方を記入する

### このissueでやらないこと

- czz の独自起動画面の中身（issue-21）
- veryare の独自起動画面の中身（issue-29）
- タイトル画面用の画像そのものの用意（フォールバック表示で足りる形にする）

## 設計方針

- ゲームはプラグインとして扱い、基盤は `launchScreen` を見て振り分けるだけで、個々のゲームの起動画面の中身を知らない（ADR 0003 の考え方の延長）
- 「はじめる」操作は、結果を変えない演出であることを踏まえ、実装は単純にする（ボタン押下でゲームホストへ遷移するだけ）
- コンソール風の視覚方向性（ADR 0029）を踏襲する

## 受け入れ条件

- `GameManifest` に `launchScreen` ほか新フィールドが追加され、型チェックが通る
- `launchScreen: "shared"` のゲーム（テトリス・Tilt Maze）は、選択画面から選ぶと共通起動画面が表示され、「はじめる」を押すまで本編に進まない
- `launchScreen: "custom"` を持つゲームは、共通起動画面を経由せず、直接そのゲーム自身のコンポーネントに遷移する（この時点では custom なゲームは無いため、分岐が機能することだけをテストで確認する）
- タイトル画面用の画像が無い場合、フォールバック表示で違和感なく見える
- `make verify` が通る

## 段階

1. `packages/contracts` に `GameManifest` の新フィールドを追加する
2. 基盤共通の起動画面コンポーネントを実装する
3. ゲームホストで `launchScreen` による分岐を実装する
4. テトリス・Tilt Maze のマニフェストに新フィールドを設定する
5. フォールバック表示を実装する
