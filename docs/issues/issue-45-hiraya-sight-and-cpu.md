# issue-45: 見通しと CPU の、戸の一覧への一般化

## 背景

見通し（`sight.gleam`）と鬼 CPU（`oni_cpu.gleam`）、隠れ CPU（`hider_cpu.gleam`）は、ランダム間取りの骨格（ADR 0032）を前提にしている。

- 見通しは、廊下などの開けた場所（Open）と部屋（Room）の境にある、スロットの襖だけを見る。部屋どうしの襖や、いつも開いている戸を知らない。1マスは 1 m
- 鬼 CPU は、各部屋の最初の襖の内側を目的地にし、廊下側から襖を開ける
- 隠れ CPU は、部屋タイプ（和室・押し入れ）が割り当てられたスロットのマスに置き、その部屋タイプの代表色で塗る

平屋（ADR 0039）は、部屋どうしの襖があり、1つの部屋に入口が複数あり、いつも開いている戸があり、1マスは 0.3 m で、部屋はダイニング・キッチン・水回りを含む。本 issue では、これらを issue-44 の戸の一覧に一般化する。

## スコープ

### このissueでやること

- 見通しの一般化
  - 辺の通れる・通れない（issue-44）から、見通しを判定する。閉じた襖・壁は遮り、開いた襖・いつも開いている戸は通す
  - 1マスの大きさと原点を、ステージから受け取る
- 鬼 CPU の一般化
  - 経路は、issue-44 の歩ける格子と辺でたどる（閉じた襖は、開ければ通れるものとして経路に含め、手前で開けてから通る）
  - 部屋の入口が複数あるとき、いまいる場所から着ける入口のうち近いものを目的地にする
  - 歩く速さ（m/秒）は変えず、0.3 m のマスで進む数に換算する
- 隠れ CPU の一般化
  - 置くマスは、スロットのマスから選ぶ。玄関と床の間は選ばない（ADR 0039）
  - 部屋の代表色（`palette.gleam`）に、ダイニング・キッチン・水回り・板の間（廊下・広縁・縁側）の色を足す（仮の値）
- シミュレーション（`make simulate`）で、平屋をステージの1つとして回し、異常が0件であることを確かめる。平屋での隠れ側の勝率を、骨格10種と並べて報告する

### このissueでやらないこと

- ステージのデータと移動の規則（issue-44）
- クライアントの表示（issue-46）
- 強さのプリセットの値の見直し（平屋の集計を見て、必要なら別 issue にする）

## 設計方針

- ADR 0038・0039 に従う
- ランダム間取りの骨格も、同じ一般化した形（戸の一覧）に直して使えるようにし、骨格での既存のテストとシミュレーションの結果が変わらないことを確かめる
- 判定は純粋関数で、乱数は種を引数に取る。テストファーストで進める
- 受け入れの基準は ADR 0028 に従う。閉じた襖・壁の向こうの隠れ側を見つけないことを守る

## 受け入れ条件

- 平屋で、閉じた襖・壁の向こうは見えず、開いた襖・いつも開いている戸の向こう（例: キッチンからダイニング）は見える（テストで確認）
- 鬼 CPU が、平屋で玄関から出て、襖を開けながら全スロットを巡れる。入口が複数の部屋では、近い入口から入る（テストで確認）
- 隠れ CPU が、平屋のスロットのマスに、ほかの隠れ側と被らずに置かれる。玄関と床の間には置かれない（テストで確認）
- シミュレーションで、平屋を含めて異常が0件。平屋の集計が表に出る
- 骨格10種での既存のテストが通り、シミュレーションの集計が一般化の前と同じ（種を固定して比べる）
- `make verify` が通る（TS・Gleam 双方）

## 段階

1. 見通しを、辺の通れる・通れないで判定する形に直す（テストを先に書く。骨格での既存のテストを通したまま）
2. 平屋での見通しのテストを足す
3. 鬼 CPU の経路と目的地を、歩ける格子と入口の一覧に直す
4. 隠れ CPU の置き場所と、代表色を足す
5. シミュレーションに平屋を足し、異常0件と集計を確かめる
