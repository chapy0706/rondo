# issue-42: veryare の game-ended の送出と結果画面への接続

## 背景

veryare は、答え合わせタイムの後に終了する。しかし、サーバーはゲーム終了の通知（game-ended）を送っておらず、基盤の結果画面にも繋がっていない。現在は、画面の中に勝敗を重ねて表示している。

本 issue で、終了を基盤の仕組みに乗せる。マイルストーン1（鬼選出から結果まで通る）の「結果」を、完成させる。

## スコープ

### このissueでやること

- 答え合わせタイムの終了時に、サーバーが game-ended を全員に送る
  - RealtimeResult（order、rankings）の中身は、実装前に提示して確認を取る
  - 勝敗を、基盤の順位の形にどう写すか、既存の ADR（0033、0036）と veryare の概要資料を読んで案を出す
- クライアントが game-ended を受け取って、基盤の結果画面へ遷移する
- 終了後のルームの扱い
  - 終わったルームを、ルーム一覧に出さない（issue-31 の判断に従う）
  - 終了後、退出または結果画面からの戻りで、ロビーやゲーム選択に戻れる
- 画面内の勝敗の重ね表示は、残すか基盤の結果画面に任せるか、案を出して確認を取る
- モックでも、終了から結果画面までが動く

### このissueでやらないこと

- ポイント・いいねの計算（issue-32）
- 勝敗の判定ロジックの変更
- Tilt Maze（rolling）の game-ended
- 再戦機能

## 設計方針

- 判定は既存のゲーム状態機械の終了遷移に乗せ、新しい判定は作らない
- 契約の game-ended の形（ADR 0009）は変えない。TS の契約と Gleam の対応テストで守る
- 隠すべき情報を、結果の通知に含めない（ADR 0021）。全員に送ってよい情報だけにする
- 判定ロジックはテストファーストで書く

## 受け入れ条件

- 答え合わせタイムの終了後に、全員のソケットに game-ended が届く（結合テストで確認）
- 鬼の離脱・全員失格・時間切れなど、各種の終了経路でも game-ended が送られる（テストで確認）
- クライアントが基盤の結果画面に遷移し、そこからゲーム選択に戻れる
- 終わったルームがルーム一覧に出ない
- 契約の対応テストが通る
- `make verify` が通る

## 段階

1. 既存の終了遷移と、結果に使えるデータを読み、RealtimeResult の案を提示する
2. サーバーの送出を、テストを先に書いて実装する
3. 契約の対応と、クライアントの受信を確認する
4. 基盤の結果画面への遷移を実装する
5. モックの台本を更新する
6. 2〜3タブでの確認手順を報告にまとめる
