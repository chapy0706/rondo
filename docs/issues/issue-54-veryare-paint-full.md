# issue-54: veryare ペイントの本格版（5本円柱・X Bot・ポーズ）

## 背景

issue-25 で、ペイントの簡略版（胴1本の円柱に描き、体全体へ映す）を実装した。描き込み面の座標、ストロークの契約（部位 `part` を含む）、フェーズ終了時の一度だけの送信、探索開始時の一括配信、体のシェーダー、体を作る口（差し替えの仕組み）は揃っている。

本 issue では、ADR 0037 の本来の形（5本の円柱、スキンの重みによる部位の割り当て、本素材のキャラクター）と、ポーズの選択、鬼 CPU の溶け込み度への反映を足す。

優先度は低い。遅れたら切る（切った場合は、issue-25 の簡略版のまま発表する）。

## スコープ

### このissueでやること

- 5本の円柱（胴・左腕・右腕・左脚・右脚）を、描き込み面の部位として分ける
  - 描き込み面は、5部位を領域として並べた1枚のキャンバスにする（ADR 0037）
  - 契約のストロークの部位（`part`）に、腕・脚を足す。共有の見本と、上限（本数・点の数）を見直す
- スキンの重みによる頂点の部位の割り当て
  - 頂点ごとに、スキンの重みが最も大きい部位に割り当てる。モデルの読み込み時に計算する（純粋関数でテストを先に書く）
- X Bot の本素材での表示
  - 体を作る口（issue-25 の `BodyKit` と差し替えの仕組み）に、X Bot を読み込む実装をつなぐ
  - issue-43 の素材配信（A1 への手作業）の後に行う。素材が無いときは、仮のカプセルのまま動く
- ポーズを選ぶ画面（立つ・しゃがむ・寝る）
  - ペイントは基準姿勢で描き、描き終えたら選んだポーズで表示する。ポーズを変えても、塗りが体の同じ部位に付いてくる
  - 選んだポーズを、ペイントと一緒に送り、探索開始時の一括配信に載せる（いまは人間の隠れ側のポーズは null）
- 鬼 CPU の溶け込み度に、人間のペイントを使う
  - ストロークの面積で重みを付けた平均色に、塗っていない部分を混ぜて求める（サーバーの純粋関数でテストを先に書く）
  - いまは人間の隠れ側を未塗装として扱っている（`docs/schedule.md` の既知の抜け）

### このissueでやらないこと

- ペイントの逐次同期（ADR 0025）
- 頭の専用円柱、手や足先の細かい塗り分け
- ポーズのアニメーション（issue-53）

## 設計方針

- ADR 0025・0035・0037・0038 に従う
- issue-25 の契約と描き込み面の座標を、壊さずに広げる（胴だけのペイントは、そのまま読めること）
- ペイントフェーズ中は他プレイヤーに自分のペイントを見せない（ADR 0035 で維持するもの）
- 判断のロジック（部位の割り当て、円柱座標、平均色）は純粋関数にし、テストを先に書く
- 受け入れの基準は ADR 0028 に従う

## 受け入れ条件

- 胴・腕・脚を塗り分けられ、塗った内容がリアルタイムに体へ映る
- ポーズを変えても、塗りが体の同じ部位に付いてくる
- 素材が無いときは、仮のカプセルで動く（簡略版と同じ）
- 胴だけのペイント（issue-25 の形）も、そのまま読めて描ける
- 鬼 CPU の溶け込み度が、人間のペイントの平均色で変わる（純粋関数のテスト）
- `make verify` が通る

## 段階

1. contracts のストロークの部位を広げ、共有の見本と上限を見直す
2. 頂点の部位の割り当てと、5本の円柱の座標の計算を、純粋関数としてテストファーストで実装する
3. 体のシェーダーを5部位に広げる（まず仮のカプセルで）
4. X Bot を読み込む体を作る口を実装する（素材配信の後）
5. ポーズを選ぶ画面と、ポーズの送信・一括配信を実装する
6. 鬼 CPU の溶け込み度に、人間のペイントの平均色を使う
