# issue-58: ルーム名を、作るときに自分で決められるようにする

## 背景

ロビーのルーム一覧と、ゲーム画面には、ルームの識別子（room- と 16 桁の英数字）が、そのまま出ている。来場者が、どのルームに入るかを選ぶとき、読めない文字列では分からない。

本 issue では、ルームを作るときに、名前を決められるようにし、一覧と画面に出す。名前を決めなかったときは、作った人の表示名から、既定の名前を付ける。

## スコープ

### このissueでやること

- 契約（packages/contracts）を、省略できる項目の追加で変える（ADR 0009 に従い、TS の型、見本、共有の見本、Gleam の型と変換、対応テストをそろえる）
  - create-room に、省略できる roomName を足す
  - ルーム一覧の 1 件（RoomSummary）に、省略できる name を足す
  - room-joined に、省略できる roomName を足す
  - 省略したときの動きは、これまでと同じ（古い画面や古いボットが、壊れない）
- サーバーで、名前を整える
  - 前後の空白を落とす。制御文字は取り除く。長さは 1〜20 文字（コードポイントで数える）。超えた分は切り捨てる
  - 空、または空白だけのときは、既定の名前（作った人の表示名 + 「のルーム」）にする
  - 名前は、ルームが持つ。ルームの一覧と、参加したときの返事に載せる
  - 名前の重複は、許す（識別子が別なので、区別できる）
- クライアント
  - ロビーの「作る」に、ルーム名の入力欄を足す。入力欄の既定値は空で、案内の文言に既定の名前の例を出す
  - ルーム一覧に、名前、人数、状態を出す。識別子は出さない
  - ゲーム画面の見えるところ（退出ボタンの近く）に、ルーム名を出す
  - 選択画面の「新しく遊ぶ」から作るときは、既定の名前になる。名前を決めたい人は、ロビーの「作る」から作る
  - 名前は、文字として表示する（HTML として解釈しない。React の標準の表示のままにする）
- モックでも、同じ形で動く（モックのルームにも名前を付ける）

### このissueでやらないこと

- ルーム名の変更（作ったあとの変更）、パスワード、検索
- 不適切な言葉の検査（来場者の自由な入力だが、10/26 の発表会では、長さの上限だけで足りる。必要なら別 issue）
- ゲーム固有のロジックの変更

## 設計方針

- 名前を整える処理は、純粋関数にして、テストを先に書く（TS 側にも、入力欄の検査として同じ規則を置き、サーバーと食い違わないよう、共有の見本で確かめる）
- サーバーが正。クライアントの検査は、入力のしやすさのため
- 受け入れの基準は ADR 0028 に従う。名前の長さの上限と、制御文字の除去で、画面を壊す入力を防ぐ

## 受け入れ条件

- ルーム名を決めて作ると、一覧とゲーム画面に、その名前が出る
- 決めずに作ると、既定の名前（「◯◯のルーム」）が出る
- 21 文字以上は、20 文字に切られる。空白だけは、既定の名前になる。制御文字は、取り除かれる（テストで確認）
- 名前に、HTML の記号（<、>、&）を入れても、そのまま文字として表示される（テストで確認）
- 契約の対応テスト（TS と Gleam が、同じ見本を読む）が通る。名前なしの古い形の電文も、読める
- ボット（bots/）が、名前なしで作成・参加しても、変わらず動く（make bots が通る）
- ルーム識別子は、利用者に見えない（表示には出ない）
- `make verify` が通る

## 段階

1. 契約の変更の形を提案する（optional の追加で足りること、既存の見本とボットへの影響）
2. 名前を整える純粋関数と、共有の見本を、テストを先に書いて実装する（TS・Gleam）
3. サーバーで、ルームに名前を持たせ、一覧と room-joined に載せる
4. クライアント（ロビーの入力欄、一覧、ゲーム画面、モック）を実装する
5. ボットのシナリオに、名前つきの作成と、一覧での確認を足す
6. 目視で確かめる項目を、報告にまとめる
