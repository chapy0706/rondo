# issue-36: Tilt Maze の作り直し（3ステージ・モード選択・名称変更）

## 背景

Tilt Maze は現在10ステージで構成されているが、発表会で遊ぶ時間を考えると多すぎる。また、名前が覚えにくい。

issue-31 では、Tilt Maze の実接続（サーバー権威での game-ended 送出）を対象外とした。そのため、実接続を前提とした対戦は今回も作らず、見せ方だけを整える。

優先度は低い。10/10〜12 のマイルストーン1の後に、窓の余力で行う。遅れた場合は、切る順の早い段階で切ってよい。

## スコープ

### このissueでやること

- ステージを10から3つに減らす
  - 既存10ステージから、難易度が易・中・難の順になる3つを選ぶ
  - 選定案は実装前に提示し、確認を取る
  - 残りの7ステージのデータは、削除せず別の場所（または未使用の定義）として残すか、削除するかを提案する
- ゲーム開始前に、モード選択画面を追加する
  - 「1人モード」: 従来どおり遊べる
  - 「対戦モード」: 選ぶと「準備中です」という旨のポップアップを出す。サーバー接続、ルーム作成、画面遷移は行わない
- 表示名を変更する
  - 名前は「rolling」に決定済み。画面上の表記は英小文字の rolling とする
  - 変更するのは表示名のみ。内部の gameType（tilt-maze）は変えない

### このissueでやらないこと

- 対戦モードの実装、サーバー側 Tilt Maze の変更、game-ended の送出
- 契約（packages/contracts）と Gleam 側の型・JSON の変更
- 新しいステージの作成、迷路の自動生成、お助け機能（issue-39 で扱う）

## 設計方針

- 内部識別子を変えないことで、契約と Gleam の対応テスト（ADR 0009）に触れずに済ませる
- モード選択は、Tilt Maze の中に閉じた画面とする。基盤（ロビー、ゲーム選択）の構造は変えない
- 準備中ポップアップは、将来の対戦モード実装時に差し替えやすいよう、モード定義の側に「利用可能か」を持たせる
- 表示文字列は一か所にまとめ、名称変更の影響範囲を小さくする
- 名称変更の判断を ADR に残す場合は、ADR は書き換えず、最新番号の次を新規に採番する

## 受け入れ条件

- ステージが3つになり、1人モードで最初から最後まで遊べる
- 対戦モードを選ぶと準備中のポップアップが出て、閉じるとモード選択に戻る
- 画面上の名称が新しい名前になり、旧名称が残っていない
- 内部の gameType は変わっていない
- `make verify` が通る（TS・Gleam 双方）

## 段階

1. 既存ステージの一覧を確認し、3つの選定案を提示する
2. ステージを3つに絞る
3. モード定義とモード選択画面を追加する
4. 準備中ポップアップを実装する
5. 表示名を差し替え、旧名称の残りを検索して確認する
6. 画面での確認手順を報告にまとめる
