# ADR 0021: サーバーがプレイヤーを限定してメッセージを配信できるようにする

- ステータス: 受理
- 日付: 2026-09-26

## 文脈

既存のリアルタイム同期（`readGameState` / `game-state` メッセージ）は `gameType` と `roomId` で宛先を絞るだけで、ルーム内の全員に同じ内容を配信する前提になっている（ADR 0007）。

めっちゃカメレオン風ゲームでは、鬼に隠れ側の位置を送らない、見つかった後の観戦者にまだ隠れている全員の位置を送らないなど、**プレイヤーごとに異なる内容を配る**必要がある。

## 決定

既存のブロードキャスト型メッセージ（全員に同じ内容）は変更しない。これに加えて、特定のプレイヤーだけに宛てたメッセージ（targeted message）を1種類追加する。サーバー（room_actor）が送信先プレイヤーを選んで配信する。

## 理由

- 既存ゲーム（Tilt Maze 等）は全員ブロードキャストで成立しており、これを変更する理由がない。追加のみで対応し、影響範囲を局所化する
- 「誰に何を隠すか」の判断はサーバー権威の一部であり、ゲームごとに決める方針（ADR 0008）と整合する
- クライアント側は `readGameState` と同様の型で受け取れるようにし、ブロードキャストか限定配信かの違いをゲームコードから意識させない

## 検討した代替案

- 全メッセージを個別配信に統一する案。既存ゲームの単純さを壊し、不要な変更が広がるため却下した
- クライアント側でフィルタする（サーバーは全員に送るがクライアントが無視する）案。隠すべき情報がネットワーク上に流れてしまい、ブラウザの開発者ツールで見えてしまうため、権威の観点から却下した

## 結果

- `protocol/message.gleam` に、宛先プレイヤーIDを持つメッセージ種別を追加する
- `packages/contracts` の `ServerMessage` に対応する型を追加する
- room_actor は「誰に送るか」を判断してから配信する。送るべきでない情報は、そもそも該当プレイヤーの接続に送信しない
