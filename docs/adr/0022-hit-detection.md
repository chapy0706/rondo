# ADR 0022: 当たり判定はクライアント申告とサーバーの簡易検証で行う

- ステータス: 受理
- 日付: 2026-09-26

## 文脈

めっちゃカメレオン風ゲームでは、鬼が隠れ側を撃って当てたかどうかを判定する必要がある。正確な当たり判定には3D空間でのレイキャストが要るが、Gleamサーバーは3Dシーンの形状を持たず、これを実装するのは大きな追加作業になる。

## 決定

当たったかどうかの一次判断はクライアント（鬼側）が行い、「誰に当たったか」をサーバーに申告する。サーバーは申告の妥当性を、保有している情報（各プレイヤーの座標、直前の射撃時刻）だけで簡易に検証する。3D空間の厳密な遮蔽判定（壁越しに当たらないか等）は行わない。

## 理由

- サーバーに3D幾何演算を持たせる実装コストを避けられる。発表会規模の身内利用では、この検証範囲で実害は小さいと判断する
- リロード時間（3秒）の検証は、サーバーが射撃イベントの受信時刻を記録するだけで実現でき、ADR 0014（サーバー受信順を権威とする）の延長で自然に扱える
- 申告された相手がその時点で鬼から一定距離内にいたかどうかは、サーバーが持つ座標だけで検証でき、明らかに不正な申告（大きく離れた相手を当てたことにする等）は防げる

## 検討した代替案

- サーバー側で完全なレイキャスト判定を行う案。実装コストが大きく、2週間のスコープに対して過大なため却下した
- クライアントの申告をそのまま信頼する案。距離とリロードの検証すら行わないと、明白な不正が素通りしてしまうため、最低限の検証は残すこととした

## 結果

- 鬼クライアントは「対象プレイヤーID」を含む射撃申告メッセージを送る
- サーバーは距離としきい値、直前射撃からの経過時間を検証し、妥当なら命中として扱う
- 壁を挟んだ誤判定などの精度限界は許容する
