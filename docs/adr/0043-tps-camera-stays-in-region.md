# ADR 0043: TPS カメラは、体のいる領域の外に出さない

- ステータス: 提案（下書き）
- 日付: 2026-10-11
- 関連: ADR 0034（TPS 視点）の「カメラの制約」のうち、「壁や襖へのカメラのめり込みは許容し、衝突による補正は行わない」を、ステージに限って置き換える。ADR 0028（許容基準）、ADR 0035（性善説）、ADR 0042（地図の通知と移動の規則）。本 ADR は ADR 0034 を書き換えない

## 文脈

ADR 0034 は、全プレイヤーを TPS 視点とし、カメラの壁へのめり込みを許して、衝突による補正をしないと決めた。理由は「壁越しに見えても、隠れ側は移動できず、誰にも隠すべき秘密は生じない」ことだった。

平屋（ADR 0039）では、部屋の幅が 3.7 m ほどで、カメラは体から水平に約 2.4 m 後ろにある。壁際に立つと、カメラは壁の向こう（隣の部屋）に出る。隠れ側の状態は、探索の開始に全員へ届いている（ADR 0025・0035）。そのため、カメラが隣の部屋に出ると、鬼の画面に、その部屋の隠れ側が遮るもの無しに描かれる。ADR 0034 の理由は観戦者だけを考えていて、鬼の画面では、隠れ場所が分かってしまう。これは ADR 0028 が避けたい、鬼が意図せず隠れ側の位置を知る状況にあたる。

壁を消す（半透明にする）方法は、向こうの部屋が見えるので、同じ問題を残す。

## 決定

**ステージのカメラは、体のいる領域の外に出さない**: 体からカメラへの線を、地図の格子（ADR 0042 の通知の地図）でたどり、体のマスの領域が変わる境（壁、すべての戸。開いた襖と、いつも開いている戸を含む）の手前で止める。開いた戸も遮るのは、開口から隣の部屋へカメラが出るのを防ぐため。角をちょうど通るときは、両脇の一方でも領域が変われば止める（安全側）。

**近づいたぶん、見下ろす角度を上げる**: カメラの水平の距離が短いほど、見下ろす角度を、ADR 0034 の既定の角度から上限まで上げる。水平の距離が 0 でも、カメラは見る点より一定の高さ以上の上に置く。

**縮むときは即座、伸びるときはなめらかに**: カメラが近づく（縮む）ときは、その場で合わせ、1 フレームでも領域の外に出さない。離れていく（伸びる）ときは、短い時間でなめらかに戻す。

**当てる範囲**: ステージの準備移動・探索・答え合わせ・観戦（鬼視点）で、すべての役割（鬼、隠れ側、観戦者）。箱の表示でも平屋でも同じ。ペイント画面と待機ルームは、ADR 0034 のまま。

カメラの距離の上限・既定の角度・目線の高さは、ADR 0034 のまま変えない。戸口を通るときの見え方は、定数（境から離す距離、角度の上限、伸びるときの時間、高さの下限）だけで調整する。

## 理由

- 情報の漏れ（ADR 0028）を防ぐことを、ADR 0034 の酔いへの配慮より優先する。漏れは勝敗に直結するが、カメラの寄せは見え方の問題にとどまる
- 縮みを即座にしても、壁に近づく操作は本人が行うので、意図しない画面の回転にはならない。伸びをなめらかにして、跳ねを避ける（ADR 0034 の、急な寄せや跳ねを避ける考え方を、伸びる側で守る）
- 判定と同じ地図（ADR 0042）を使うので、見た目の壁と、カメラを止める境が、移動の規則と同じ精度でそろう
- 角度を上げると、近づいても体の周りの床が見え、狭い部屋でも自分の位置が分かる

## 検討した代替案

- 壁を消す・半透明にする。向こうの部屋の隠れ側が見えるため採用しない
- 通れる辺（開いた襖は通す）の手前で止める。開いた襖の向こうの部屋にカメラが出るため採用しない
- カメラを体の真上に固定する（見下ろし視点）。TPS の操作感（ADR 0034）が大きく変わるため採用しない

## 結果

- issue-46 の続きで、`apps/web/src/games/veryare/cameraRig.ts`（地図をたどる計算・距離と角度・なめらかさ）と `camera.ts`（定数）に実装する
- ADR 0034 の「壁や襖へのカメラのめり込みは許容し、衝突による補正は行わない」は、ステージでは本 ADR で置き換える。ペイント画面と待機ルームでは、ADR 0034 のまま
