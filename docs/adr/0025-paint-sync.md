# ADR 0025: ペイントはフェーズ終了時に一括同期する

- ステータス: 受理
- 日付: 2026-09-29

## 文脈

隠れ側がキャラクターに描いた擬態ペイントを、鬼にも見える形にする必要がある。3Dモデルへの逐次描画をリアルタイムに同期すると、通信量・実装コストが大きい。

## 決定

ペイントはストローク（座標と色の配列）としてクライアント内に保持する。ペイントフェーズの間は各クライアントのローカル状態のみで完結させ、フェーズ終了時に一度だけサーバーへ送信する。サーバーは探索フェーズ開始時に、まだ隠れている隠れ側全員の状態（位置・向き・ポーズ・確定したペイントのデータ）を、全員へ同じ内容で一括配信する（ADR 0035。観戦者や鬼 TPS 視点を選んだ隠れ側にも、鬼の周囲の世界を見せるため）。

## 理由

- ペイント中の逐次同期が不要になり、通信量を大きく抑えられる
- 「フェーズが終わるまで自分にしか見えない」という前提（被り判定の心理戦、ADR 0026 参照）と自然に合う
- ストロークデータという軽量な形式のため、サーバーが一度中継するだけで済む

## 検討した代替案

- 描画を逐次同期する案。通信量・実装コストが大きく、ペイントフェーズ中は他人に見えないという体験（心理戦の要）とも矛盾するため却下した

## 結果

- contracts にストローク配列の型を定義する
- クライアントはペイントフェーズ終了時に一度だけ送信し、サーバーは探索フェーズ開始時に鬼へ配信する
