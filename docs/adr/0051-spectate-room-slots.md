# ADR 0051: 観戦ルームを、人間用の枠とは別の枠で数える（同時ルーム数 4 = 人間 3 + 観戦 1）

- ステータス: 提案（下書き）
- 日付: 2026-10-20
- 関連: ADR 0030（定員・同時ルーム数・ルームの寿命）、ADR 0045（終わったルームは数えない）、ADR 0050（結果のあとに閉じる）、ADR 0013（再接続猶予）。issue-67。本 ADR は、ADR 0030 の同時ルーム数（3）と、ADR 0045 の数え方を、観戦ルームについて置き換える。人間が参加する対戦のルームの数え方は変えない

## 文脈

issue-67 で、CPU だけの試合を見るための観戦ルームを足す。観戦ルームは、人間の参加者を持たず、試合が終わると、結果を見せたあと、同じルームの中で次の試合を始める。ADR 0030 の同時ルーム数（veryare は 3）にそのまま数えると、観戦ルームが人間の対戦の枠を 1 つ占める。ADR 0045 の数え方（終わったルームは数えない）をそのまま当てると、試合の合間（結果を見せている間）に枠が空き、観戦ルームが 2 つ目、3 つ目と作れてしまう。

## 決定

- veryare の同時ルーム数を 4 にする。人間が参加する対戦のルームの枠は、これまでどおり 3（`veryare.max_active_rooms`）。観戦ルームは、別の枠で数え、種別ごとに同時に 1 つまで（`room_directory.max_spectate_rooms`）
- 台帳（`room_directory`）は、ルームの種類（対戦・観戦）を、作るとき（`open_with`）に受け取って覚える。対戦のルームは人間用の枠で、観戦ルームは観戦の枠で、上限に達していれば `room-limit` で断る。片方の枠が埋まっていても、もう片方は作れる
- 観戦ルームは、試合が終わっても、閉じるまで数えたまま（ADR 0045 の「終わったルームは数えない」を当てない）。閉じるのは、観戦者が 0 人のまま 60 秒たったとき。切断の猶予（10 秒 / ADR 0013）の間は、接続が離脱を伝えていないので、観戦者に数えたまま（猶予を過ぎてから 60 秒を数える）。作った時点で誰も入らなかったときも、同じく 60 秒で閉じる
- 観戦ルームには、ADR 0050 の「結果のあと 3 分で閉じる」を当てない（次の試合を始めるため）。結果を見せる時間は 10 秒
- 観戦ルームの観戦者は、参加者ではなく、定員に数えない。上限は 20 人
- ルーム一覧（`RoomSummary`）には、観戦ルームのとき、省略できる項目 `spectate: true` を載せる。観戦ルームの `playerCount` と `capacity` は、観戦者の数と、その上限。試合の合間も、一覧に出す
- 観戦ルームは、旗（`veryare.spectate_ready`。既定 false）の裏に置く。旗が false の間は、作成の設定の `spectate: 1` を `invalid-settings` で断る。開発用の環境変数 `RONDO_SPECTATE_DEV=1` のときだけ、テストのために受け付ける

## 理由

- 観戦ルームは、人間の対戦を妨げないことが前提。枠を分ければ、観戦ルームがあっても、人間用の 3 つは、これまでどおり使える
- 観戦ルームは、試合を回し続けて A1 の資源を使い続けるので、1 つまでに抑え、終わった・合間であっても数える
- 閉じる判断を「観戦者 0 人のまま一定時間」にすれば、見る人がいない観戦ルームが、資源を使い続けない

## 影響

- 安全性: 人間の対戦のルームの数え方と、勝敗の判定は変わらない
- 性能: 同時に動くルームは、最大 4（人間 3 + 観戦 1）。観戦ルームの試合は、観戦者がいる間、続く
- 確かめ: `server/test/rondo_server/room/spectate_directory_test.gleam`（人間 3 + 観戦 1 で 5 つ目が断られる、人間 3 で 4 つ目の人間が断られる、2 つ目の観戦が断られる、観戦ルームが閉じると枠が戻る）、`server/test/rondo_server/connection/spectate_test.gleam`（試合の合間も数えたまま、0 人で閉じる、切断の猶予）

## 検討した代替案

- 同時ルーム数 3 のまま、観戦ルームも同じ枠で数える案。観戦ルームが人間の枠を占めるので採らない
- 観戦ルームにも ADR 0045 の数え方を当てる案。試合の合間に枠が空き、観戦ルームが増えるので採らない
