# ADR 0053: 動ける隠れ側・襖の自動開閉・増え鬼を、ルームの設定で選べる規則として足す

- ステータス: 提案（下書き）
- 日付: 2026-10-23
- 関連: ADR 0024（フェーズ制進行。探索中の隠れ側は動けない）、ADR 0025・0026（ペイントの間は互いを見せない）、ADR 0033（終了の条件と襖の開閉）、ADR 0035（探索の開始の一括配信を全員へ）、ADR 0042（移動の規則と襖）、ADR 0044（待機ルームのメンバーの同期）、ADR 0009（契約）、ADR 0014（受信順）。issue-68（増え鬼）。本 ADR は、どれも書き換えない。従来の規則のルームでは、これらがそのまま効く。新しい規則のルームについてだけ、次のように置き換える

## 文脈

実際に遊んでみて、隠れ側が、探索の間に動けず、塗れないのはつまらないと分かった。見つかるまで、画面を見ているだけになる。本家のゲームの人気の遊び方である増え鬼（issue-68）も、まだ無い。

ただし、従来の動き（隠れたら動けない、鬼が襖を開ける、鬼は 1 人）は、それ自体で遊べる形になっていて、テストと運用の実績もある。いきなり置き換えず、選べるようにして、遊び比べてから既定を決めたい。

## 決定

### 規則は 2 つの設定で選ぶ（既定は従来）

- ルーム作成の設定 roaming（0 = 従来、1 = 動ける）。規則 1（動ける隠れ側）と規則 3（襖の自動開閉）は、ひとまとまりで切り替える。動けるのに、鬼だけがボタンで襖を開ける形は、隠れ側が襖の前で詰まるので、分けない
- 増え鬼（規則 2）は、別の設定 spreading（0 = 従来、1 = 増え鬼。既定は従来）
- 既定は、定数で変える（サーバーの room.gleam の default_roaming・default_spreading。契約の VERYARE_ROAMING.defaultRoaming・VERYARE_SPREADING.defaultSpreading は、同じ値の写しで、共有の見本 fixtures/veryare-roaming.json で一致を両方のテストで確かめる）。ロビーに選択肢を出すまでは、作成の設定に載らないので、サーバーの定数だけで既定が決まる
- ロビーの選択肢は、旗（manifest.ts の ROAMING_READY・SPREADING_READY。いまは false）が立つまで出さない。開発用の環境変数 NEXT_PUBLIC_VERYARE_ROAMING=1・NEXT_PUBLIC_VERYARE_SPREADING=1 のときだけ出す（平屋の旗と同じ形）
- ルーム情報（room-info）に roaming: true・spreading: true を載せる（従来の規則では載せない。形はこれまでと同じ）。画面は、これを見て操作を変える
- 観戦ルームは、いつも従来の規則（設定を読まない）

### 規則 1: 動ける隠れ側（ADR 0024 の「探索中の隠れ側は動けない」を、このルームについて置き換える）

- まだ隠れている人間の隠れ側は、ペイントと探索の間も、動けて、向きを報告できる。移動の規則（ADR 0042）は鬼と同じ。隠れ CPU は動かない
- 見た目（ペイントとポーズ）は、既存の電文（type: "paint"）を、更新として何度でも受け付ける（同じ人は 1 秒あける。大きさの上限は、これまでの VERYARE_PAINT_LIMITS）。null の項目は前のまま残す
- 探索の間だけ、動く隠れ側の位置と向きを、1 通にまとめて全員へ送る（type: "roaming"。変わったときだけ、120 ms の間隔。待機ルームのメンバーと同じ仕組み / ADR 0044）。探索の間に受け付けた見た目の更新は、その場で全員へ送る（type: "look"）
- ペイントの間は、互いの位置と見た目を見せない（ADR 0025・0026 の心理戦を保つ）。ペイントの間の見た目は、探索の開始の一括配信（ADR 0035）に載る
- 射撃の判定と鬼 CPU は、サーバーが持ついまの位置を使う（もともと、そうなっている。テストで確かめる）
- 探索中の隠れ側の歩く速さは、画面の定数（初期値 3.0 m/秒。鬼は 4.5 m/秒）。サーバーは速さを制限しない（性善説 / ADR 0035）

### 規則 3: 襖の自動開閉（ADR 0033・0042 の「鬼が開ける」を、このルームについて置き換える）

- 探索の始まりで、全部の襖が閉まる（これまでどおり）
- 探索の間、鬼（人間・CPU）と隠れ側が、襖の境から 0.8 m（定数 auto_door_reach）以内に入ると、サーバーがその襖（組の辺すべて）を開ける。一度開いた襖は、試合の終わりまで開けっぱなし
- 判定はサーバーが持つ位置で行う。開ける報告（type: "open-door"）は捨て、画面は「襖を開ける」ボタンを出さない
- 開いた襖は、これまでの襖の通知（type: "doors"）で全員に届く

### 規則 2: 増え鬼（最小版）

- 人間の隠れ側だけが、見つかると、鬼になる（見つかった場所で、すぐ動け、撃てる）。CPU の隠れ側は鬼にならない。最後の 1 人も鬼になる（結果で鬼の側に並ぶ）
- 状態機械は、最初の鬼（oni。1 人）と、途中から鬼になった人（extra_oni。見つかった順）を分けて持つ。フェーズの通知の oni、鬼 CPU、見逃しポイント、鬼の視界の報告は、最初の鬼だけを使う（従来と同じ）
- 撃つ間隔は鬼ごと。同時に複数の鬼が同じ隠れ側を撃っても、サーバーが受け取った順で最初の 1 つだけが有効（ADR 0014。2 つ目は、もう隠れていないので外れ）。二重に鬼にならない
- 鬼の位置と向きの通知は、複数の鬼を 1 通にまとめる。増え鬼のルームだけ、鬼の通知（type: "oni"）に others（途中から鬼になった人の位置と向き）を足す。人が鬼になったときは、その場で送り、途中から鬼になった人が動いたら、120 ms の間隔で、変わったときだけ送る
- 隠れ側が 0 人で鬼の勝ち。時間切れで 1 人以上残れば、隠れ側の勝ち（勝敗の判定は従来のまま）。結果の行では、途中から鬼になった人は鬼の側（状態: 途中から鬼）に並ぶ。トロフィーは入れない
- 途中から鬼になった人の離脱は、鬼から外すだけ。最初の鬼の離脱は、従来どおり隠れ側の勝ち（最小版の割り切り。鬼を引き継ぐかは、あとで決める）
- 隠れ側の情報は、これまでどおり、探索の開始の一括配信で全員に届いている（ADR 0035）。鬼になった人が新しく得る情報は無い

## 理由

- 選べる形にすると、従来の動きとテストを変えずに、新しい規則を遊び比べられる。既定を変えるのは、定数 1 つで済む
- 隠れ側の位置を探索中に送ることは、ADR 0035 の延長である。探索の開始の一括配信で、もともと全員に位置が届いている。動けるようになった分を、同じ考え（誠実なプレイヤーが不公平を感じないか）で送り続ける
- 襖の判定をサーバーの位置で行うと、画面と電文が 1 つ減り、隠れ側と鬼で同じ規則になる

## 検討した代替案

- 規則を 1 つの設定にまとめる案。増え鬼は勝敗と結果の形に触れるので、動ける隠れ側とは別に遊び比べたい。分ける
- 見た目の更新を、新しい電文にする案。既存の paint の電文で形が足りるので、意味だけを広げる（契約の変更は payload の追加だけ）
- 動く隠れ側の位置を、隠れ側の一括配信（hiders）の送り直しで送る案。ペイントを毎回載せると重いので、位置と見た目を分ける

## 結果

- サーバー: game.gleam に roaming（規則）と、動ける判定・見た目の更新・襖の自動開閉・動く隠れ側の一覧を足す。room.gleam に設定の読み取り（parse_rules）、通知のタイマー、送り直しを足す。従来の規則の分岐は変えない
- 契約: VeryareRoamingNotice・VeryareLookNotice・VERYARE_ROAMING を足し、共有の見本 fixtures/veryare-roaming.json を両方のテストで読む
- 参加・復帰の組み合わせ表（bots/src/trials/joinMatrix.ts）に、動ける隠れ側の構成を足す
- 画面: 探索中の隠れ側に移動パッドと、動かせるペイントの板（既定で上に出す）を出す。鬼の画面で、動く隠れ側の体を補間して動かす（待機・歩く・走る・止まると選んだポーズ）。新しい規則では、襖のボタンを出さない。増え鬼では、途中から鬼になった人を鬼の体で描き、本人には「あなたも鬼になった」を出し、鬼と隠れ側の人数を出す
- 調整: 襖が開く距離はサーバーの定数（game.gleam の auto_door_reach）。隠れ側の歩く速さは画面の定数（roaming.ts の ROAMING_HIDER_SPEED）で、開発用の合図（?roof=1）があれば URL の ?hiderSpeed= で変えられる
- ボット: 動ける隠れ側のシナリオ 1 本と、増え鬼のシナリオ 2 本。従来の規則のルームで、動ける隠れ側の通知が届かないことを、すべてのシナリオで確かめる
