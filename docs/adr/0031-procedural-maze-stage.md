# ADR 0031: 迷路生成によるステージ構成とステージ選択

- ステータス: 受理
- 日付: 2026-09-30
- 関連: 本ADRは ADR 0026 の「禁止エリア（めり込み処理）」の部分を置き換える。ADR 0026 の「被り判定」の部分は変更しない
- 関連（後日追記）: 迷路生成（全域木）の方式は ADR 0032 で置き換えられ、ドアを対象外とする決定は ADR 0033 で覆された。現実的な縮尺とステージ選択（roomOptions）は現在も有効

## 文脈

ADR 0026 では、フリー素材のオブジェクトにバウンディングボックスから禁止エリアを自動生成し、めり込みへの猶予とカウントダウン、固定候補地点への強制移動という仕組みを定めた。

これに対し、天井まで繋がった通り抜け不可の壁で構成される迷路状のステージにすれば、めり込みの判定自体が不要になり、実装が単純になる。また、ステージが毎回同じだと周回を重ねるうちに攻略が固定化するため、エリアのサイズは固定のまま、壁の配置を毎回変えられると、隠れる楽しさが持続する。

加えて、ステージそのものを複数の選択肢から選べるようにしたいという要望があり、ランダム生成のステージはその選択肢の1つと位置づける。

## 決定

**迷路生成**: ステージは格子状のマスで構成し、マスとマスの間の壁の有無をランダムに決めて生成する。生成には全域木を作る手法（マスとマスの接続をランダムに選びながら、全マスが必ず繋がった状態になるまで壁を取り除く）を用い、孤立して到達不能なマスが生じないことを保証する。壁は天井まで届き、通り抜けはできない。壁の当たり判定は、通常の3D衝突判定（触れたら止まる）でよく、ADR 0026 のような猶予・カウントダウン・強制移動の仕組みは不要とする。

**現実的な縮尺**: すべてのステージ（迷路に限らず、待機ルームやランダム生成でない将来のステージも含む）は、人が違和感を覚えない現実的な広さを基準とする。迷路については次を目安とする（実装後、実際に歩いて調整する前提の仮の値）。

- 廊下の幅: 2m
- 1マスの大きさ: 4m四方（部屋1つ分の広がり）
- 壁の高さ: 2.4〜2.7m
- 格子全体: 8×8マス（「巨大な屋敷」の広がりを想定）

**ステージ選択**: GameManifest の roomOptions（ADR 0024 で導入した仕組み）に、ステージを選ぶ項目を追加する。現時点での選択肢はランダム生成のみとする。将来、作り込んだステージ（和風の屋敷など）を追加する場合も、選択肢を増やすだけで済む形にしておく。

**ドアの扱い**: 開閉可能なドア（襖など）は、今回のスコープに含めない。壁は生成後は固定とする。ドアは将来の拡張候補として扱う。

## 理由

- 天井まで届く壁による通り抜け不可の構成にすることで、めり込みの許容量やカウントダウンといった、ADR 0026 で必要だった複雑な仕組みが丸ごと不要になる。当たり判定は「触れたら止まる」だけで済み、実装・検証のコストが下がる
- 全域木による生成手法を使うことで、孤立したマス（どこにも繋がっていない、辿り着けない領域）が原理的に発生しない。ちゃぴぃが懸念していた「埋まってしまう」問題は、アルゴリズムの性質上解消される
- エリアのサイズを固定し、配置だけを毎回変えることで、周回ごとに新鮮な隠れ方の選択を提供できる
- すべてのステージに現実的な縮尺を適用することで、プレイヤーが空間の広さに違和感を覚えず、直感的に距離感を掴める
- roomOptions という既存の仕組み（探索時間の選択で使用済み）にステージ選択を乗せることで、新しい基盤機能を追加せずに済む

## 検討した代替案

- 開閉可能なドア（襖）を含める案。同期・駆け引きの設計が新たに必要になり、2週間のスコープに対して過大なため、将来の拡張候補として見送った
- 固定の単一ステージのみとする案。ステージ選択という要望と、周回ごとの新鮮さを両立できないため、生成方式を採用した

## 結果

- ADR 0026 の禁止エリア関連の実装方針（バウンディングボックス自動生成、80%縮小、5秒カウントダウン、固定候補地点への強制移動）は、迷路生成ステージには適用しない。被り判定（プレイヤー同士の球体コリジョンの重なり）は ADR 0026 のまま変更しない
- 迷路生成のアルゴリズム（全域木方式）と、上記の縮尺目安を issue-26 に反映する
- GameManifest の roomOptions に、ステージ選択の項目を追加する（issue-29）
- ドアは対象外とし、壁は生成後固定とする
