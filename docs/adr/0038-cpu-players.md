# ADR 0038: CPU プレイヤー（隠れ CPU・鬼 CPU）

- ステータス: 受理
- 日付: 2026-10-01

## 文脈

本家にない機能として、CPU のプレイヤーを設けたい。1台でも鬼と隠れ側の両方の視点を体験・説明できること、人数が揃わなくても遊べること、開発中に1タブで動作確認できることが狙いである。

## 決定

**実装の場所**: CPU はサーバー側（Gleam）の純粋関数として実装し、ルームの参加者として扱う。識別子は `cpu-N`、表示名は「CPU N」とし、クライアントからは通常のプレイヤーと同じに見える。乱数は種を引数に取り、テストで決定的に検証できるようにする。

**追加の方法**: ルーム作成時の選択肢（roomOptions、ADR 0024）に「CPU」を設ける。選択肢は「なし」「隠れ側 CPU 1〜3体」「鬼 CPU」とする。CPU は定員（5人）の枠に含まれ、最小人数（2人）の判定にも数える。鬼 CPU を選んだ場合は鬼選出フェーズを省き、CPU を鬼とする（人間は全員隠れ側）。隠れ側 CPU は、鬼希望エリアに立候補せず、鬼の抽選の対象にもならない。

**隠れ CPU**: 準備移動フェーズの間に、部屋スロット内のマスから、他の隠れ側と被らないようにランダムに位置を選ぶ。ポーズもランダムに選ぶ。ペイントは、その場の周囲の代表色で全面を1色に塗る。準備移動の終了時点で状態を確定させ、人間の隠れ側と同じ経路（探索開始時の一括配信）で配信される。

**鬼 CPU**: 探索フェーズの間、0.5秒ごとに1ステップ進む。

- 探索: 玄関から出発し、部屋スロットの襖を、ランダムな順の深さ優先（または幅優先）で巡る。一定の確率で襖を飛ばしたり、再訪したりして、精度を粗くする。開けた襖は開けっぱなしとする（ADR 0033）
- 視界: CPU ごとに、視野角と視距離を、決められた範囲の乱数で決める。壁と閉じた襖は視線を遮るものとして、マス目の上で見通しを判定する
- 発見判定: 視界に入った隠れ側に対し、0.5秒ごとに乱数を引く。発見確率は、距離が近いほど高く、周囲との溶け込み度が高いほど低い。成功すれば、人間の鬼が撃って当てた時と同じ「見つけた」処理を呼ぶ
- 溶け込み度: 隠れ側のペイントの平均色と、その場の周囲の代表色（部屋タイプごとの色の表）の差を、0〜1 に正規化したもの。差が小さいほど発見確率が下がるが、0 にはならない下限を設ける
- 見逃しポイントの「視界に入っているか」（ADR 0036）は、鬼 CPU の場合、上記と同じ見通しの判定をサーバーが行う

CPU は、勝敗の判定と「まだ隠れている」集合に、通常のプレイヤーと同じように入る。

**強さの設定**: 歩く速さ、視野、発見確率、探索の粗さをひとまとめにして、「よわい／ふつう／つよい」のプリセットとする。ルーム作成時の選択肢（roomOptions）で選べるようにする。隠れ CPU にも、色のずれや配置の奥まり具合などで強さの差をつけられる。

**シミュレーション**: CPU だけの対戦（鬼 CPU と隠れ CPU のみ）を、骨格と強さの組み合わせごとに種を変えて繰り返し実行し、結果を集計する。集計するのは、勝率、見つかるまでの時間、ゲームが時間内に終わったか、そして ADR 0028 の条件に反する異常（フェーズが止まる、壁越しの発見など）の有無である。ここで得た数値は、難易度の調整とバグの発見に使う。人間の隠れ方の癖や、カメラの操作感、通信の遅れは反映されないため、最後の調整は実際に遊んで行う。

## 理由

- サーバー側の純粋関数にすることで、乱数の種を固定したテストと、数千回のシミュレーションによる難易度の調整ができる
- サーバーは骨格の歩ける範囲・襖・部屋スロットを既に持っており、経路探索と見通しの判定に必要なデータが揃っている
- 発見判定を既存の「見つけた」処理に繋ぐため、勝敗・観戦・ポイントの仕組みを CPU のために変える必要がない
- 見通しの判定を、見逃しポイントの視界判定と共通化できる

## 検討した代替案

- CPU をホストのクライアントで動かす案。ホストの端末と通信に依存し、再現性のあるテストも難しいため採用しない
- 色の差を、実際の描画から取る案。サーバーには描画がないため採用しない

## 結果

- 色の差は、色の表を使った近似になる。実際のモデルの質感と大きくずれないよう、素材から平均色を取って表を作る
- 発見確率・歩く速さ・視野角と視距離の範囲は、パラメータとして持ち、シミュレーションで調整する
- issue-33（CPU 基盤と隠れ CPU）、issue-34（鬼 CPU）で実装する
