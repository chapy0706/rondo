# ADR 0052: 表示名（userN）の番号は、空いている一番小さい番号から使い回す

- ステータス: 提案（下書き）
- 日付: 2026-10-22
- 関連: ADR 0015（端末保持の表示名。既定は user1, user2, ...）、ADR 0013（再接続猶予）、ADR 0028（許容基準）、ADR 0045・0047（台帳とプロセスの監視の形）。issue-71。本 ADR は ADR 0015 を書き換えない（名前の形 user + 番号は同じ）

## 文脈

接続したときにサーバーが付ける表示名（user + 番号）は、VM の中で単調に増える番号（`erlang:unique_integer([positive, monotonic])`）を使っていた。番号は戻らないので、2 人しか遊んでいなくても、接続を重ねると user33 のような名前になり、ルーム名の既定（「user33のルーム」）や待機ルームの頭上の名前に出る。番号はサーバーの再起動でだけ 1 に戻っていた。

## 決定

1. 番号は、接続ごとに 1 つ持ち、空いている一番小さい番号（1 から）を渡す。番号の選び方は、プロセスを持たない純粋な部分（`connection/user_number`）に置く
2. 番号の窓口は、接続アクターの台帳（`connection/sessions`）が兼ねる。台帳は、接続アクターを登録するときに番号を渡し、接続アクターのプロセスを監視する。プロセスが止まったら、終わり方（ふつうの退出、切断の猶予切れ、復帰で捨てられた接続、異常終了）に関わらず、監視の知らせで番号を空ける
3. 切断の猶予の間は、接続アクターが生きているので、番号は取っておかれる。復帰した人は、同じ接続アクターに戻るので、同じ名前のまま。猶予が過ぎて接続アクターが止まると、番号が空く
4. 名前は、接続を開いた直後（電文を受け取る前）に付ける。ルームに入る前に決まっているので、ルーム名の既定、参加者の一覧、結果の一覧には、新しい名前が出る
5. 窓口（台帳）は、作り直さない。台帳はサーバーの起動のプロセスにつながっていて、落ちるとサーバーのプロセス全体が終わる（`gleam@@main:run` が `init:stop(1)` で止まる）。本番は `restart: unless-stopped` で作り直され、そのときには接続が 1 つも残っていないので、番号は 1 から始まり、すでに接続している人の番号と重ならない。ルーム台帳（room_directory）と同じ扱い

## 理由

- 番号を持つ期間を、接続アクターの寿命にそろえると、「確保」と「解放」の対が、登録と監視の知らせの対になり、解放の漏れ（いつまでも空かない番号）が起きない
- 台帳は、すでに接続アクターを監視し、止まったら消す役を持っているので、番号の窓口を兼ねても、新しい監視や新しいプロセスが増えない。接続の部品の受け渡し（Deps）の形も変わらない
- 窓口だけを作り直す形は、作り直したときに、生きている接続の番号を知らないので、重なる。全体を作り直す形なら、重なりようがない

## 影響

- 契約（電文の形）と、勝敗の判定は変わらない。名前は、これまでどおりサーバーが付けるラベル
- 同じ名前が、時間をおいて別の人に付く。プレイヤーの区別は識別子（player_id）で行っていて、名前に頼る処理は無い
- 既定のルーム名（「user1のルーム」）が、一覧に同時に 2 つ出ることがある（作った人が抜けたあとも、他の人が残るルーム）。ルーム名は、これまでも人が決められ、重なりを許していた。一覧の行はルーム ID で見分ける
- 復帰のときに、新しいソケットのために開いた接続アクターも、一時的に番号を持つ（付け替えに成功すると止まり、すぐ空く）
- 番号の選び方は、使っている番号の数に比例する手間（同時接続は数百まで）

## 検討した代替案

- 単調な番号のまま、ルームの中だけで番号を振り直す案。頭上の名前と結果の一覧で、同じ人の名前がルームごとに変わるので、採らない
- 番号の窓口を、別のプロセスとして立てる案。接続の部品の受け渡し（Deps）を変える必要があり、監視も二重になる。台帳と寿命が同じなので、分ける利点が無い
- 窓口が作り直されたときに、生きている接続から番号を集め直す案。仕組みが大きくなる一方、窓口が落ちるのは台帳ごと落ちるとき（サーバー全体の作り直し）だけなので、採らない

- `server/test/rondo_server/connection/user_name_test.gleam`（実接続の入口から: 空いた番号の再利用、全員が抜けたあとの user1、猶予の間の保持と猶予切れの解放、異常終了での解放、200 接続を同時につないだときの重なりの無さと、最小の空きからの再利用）
