# ADR 0040: 素材は公開リポジトリに入れず、別のオリジンから配信する。素材がなくても動く

- ステータス: 提案（下書き）
- 日付: 2026-10-05
- 関連: ADR 0009（契約は TypeScript を正とする）、ADR 0028（許容基準）、ADR 0035（性善説）、ADR 0039（固定ステージ「平屋」）。本 ADR は既存の ADR を書き換えない

## 文脈

GitHub のリポジトリは公開である。ステージ（平屋）とキャラクター（Mixamo）の素材は、再配布が制限されている（平屋の規約は、権利者でない者による二次的な配布を禁じている）。そのため、素材は、元データも変換後の glb も、リポジトリに入れない（`docs/assets.md`）。

一方、ゲームは本番で素材を読み込みたい。また、リポジトリを取り出した人や CI、素材の配信が止まったときにも、ゲームが動かなくなってはいけない。これまでの veryare は、仮の表示（箱とカプセル）で動いている。

## 決定

**素材は公開リポジトリに入れない**: 元データ（`.blend`・`.fbx` など）も、変換後の glb も、リポジトリに入れない。`.gitignore` で除外する。ゲームのコードにも、素材のファイル名を直接書かない。素材は、論理的な名前（key。例: `hiraya-indoor`）で指す。リポジトリに入れるのは、変換・調査のスクリプト、手順、素材の位置を写した設計のデータ（ADR 0039 の文字地図など）、規約の要約だけとする。

**別のオリジンから配信する**: 素材は、A1 の素材ディレクトリから、専用の小さなコンテナ（`rondo-assets`、nginx）で、`assets-rondo.chapy0706.com` として配信する。

- 素材の一覧（`manifest.json`）を配信側に置き、アプリが最初に取得する。各素材の key、品質（テクスチャの長辺の上限 512 / 1024）、版、相対パス、バイト数を持つ
- 素材のパスには版を入れ（`v1/...`）、中身を変えない。長期キャッシュ（`immutable`）にする。中身を変えるときは版を上げる。`manifest.json` だけは短くキャッシュする
- CORS は、許可する1つのオリジン（本番は `https://rondo.chapy0706.com`）を、要求の `Origin` に関わらず返す。Cloudflare は既定で `Vary` を見ず、`Origin` をキャッシュの鍵に入れられないため。ローカル開発は、同じコンテナを手元で起こし、ローカルのオリジンを許可する
- Cloudflare は `.glb` を既定でキャッシュしないので、Cache Rules で版付きのパスをキャッシュの対象にする（`docs/deploy.md`）

**基準 URL はビルド時の環境変数**: アプリは、素材の基準 URL を `NEXT_PUBLIC_ASSET_BASE_URL`（ビルド時）で受け取る。WebSocket の `NEXT_PUBLIC_RONDO_WS_URL` と同じ扱いとする。

**素材がなくても動く**: 仮の表示を基準とし、本素材は上乗せとする。

- 基準 URL が未設定なら、素材は読み込まず、仮の表示で動く
- 読み込みの失敗（manifest が無い、404・接続できない、壊れた glb、タイムアウト）は、利用者に警告を出さず、仮の表示に切り替える。エラーで止めない。原因は console に記録する
- 読み込みは、ゲームの開始を待たせない。仮の表示で始め、見た目が急に変わらない時点（待機ルームの間など）で、読み込めていれば差し替える。間に合わなければ、その回は仮の表示のまま
- 素材の有無で、遊べる機能は変わらない。テスト（`make verify`）は素材に頼らない
- 品質は既定で 512 とする

## 理由

- 再配布が制限された素材を、公開リポジトリに置かずに本番で使える
- 素材が届かない環境（clone した人、CI、配信の障害）でも、仮の表示でゲームが成立する。ADR 0028 の許容基準（見た目の粗さは許容）とも合う
- 版付きのパスと長期キャッシュで、Cloudflare とブラウザのキャッシュが効き、A1 への負荷と読み込みの時間を抑えられる。manifest.json を短くするだけで、素材の差し替えが反映される
- 配信を小さな nginx に分けることで、アプリのイメージに素材を含めず、アプリのビルドと素材の更新を独立させられる

## 検討した代替案

- 素材をリポジトリ（`apps/web/public/`）に置く案。公開リポジトリで再配布にあたるため採用しない
- 素材をアプリのイメージに焼き込む（ビルド時に私的な場所から取り込む）案。ビルドの手順が複雑になり、素材の差し替えのたびにアプリを再ビルドする必要があるため採用しない
- 要求の `Origin` に合わせて CORS のヘッダを返す案（複数のオリジンを許可）。Cloudflare が Origin でキャッシュを分けないため、別のオリジン向けの応答が配られるおそれがあり採用しない
- 認証付きの配信・素材の暗号化。ブラウザに届く以上、取り出しを完全には防げず、性善説（ADR 0035）にも合わないため採用しない

## 結果

- issue-43 で、配信（`docker-compose.assets.prod.yml`、`deploy/assets/`、Traefik の見本）、クライアントの読み込み（`apps/web/src/infrastructure/assets/`）、疎通の確認用の glb（`tools/make_test_glb.mjs`）、手順（`docs/assets.md`・`docs/deploy.md`）を用意する
- 素材を使う機能（平屋 issue-46、キャラクター issue-25）は、key で素材を読み込み、差し替えの時点を自分で決める
- A1 の素材ディレクトリの作成、Cloudflare Tunnel の公開ホスト名・Cache Rules、Traefik の設定の配置、素材のアップロード、web の再ビルドは、人手で行う
