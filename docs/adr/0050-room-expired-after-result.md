# ADR 0050: 結果のあと、一定の時間で、ルームを閉じる（room-expired と closesInMs）

- ステータス: 提案（下書き）
- 日付: 2026-10-20
- 関連: ADR 0017（ルームは作る → 遊ぶ → 終わる → 解散）、ADR 0045（終わったルームは数えない）、ADR 0046（通知の長さは、作った時点からの残り）、ADR 0047（落ちたルームと room-closed）。issue-70。本 ADR は ADR 0045 の「ルームのプロセスの寿命は変えない」を、結果のあとについて置き換える

## 文脈

ADR 0045 で、終わったルームは同時ルーム数に数えなくなった。ただし、終わったルームそのものは、中に人が残っている限り、サーバーに残り続ける（ルームのプロセス、接続、メモリ）。発表会では、スマホが結果画面のまま置かれることがよく起き、1 日のあいだに、終わったルームが溜まっていく。

## 決定

- 閉じる判断は、サーバー（ルーム）が持つ。結果が確定したとき（Finished に移ったとき）だけ、ルームが自分にタイマーを張り、3 分（`room/expiry.gleam` の `default_close_ms`）がたつと閉じる。進行中のルームは閉じない
- 時間は、テスト用の短縮（`RONDO_TEST_PHASE_DIVISOR`）で、フェーズ時間と同じく割る（`games/timing.gleam` の `finished_close_ms`）。ルームの設定（`RoomSpec`）の `close_after_ms` で渡す
- タイマーは、ルームの `Wake` の token で受ける。token は `-1_000_000_000_000`（`expiry.expire_token`）で、ゲームのタイマー（veryare のフェーズ: 0 以上、鬼 CPU の tick: -1 - step、待機メンバー: -1_000_000 - step）と重ならない
- 閉じるとき、ルームは、残っている参加者へ `error` の `room-expired` を送ってから、ふつうに終わる。そのあとは、いまの仕組みが働く。台帳は監視でルームを外し（ADR 0045・0047）、接続は監視で入っているルームを外す。終わり方が normal なので、`room-closed` は送らない。切断中の接続は、戻る先が無いので終わり、その復帰トークンでは戻れない（`reconnect-failed`）
- `room-expired` は、`error` の code の値を 1 つ足すだけで、契約の型（`code: string`）は変わらない。落ちたときの `room-closed` の動き（案内とロビーへの導線）は変えない
- `game-ended` に、省略できる項目 `closesInMs`（閉じるまでの残り。ミリ秒）を足す。意味は、通知を作った時点からの残り（ADR 0046 と同じ考え方）。結果を出した時点では、まるごと（3 分）。結果のあとに送信先を登録し直した人（復帰）へは、ルームが結果を、残りつきで送り直す。省略されたときは、これまでと同じ動き（残りを出さない）
- 画面: 結果画面に「あと ○ 秒で、ロビーへ戻ります」を小さく出す（表示だけ）。`room-expired` を受けたら、ロビー（`/lobby/veryare`）へ戻し、ロビーの案内の枠に「前のルームは、閉じられました」を出す
- 参加者が全員退出したときに閉じる、これまでの動きは変えない（タイマーが残っていても、ルームはもう無いので、何も起きない）

## 理由

- 閉じる時刻をルームが持てば、接続や台帳がルームの中の状態を問い合わせなくてよい。閉じたあとの後片付けは、落ちたときのための監視の仕組み（ADR 0047）がそのまま使える
- 残りを `game-ended` に載せれば、画面の時計と、サーバーの閉じる時刻（テストの短縮を含む）がずれない。省略できる項目なので、古い画面は壊れない
- 落ちたとき（`room-closed`）と、時間で閉じたとき（`room-expired`）を、code で分けると、時間で閉じたときだけ、自動でロビーへ戻せる

## 影響

- 安全性: 勝敗の判定とフェーズの遷移は変わらない。閉じるのは結果のあとだけ
- 運用: 結果画面のまま置かれた端末は、3 分でロビーへ戻る。ロビーの一覧の自動更新が、そのまま続く
- 確かめ: サーバーの結合テスト（`server/test/rondo_server/connection/room_expired_test.gleam`）、閉じる判断の純粋関数のテスト（`server/test/rondo_server/room/expiry_test.gleam`）、ボット（`make bots` の「結果のあと、ルームが閉じる」と、`./tools/load.sh join` の「結果のあと」の時機）、E2E（`pnpm --filter @rondo/e2e e2e:expiry`）

## 検討した代替案

- 落ちたときの `room-closed` を使い回す案。落ちたときも自動でロビーへ戻るようになり、ADR 0047 の動きが変わるので採らない
- 画面が定数（3 分）を持ち、契約を変えない案。テストの短縮に付いて行けず、サーバーの時刻とずれるので採らない
