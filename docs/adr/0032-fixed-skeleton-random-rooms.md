# ADR 0032: 固定骨格(10種)とランダム間取りによるステージ構成

- ステータス: 受理
- 日付: 2026-09-30
- 関連: 本ADRは ADR 0031 の迷路生成方式（全域木によるマス間の壁生成）を置き換える。ADR 0031 のうち、現実的な縮尺・ステージ選択機能(roomOptions)・被り判定への非影響は、そのまま維持する

## 文脈

ADR 0031 では、格子状のマスを全域木アルゴリズムで繋ぐことで、毎回配置の変わる迷路を生成する方式を定めた。これは孤立した到達不能マスを防げる一方、生成アルゴリズム自体の実装と検証が必要になる。

より単純に同じ目的（周回ごとの新鮮さ、到達不能な区画が生じないことの保証）を達成する方法として、廊下の骨格をあらかじめ複数パターン用意し、各パターン内の部屋の中身だけをランダムに割り当てる方式が提案された。

## 決定

**廊下骨格**: あらかじめ10種類の廊下レイアウト（骨格）を作成する。1回のゲームにつき、この10種類から1つをランダムに選ぶ。骨格は固定であり、生成アルゴリズムを介さない。

**部屋タイプ**: 部屋タイプの候補プールは、和室・縁側・押し入れ・玄関とする（平屋モデルの実際の間取りを参考にする）。実際の素材寸法を確認したところ、大きい和室1室分のサイズが「中くらいの和室＋押し入れ」または「中くらいの和室＋掛け軸エリア（床の間）」の組み合わせと一致することが分かった。これを踏まえ、部屋スロットには大小2種類のサイズを設ける。

- **大スロット**: 次のいずれかを割り当てる
  - 和室単体
  - 和室＋押し入れの組み合わせ（押し入れは部屋の内部から入る形とし、廊下側からは部屋の襖1つだけが見える。実際の素材構造に沿った、組み立てやすい形）
  - 和室＋掛け軸エリアの組み合わせ（床の間のような、部屋内部の一角。**隠れる機能は持たせない見た目だけの装飾とする**。段差があり特殊な形のニッチで、専用の当たり判定・隠れポーズを要するため、初期スコープでは対象外とした。当たり判定・座標データとしては部屋全体の一部として扱う）
- **小スロット**: 押し入れ単体を割り当てる。これは廊下に直接面した、部屋を介さない独立した押し入れで、狭く閉塞感のある隠れ場所になる。ランダムに出現する変化球として位置づける
- **空きスロット**: スロットに何も割り当てず、廊下だけが通っている区画として残すことも許容する。屋敷全体の密度に濃淡を持たせ、生成のたびの見た目の変化を大きくする

和室は8〜12室程度（内訳は和室単体・押し入れとの組み合わせ・掛け軸エリアとの組み合わせが混在してよい）、押し入れ（部屋内包・独立の両方を合わせて）は4室前後、縁側は1箇所、玄関は1箇所で固定とする。

- 縁側: 隠れることはできるが、屋敷の外周（庭側）には見えない壁を設け、そこから出られないようにする
- 玄関: 1箇所で固定とする。**鬼の初期リスポーン位置**であり、**隠れ側が準備移動フェーズ開始時にステージへ移動する際の初期位置**でもある（両者とも同じ玄関から屋敷に入る）

全体の規模感は、縦長の屋敷を想定する。10種類の骨格は、いずれもこの部屋タイプの構成に沿う。

**到達可能性の保証**: 部屋への出入り口（襖）は、廊下に面したスロットにのみ設ける。廊下はあらかじめ人間が設計した、必ず繋がっているレイアウトであるため、全域木のような接続保証のアルゴリズムを必要とせず、構造的に「廊下経由で到達できない部屋」が生じない。

**部屋同士は直接繋がない**: 骨格の配置上、2つの部屋スロットが隣り合う（壁を共有する）ことがあっても、その共有壁には襖を設けない。常に塞がれた壁として扱う。部屋の出入り口は、各部屋が持つ「廊下に面した襖」1つだけとする。これにより、廊下だけが繋がりを保証するという単純さが保たれ、部屋同士の隣接関係による間接的な到達可能性を検算する必要が生じない。

## 理由

- 廊下が固定・既知の構造であるため、到達可能性を検算するアルゴリズム（全域木など）が不要になる。骨格そのものが接続の保証であり、実装・検証のコストが ADR 0031 の方式より小さい
- 10種類の骨格 × 部屋タイプのランダム割り当てにより、完全な procedural generation ほどの実装コストをかけずに、周回ごとの新鮮さを確保できる
- 部屋の出入り口を廊下に面したスロットに限ることで、「誰も入れない部屋ができる」ことが構造的に起こり得ない
- 平屋モデルの実際の間取りを部屋タイプの候補として使うことで、素材の質感と設計の意図を活かせる

## 検討した代替案

- ADR 0031 の全域木による迷路生成。孤立マスを防ぐ保証は同等だが、生成アルゴリズムの実装・検証コストが本方式より高いため、より単純な代替として本ADRを採用した
- 部屋の配置自体もランダムにする（スロットの位置も毎回変える）案。到達可能性の保証が複雑になるため見送り、スロット位置は骨格に固定した
- 隣接する部屋同士を直接繋ぐ襖を設ける案。移動の近道として面白みは増すが、廊下だけが繋がりを保証するという単純さが崩れ、部屋同士の隣接関係を通じた間接的な到達可能性を検算する必要が生じるため、今回は見送った（将来、特定の骨格にだけ手作業で「隠し通路」的に加える案は、時間が許せば検討の余地がある）
- 掛け軸エリアを隠れられる場所にする案。段差・特殊な形状に対応する専用の当たり判定・隠れポーズが必要になり、対象となる室数の割にテスト・実装のコストが見合わないため見送った。装飾として扱い、隠れる機能は持たせないこととした（issue-29 以降、時間が許せば後付けで拡張する余地は残す）

## 結果

- 10種類の廊下骨格を用意する（issue-29 で作成）。スロットは大小2種類のサイズを持つ
- 大スロットには、和室単体・和室＋押し入れ・和室＋掛け軸エリアのいずれかをランダムに割り当てる。小スロットには押し入れ単体を割り当てる。スロットは何も割り当てず空きのままにすることも許容する
- 部屋の出入り口（襖）は、廊下に面した各スロットにつき1つとする。部屋内包の押し入れ・掛け軸エリアは、その部屋の内部からのみ入れる（廊下に別の襖を設けない）。部屋同士を直接繋ぐ襖は設けない
- 縁側の外周（庭側）には見えない壁を設け、屋敷の外に出られないようにする
- 玄関を、鬼と隠れ側の双方の初期リスポーン位置とする（探索フェーズ開始時の鬼、準備移動フェーズ開始時の隠れ側、いずれも玄関からステージに現れる）
- ADR 0031 の全域木生成ロジックは、この方式に置き換えて実装しない
