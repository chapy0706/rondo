# ADR 0047: ルームのプロセスが落ちたときは、作り直さず、入っていた人に room-closed を送る

- ステータス: 提案（下書き）
- 日付: 2026-10-16
- 関連: ADR 0006（ルームはプロセスとして独立し、スーパーバイザーが監視する）の「異常終了のときは回復させる」を、ルームについて置き換える。ADR 0013（再接続猶予）、ADR 0030（同時ルーム数）、ADR 0045（終わったルームは数えない）。issue-60 の後半。本 ADR は ADR 0006 を書き換えない

## 文脈

ルーム（room_actor）は、room_supervisor の子として動き、再起動の方針は既定の Transient（異常終了のときだけ作り直す）だった。issue-60 の調べで、ルームのプロセスが落ちたときに、次のことが分かった。

- 作り直したルームは、作成の時の設定で、空の状態で立ち上がる。ルーム台帳（room_directory）は、落ちたプロセスの監視の知らせで、そのルームを外すので、作り直したルームは台帳に載らず、誰の接続にもつながらないまま残る（台帳の数え漏れ。`docs/schedule.md` の既知の抜けだった）
- 入っていた人の接続（session_actor）は、落ちたルームを指したまま。ゲームの通知が来なくなるが、ハートビートは接続の層なので続き、切断にもならない。画面は黙って固まり、案内が出ない。入っていることになっているので、新しいルームも作れない（already-in-room）
- 一覧と参加の処理は、各ルームへ 1 秒の問い合わせ（process.call）をする。相手が落ちている・1 秒答えないと、問い合わせた接続の処理が止まる

## 決定

1. ルームの再起動の方針を Temporary にする。落ちたルームは作り直さない（台帳と supervisor の子の数が揃う）
2. 接続（session_actor）は、入っているルームのプロセスを監視する（入る・出るたびに張り直す）。ルームが異常に終わった（落ちた）ときだけ、本人に `error` の `room-closed` を送り、入っているルームを外す。ふつうに終わったとき（退出で解散・解散の指示。終わり方が normal）は送らない。どちらでも、入っているルームは外す
3. 切断している間にルームが落ちたら、戻る先が無いので、接続は終わる（ルームにいないときの切断と同じ）。戻ってきた接続は `reconnect-failed` で断られる。復帰の直前に落ちていて、監視の知らせより先に戻ったときは、`room-closed` を送ってルームを外す
4. 一覧と参加のときのルームへの問い合わせは、止まらない形（`room_actor.try_snapshot`。相手の監視つきで、落ちていれば、すぐ、答えなければ 1 秒で失敗）にする。失敗したルームは、一覧から飛ばし、参加は `room-not-found` で断る。入った直後に落ちたときは、`room-closed` を返す
5. `room-closed` は、`error` の code の値を1つ足すだけで、契約の型（`code: string`）は変わらない。画面は code から文言を決める（issue-60 の文言の表）。サーバーの文（message）は、表を持たない画面のための既定

## 理由

- 作り直したルームには誰も戻れない（台帳にも接続にもつながらない）ので、作り直す意味がなく、数え漏れと、使われないプロセスが残るだけだった
- 落ちたことを、ルームの外（接続）が監視で知るので、ルームの中の状態に頼らない。落ち方に関わらず届く
- 終わり方（normal かどうか）で見分けると、結果のあとの解散で、誤って「閉じました」と出さない
- 問い合わせの失敗を、接続の処理の外へ広げない。1 つのルームの不具合が、ロビー全体を止めない

## 影響

- 勝敗の判定とフェーズの遷移は変わらない。ルームが落ちたときの遊びは、これまでどおり失われる（作り直しても、状態は戻らなかった）
- `try_snapshot` の答えが 1 秒より遅れて届いたときは、問い合わせた接続の受け箱に 1 通残る（捨てる先が無いため。1 秒以上答えないルームでだけ起こる）
- 確かめ: サーバーの結合テスト（`server/test/rondo_server/connection/room_closed_test.gleam`）。ルームを止める手段がサーバーの外に無いので、ボットでは確かめない

## 検討した代替案

- 作り直したルームを台帳に載せ直し、接続をつなぎ直す案。状態は戻らず、空のルームに戻されるだけなので採らない
- 画面の側で、一定の時間ゲームの通知が来なければ案内を出す案。veryare の待機中は、何も起きなければ通知が来ないので、誤って出る。採らない
