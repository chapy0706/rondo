# ADR 0045: ゲームが終わったルームは、同時ルーム数に数えない

- ステータス: 提案（下書き）
- 日付: 2026-10-14
- 関連: ADR 0030（定員と同時ルーム数とルームの寿命）の「4つ目のルーム作成は、既存のいずれかが終了するまでできない」の「終了」を、ゲームの終了（結果の確定）と定める。ADR 0017（ルームは作る → 遊ぶ → 終わる → 解散）。本 ADR は ADR 0030 を書き換えない

## 文脈

veryare の同時ルームは3つまでとした（ADR 0030）。ルーム台帳（room_directory）は、生きているルームのプロセスを数えていた。ルームのプロセスは、人間の参加者が誰も残らなくなったときに解散する。

issue-51 の上限の試験で、ゲームが終わった（game-ended の後の）ルームに人が残っている間、そのルームが3つのうちの1つとして数えられたままで、新しいルームを作れないことが分かった。結果画面は、参加者が「退出する」を押すまで、ルームに入ったまま出る。発表会で、結果画面のまま置かれた端末があると、枠が埋まり続け、次のグループが遊べない。

## 決定

ゲームが終わったルーム（room_actor の Finished）は、同時ルーム数に数えない。

- ルームは、Finished に移った時点で、ルーム台帳へ知らせる（台帳が、ルームの作成の直後に知らせ先を登録する）
- 台帳は、知らせを受けたルームに印を付け、同時ルーム数から外す。ID では引けるまま（残っている人の退出・再接続の失敗の返事のため）
- ルームのプロセスの寿命は変えない（人間が誰も残らなくなったら解散する）。終わったルームは、これまでどおり参加できず、一覧にも出ない

## 理由

- 終わったルームは、参加できず、一覧にも出ないので、遊べる枠としては、すでに空いている
- 台帳からルームへ問い合わせる形（数えるたびに状態を聞く）は、ちょうど落ちたルームに問い合わせると台帳ごと止まるため、採らない。ルームから知らせる形は、台帳がルームを待たない
- 終わったルームは、人が残っている間だけ生きる。1つの接続は同時に1つのルームにしか入れないので、終わったルームの数は、接続の数を超えない（際限なく増えない）

## 検討した代替案

- ゲームの終了から一定の時間で、ルームを解散する案。結果画面を見ている人の再接続で戻れなくなる、時間の決め方が要る、という点で、今回の目的（枠を空ける）には大きすぎるため採らない
- 直さずに、当日の運用で「結果画面のあとは退出を押す」と案内する案。押し忘れで枠が埋まる心配が残るため採らない

## 結果

- room_actor に、ゲームが終わったときの知らせ先（notify_when_finished）を足す
- room_directory は、知らせを受けたルームを、同時ルーム数（active_count と作成の判定）に数えない
