# ボット同士の対戦（issue-49）

ブラウザを使わず、契約（`packages/contracts`）の電文だけで動くボットを、実際の Gleam サーバーにつなぎ、veryare の最初から最後まで（入室 → 鬼選出 → 準備移動 → ペイント → 探索 → 答え合わせ → 結果）を自動で通す。

## 実行

```bash
make bots                        # 全シナリオ
make bots ARGS="--seed 123"      # 同じ種で再現する
make bots ARGS="--only 不成立"    # シナリオ名の一部で絞る
```

- Gleam サーバーを **3300 番**で起動し（開発用の 3000 番とは別）、終わったら止める
- その間だけ、フェーズ時間を **1/20** に縮める（環境変数 `RONDO_TEST_PHASE_DIVISOR=20`）。1 シナリオは数秒で終わる
- その間だけ、広い屋敷だけ（`{ stage: 3 }`）のルームを受け付ける（環境変数 `RONDO_WIDE_DEV=1` / issue-65）。広い屋敷のシナリオに使う
- 結果は表で出る。終了コードは、全部成功で 0、失敗があれば 1（サーバーが起動できないときは 2）
- `make verify` には含めない（サーバーの起動を伴うため）。ボットの判定の部分（結果の検査、シナリオの宣言の整合、クライアント）は単体テストにして、`make verify` で動く

## フェーズ時間の短縮（テスト用）

| 環境変数 | 意味 | 既定 |
| --- | --- | --- |
| `RONDO_TEST_PHASE_DIVISOR` | veryare の全フェーズの時間と、結果のあとにルームを閉じるまでの時間（3 分 / issue-70）を、この数で割る（2〜1000 の整数のときだけ有効） | 無し（本番の時間のまま） |
| `RONDO_PORT` | サーバーが待ち受けるポート | 3000 |
| `RONDO_WIDE_DEV` | `1` のときだけ、ルーム作成の `stage: 3`（広い屋敷だけ / issue-65）を受け付ける。ほかの値・無しなら、`stage: 3` は `invalid-settings` で断る | 無し（受け付けない） |

- 無い・正しくない値なら、短縮しない。本番（A1）では設定しない（`RONDO_WIDE_DEV` も、本番では設定しない）
- 縮めるのは、フェーズのタイマーと、撃つ間隔（issue-27）だけ。判定（状態機械）と、再接続猶予（10 秒 / ADR 0013）、ハートビート（issue-41）の時間は変わらない。撃つ間隔は、どれだけ縮めても 0 にはならない
- 縮めても、フェーズの順序と勝敗が変わらないことは、`server/test/rondo_server/games/timing_test.gleam` で確かめている

## シナリオ

| シナリオ | 人数 | 動き | 期待 |
| --- | --- | --- | --- |
| 時間切れで隠れ側の勝ち | 5 | A が立候補。隠れ側は準備移動で、玄関から別々の場所へ散らばる | 隠れ側4人が1位（逃げ切り）、鬼が2位。全員に届く。限定配信が宛先以外に届かない |
| 鬼の離脱で隠れ側の勝ち | 3 | A が立候補し、準備移動で退出 | 隠れ側2人が1位、退出した鬼も2位で結果に残る。退出した鬼には届かない |
| 人数が足りず不成立 | 2 | A が立候補し、カウント中に B が退出 | A が1位・score 0・「不成立」 |
| 被りによる全員失格で鬼の勝ち | 3 | A が立候補。B と C は玄関にとどまる（全員が玄関に現れるため、重なる） | 鬼が1位、隠れ側2人が2位（発見・失格・離脱）。全員に届く |
| ポーズの確定と一括配信 | 3 | 隠れ側 B がペイントフェーズに、塗らずにポーズだけを2回確定する（maleCrouch、femaleDance / issue-56）。C は確定しない | 確かめ「最初のポーズだけが届く」「確定しなかった人のポーズは null」が通る（探索の開始に鬼 A へ届いた一括配信で、B のポーズが maleCrouch、C が null）。時間切れで隠れ側の勝ち。全員に届く |
| ペイントの確定と一括配信 | 2 | 隠れ側 B がペイントフェーズに2回塗りを送る（issue-25） | 確かめ「最初のペイントだけが届く」が通る（探索の開始に鬼 A へ届いた一括配信で、B のペイントが1回目の色）。時間切れで隠れ側の勝ち。全員に届く |
| 壁越し・襖越しの射撃 | 3 | 部屋を1つ選び、B は壁際（r）、C は襖の内側（s）へ歩く。鬼 A は、壁の向こう（w）から B を撃ち、襖の前（c）で閉じたまま C を撃ち、襖を開けて C を撃つ（issue-29b） | 確かめ「壁越しの射撃は外れる」「閉じた襖越しの射撃は外れる」「開けた襖越しの射撃は当たる」が通る。時間切れで隠れ側の勝ち（B は逃げ切り、C は発見）。全員に届く |
| 平屋の壁越し・襖越しの射撃 | 3 | 作成時の設定で平屋を選び（`{ stage: 1 }`）、「壁越し・襖越しの射撃」と同じ手順を通す。マスは和室C と東の廊下の襖、和室C の北東の隅の壁（issue-45） | 同じ3つの確かめが通る。時間切れで隠れ側の勝ち（B は逃げ切り、C は発見）。全員に届く |
| 全員発見で鬼の勝ち | 3 | A が立候補。B と C は玄関から一直線の場所へ散らばり、探索の始まりに、玄関に現れた A が順に撃つ（issue-27） | 鬼が1位、隠れ側2人が2位（発見・失格・離脱）。全員に届く |
| 広い屋敷で時間切れ | 5 | 作成時の設定で広い屋敷だけを選び（`{ stage: 3 }` / issue-65）、「時間切れで隠れ側の勝ち」と同じ手順を通す | 確かめ「広い屋敷のステージと、+80 秒の探索時間」が通る（ステージの通知の幅が 20 m 以上、ルーム情報の探索時間が 120 秒）。隠れ側4人が1位、鬼が2位 |
| 広い屋敷で全員発見 | 3 | 広い屋敷だけで、「全員発見で鬼の勝ち」と同じ手順を通す | 同じ確かめが通る。鬼が1位、隠れ側2人が2位 |
| 広い屋敷の壁越し・襖越しの射撃 | 3 | 広い屋敷だけで、「壁越し・襖越しの射撃」と同じ手順を通す | 射撃の3つの確かめと、広い屋敷の確かめが通る。時間切れで隠れ側の勝ち（B は逃げ切り、C は発見） |
| 結果のあと、ルームが閉じる | 2 | A が立候補し、B が隠れる。時間切れで結果まで進め、結果のあと、閉じるまで（縮めた 3 分 = 9 秒）待つ（issue-70） | 結果に、閉じるまでの残り（`closesInMs` が 9000）が載り、時間がたつと、両方に `error` の `room-expired` が届く。B が1位、鬼が2位 |

- 壁越し・襖越しの射撃では、マス（c・s・r・w）を、届いたステージの通知から選ぶ（`bots/src/plan.ts` の `pickDoorShot`。割り当てられた部屋を文字の順に見て、襖と、壁で廊下に接するマスを持つ最初の部屋）。「廊下」は、部屋と別の領域で、襖が閉じていても玄関から着けるマス（骨格では廊下、平屋では東の廊下など / issue-45）。r と s は、被りの判定にかからないよう 0.8 m 以上離す。w から r へ撃つと壁の境だけを、c から s へ撃つと襖の境だけを越える（どちらも1マス先）。歩く道は、通れる境だけをたどる幅優先探索（`findPath`）。外れの原因（壁か、間隔・射程か）の区別は、サーバーの単体テストに任せ、ボットでは、つないだときの動きを確かめる。外れの確かめは、撃ってから 120 ms の間（縮めた撃つ間隔 150 ms の内側）に、隠れている一覧が変わらないこと
- 結果のあとに閉じるシナリオは、別の一覧（`expiryScenarios`）に置き、`make bots` は `allScenarios` の後に流す（`bots/src/main.ts`）。宣言と確かめ（`checkExpiry`）は `bots/src/expiryScenario.test.ts` が確かめる。閉じるまで待つので、このシナリオだけ約 15 秒かかる
- 広い屋敷のシナリオは、既存のシナリオ（`scenarios`）とは別の一覧（`wideScenarios`）に置き、`make bots` は両方を流す（`allScenarios`）。既存のシナリオの宣言の確かめ（`scenarios.test.ts`）は変えず、広い屋敷のシナリオは `bots/src/wideScenarios.test.ts` が同じ規則で確かめる。縮めた広い屋敷の探索は 6 秒（(40 + 80) 秒 ÷ 20）で、手順の時刻は既存のシナリオと同じ。広い屋敷の見本（`wideStages` の 3 種）で、隠れ場所 4 つと射撃のマスが選べることも確かめる
- 10種の骨格すべてで、`pickDoorShot` がマスを見つけることを、`bots/src/plan.test.ts` が確かめる（見本は `packages/contracts/src/fixtures/veryare-skeleton-stages.json`。サーバーの地図と一致することは、サーバーのテストが確かめる）
- サーバーは歩く速さを制限しない（性善説 / ADR 0035）。歩くのは1マスごとの移動の報告で、10種の骨格で最も長い道（61マス）でも、報告を送り終えるのに数ミリ秒しかかからない。縮めた準備移動（1 秒）・探索（2 秒）の中に収まる
- 全員が玄関に現れる（ADR 0032 / issue-29a）。隠れ側のボットは、届いたステージの通知から、玄関から一直線にたどれる別々の場所（玄関から 7 m 以内、互いに 0.8 m 以上離れる）を選んで動く（`bots/src/stage.ts` の `spreadSpots`）。一直線なので、サーバーの移動の規則で、そのまま着く
- 全員発見では、A は人間の鬼役として、契約の電文（game-event の `shoot`）で撃つ。撃つ間隔（3 秒）も 1/20（150 ms）に縮むので、間を空けても縮めた探索（2 秒）の中で撃ち終える。収まることは `bots/src/scenarios.test.ts` が、サーバーの既定値と縮め方（`bots/src/timing.ts`）から確かめる
- 鬼の離脱は、退出（leave-room）で起こす。切断で起こすと、猶予（10 秒）が縮めたフェーズより長く、先に時間切れになるため
- 限定配信（ADR 0021）: veryare は、鬼選出の途中で参加して鬼希望エリアの色が変わらないとき、参加した本人にだけ今の状態を送る。5人のシナリオで、3人目以降の参加がこれにあたる。宛先でないボットに game-state-to が届かないことと、1通以上を観測できたことを確かめる

## シナリオの足し方

`bots/src/scenarios.ts` に1件足す。

```ts
{
	name: "新しいシナリオ",
	bots: ["bot-a", "bot-b", "bot-c"],          // 先頭がルームを作る
	steps: [
		{ on: "joined", bot: "bot-a", action: { type: "touch-area" } },
		{ on: { phase: "preparation" }, bot: "bot-b", action: { type: "move", x: 1, z: 1 } },
	],
	receivers: ["bot-a", "bot-b", "bot-c"],     // game-ended が届くべきボット
	rankings: [                                  // 1位から順に
		{ bot: "bot-a", rank: 1, score: 1, details: details.oniWon },
		/* ... */
	],
	targeted: false,                             // 限定配信も確かめるなら true
},
```

- `on` は `"joined"`（全員がそろった直後）か、`{ phase, area? }`（そのボットにフェーズの通知が届いたとき）。時間ではなく通知を引き金にするので、フェーズ時間の縮め方に依らない
- `action` は `touch-area`（立候補）、`move`、`leave`（退出）、`stay`（何もしない）、`hide`（隠れ側として、`index` 番目の散らばる場所へ動く。隠れ側ごとに違う番号にする）、`go`（`pickDoorShot` で選んだマス `c`・`s`・`r`・`w` へ、`doors`（`"open"` か `"closed"`）の扱いで道を探して歩く）、`open-door`（選んだ襖を開ける報告）、`expect-hiding`（確かめ。`check` の名前、`target` のボット、`hiding` で、まだ隠れているはずか・見つかっているはずかを書く。落ちると、結果の表の「問題」に `check` の名前が出る）、`shoot`（鬼として撃つ。`target` はボットの名前か `null`）、`paint`（隠れ側として、`color` の点を1つ描いたストローク1本でペイントを確定する）、`expect-paint`（確かめ。探索の開始に届いた一括配信で、`target` のペイントが `color` のストロークか。落ちると `check` の名前が出る）。`delayMs` で、引き金から動くまで待てる足すときは `bots/src/scenario.ts` の `Action` と、`bots/src/runner.ts` の `act` に足す
- 書き間違い（参加していないボットを指す、など）は、`bots/src/scenarios.test.ts` が `make verify` で見つける

## 負荷・長時間・乱れた通信・不正な入力（issue-51）

同じボットの仕組みで、上限・同時負荷・乱れた通信・不正な入力・長時間の放置を試す。動かし方と結果は `docs/load-tests.md`（`./tools/load.sh limits|load|chaos|garbage|soak`）。

## 失敗したとき

- 表の「問題」に、どのボットに何が届かなかったか、どの行が違ったか（期待と実際）が出る
- 同じ種で流し直す: `make bots ARGS="--seed <表示された種>"`
- サーバーの出力は、端末に `make bots` の出力と一緒に出る
