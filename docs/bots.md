# ボット同士の対戦（issue-49）

ブラウザを使わず、契約（`packages/contracts`）の電文だけで動くボットを、実際の Gleam サーバーにつなぎ、veryare の最初から最後まで（入室 → 鬼選出 → 準備移動 → ペイント → 探索 → 答え合わせ → 結果）を自動で通す。

## 実行

```bash
make bots                        # 全シナリオ
make bots ARGS="--seed 123"      # 同じ種で再現する
make bots ARGS="--only 不成立"    # シナリオ名の一部で絞る
```

- Gleam サーバーを **3300 番**で起動し（開発用の 3000 番とは別）、終わったら止める
- その間だけ、フェーズ時間を **1/20** に縮める（環境変数 `RONDO_TEST_PHASE_DIVISOR=20`）。1 シナリオは数秒で終わる
- 結果は表で出る。終了コードは、全部成功で 0、失敗があれば 1（サーバーが起動できないときは 2）
- `make verify` には含めない（サーバーの起動を伴うため）。ボットの判定の部分（結果の検査、シナリオの宣言の整合、クライアント）は単体テストにして、`make verify` で動く

## フェーズ時間の短縮（テスト用）

| 環境変数 | 意味 | 既定 |
| --- | --- | --- |
| `RONDO_TEST_PHASE_DIVISOR` | veryare の全フェーズの時間を、この数で割る（2〜1000 の整数のときだけ有効） | 無し（本番の時間のまま） |
| `RONDO_PORT` | サーバーが待ち受けるポート | 3000 |

- 無い・正しくない値なら、短縮しない。本番（A1）では設定しない
- 縮めるのは、フェーズのタイマーと、撃つ間隔（issue-27）だけ。判定（状態機械）と、再接続猶予（10 秒 / ADR 0013）、ハートビート（issue-41）の時間は変わらない。撃つ間隔は、どれだけ縮めても 0 にはならない
- 縮めても、フェーズの順序と勝敗が変わらないことは、`server/test/rondo_server/games/timing_test.gleam` で確かめている

## シナリオ

| シナリオ | 人数 | 動き | 期待 |
| --- | --- | --- | --- |
| 時間切れで隠れ側の勝ち | 5 | A が立候補。隠れ側は準備移動で、玄関から別々の場所へ散らばる | 隠れ側4人が1位（逃げ切り）、鬼が2位。全員に届く。限定配信が宛先以外に届かない |
| 鬼の離脱で隠れ側の勝ち | 3 | A が立候補し、準備移動で退出 | 隠れ側2人が1位、退出した鬼も2位で結果に残る。退出した鬼には届かない |
| 人数が足りず不成立 | 2 | A が立候補し、カウント中に B が退出 | A が1位・score 0・「不成立」 |
| 被りによる全員失格で鬼の勝ち | 3 | A が立候補。B と C は玄関にとどまる（全員が玄関に現れるため、重なる） | 鬼が1位、隠れ側2人が2位（発見・失格・離脱）。全員に届く |
| 壁越し・襖越しの射撃 | 3 | 部屋を1つ選び、B は壁際（r）、C は襖の内側（s）へ歩く。鬼 A は、壁の向こう（w）から B を撃ち、襖の前（c）で閉じたまま C を撃ち、襖を開けて C を撃つ（issue-29b） | 確かめ「壁越しの射撃は外れる」「閉じた襖越しの射撃は外れる」「開けた襖越しの射撃は当たる」が通る。時間切れで隠れ側の勝ち（B は逃げ切り、C は発見）。全員に届く |
| 全員発見で鬼の勝ち | 3 | A が立候補。B と C は玄関から一直線の場所へ散らばり、探索の始まりに、玄関に現れた A が順に撃つ（issue-27） | 鬼が1位、隠れ側2人が2位（発見・失格・離脱）。全員に届く |

- 壁越し・襖越しの射撃では、マス（c・s・r・w）を、届いたステージの通知から選ぶ（`bots/src/plan.ts` の `pickDoorShot`。割り当てられた部屋を文字の順に見て、襖と、壁で廊下に接するマスを持つ最初の部屋）。w から r へ撃つと壁の境だけを、c から s へ撃つと襖の境だけを越える（どちらも 1 m）。歩く道は、通れる境だけをたどる幅優先探索（`findPath`）。外れの原因（壁か、間隔・射程か）の区別は、サーバーの単体テストに任せ、ボットでは、つないだときの動きを確かめる。外れの確かめは、撃ってから 120 ms の間（縮めた撃つ間隔 150 ms の内側）に、隠れている一覧が変わらないこと
- 10種の骨格すべてで、`pickDoorShot` がマスを見つけることを、`bots/src/plan.test.ts` が確かめる（見本は `packages/contracts/src/fixtures/veryare-skeleton-stages.json`。サーバーの地図と一致することは、サーバーのテストが確かめる）
- サーバーは歩く速さを制限しない（性善説 / ADR 0035）。歩くのは1マスごとの移動の報告で、10種の骨格で最も長い道（61マス）でも、報告を送り終えるのに数ミリ秒しかかからない。縮めた準備移動（1 秒）・探索（2 秒）の中に収まる
- 全員が玄関に現れる（ADR 0032 / issue-29a）。隠れ側のボットは、届いたステージの通知から、玄関から一直線にたどれる別々の場所（玄関から 7 m 以内、互いに 0.8 m 以上離れる）を選んで動く（`bots/src/stage.ts` の `spreadSpots`）。一直線なので、サーバーの移動の規則で、そのまま着く
- 全員発見では、A は人間の鬼役として、契約の電文（game-event の `shoot`）で撃つ。撃つ間隔（3 秒）も 1/20（150 ms）に縮むので、間を空けても縮めた探索（2 秒）の中で撃ち終える。収まることは `bots/src/scenarios.test.ts` が、サーバーの既定値と縮め方（`bots/src/timing.ts`）から確かめる
- 鬼の離脱は、退出（leave-room）で起こす。切断で起こすと、猶予（10 秒）が縮めたフェーズより長く、先に時間切れになるため
- 限定配信（ADR 0021）: veryare は、鬼選出の途中で参加して鬼希望エリアの色が変わらないとき、参加した本人にだけ今の状態を送る。5人のシナリオで、3人目以降の参加がこれにあたる。宛先でないボットに game-state-to が届かないことと、1通以上を観測できたことを確かめる

## シナリオの足し方

`bots/src/scenarios.ts` に1件足す。

```ts
{
	name: "新しいシナリオ",
	bots: ["bot-a", "bot-b", "bot-c"],          // 先頭がルームを作る
	steps: [
		{ on: "joined", bot: "bot-a", action: { type: "touch-area" } },
		{ on: { phase: "preparation" }, bot: "bot-b", action: { type: "move", x: 1, z: 1 } },
	],
	receivers: ["bot-a", "bot-b", "bot-c"],     // game-ended が届くべきボット
	rankings: [                                  // 1位から順に
		{ bot: "bot-a", rank: 1, score: 1, details: details.oniWon },
		/* ... */
	],
	targeted: false,                             // 限定配信も確かめるなら true
},
```

- `on` は `"joined"`（全員がそろった直後）か、`{ phase, area? }`（そのボットにフェーズの通知が届いたとき）。時間ではなく通知を引き金にするので、フェーズ時間の縮め方に依らない
- `action` は `touch-area`（立候補）、`move`、`leave`（退出）、`stay`（何もしない）、`hide`（隠れ側として、`index` 番目の散らばる場所へ動く。隠れ側ごとに違う番号にする）、`go`（`pickDoorShot` で選んだマス `c`・`s`・`r`・`w` へ、`doors`（`"open"` か `"closed"`）の扱いで道を探して歩く）、`open-door`（選んだ襖を開ける報告）、`expect-hiding`（確かめ。`check` の名前、`target` のボット、`hiding` で、まだ隠れているはずか・見つかっているはずかを書く。落ちると、結果の表の「問題」に `check` の名前が出る）、`shoot`（鬼として撃つ。`target` はボットの名前か `null`）。`delayMs` で、引き金から動くまで待てる足すときは `bots/src/scenario.ts` の `Action` と、`bots/src/runner.ts` の `act` に足す
- 書き間違い（参加していないボットを指す、など）は、`bots/src/scenarios.test.ts` が `make verify` で見つける

## 失敗したとき

- 表の「問題」に、どのボットに何が届かなかったか、どの行が違ったか（期待と実際）が出る
- 同じ種で流し直す: `make bots ARGS="--seed <表示された種>"`
- サーバーの出力は、端末に `make bots` の出力と一緒に出る
