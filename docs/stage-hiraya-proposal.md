## 1. 推奨案: 実際の間取りをそのまま写す（部屋どうしの襖を認める）

平屋の部屋（和室3つ、ダイニング、キッチン、押入れ、水回り3つ）を、それぞれ1つのスロット（隠れ場所の区画）にする。襖は、実際の位置にある10組（引違い戸 4枚戸 4組、2枚戸 2組、腰付障子 4枚戸 4組）をそのまま使い、部屋どうしをつなぐ襖も認める。片開き戸・ガラス戸・掃き出し窓は、開閉しない「いつも開いている戸」、玄関の戸と勝手口は「いつも閉じている戸」とする。

推奨の理由:

- 平屋は和室A・B・C とダイニングが襖で直接つながる田の字型で、廊下から入れる襖は和室Cの東の1つだけ。ADR 0032 の「部屋どうしを直接つながない」「襖はスロットごとに1つ」に合わせると、半分以上の襖を開かない飾りにするか、部屋を通路として扱うことになり、平屋を選んだ意味（田の字の回遊）が薄れる
- 襖を閉じると部屋が仕切られ、開けると回り込める。探索の始めに全部閉じる（ADR 0033）と、鬼は襖を開けながら複数の道を選ぶことになり、探索に幅が出る
- 到達できるかは、ADR 0032 の「廊下に面している」ではなく、玄関から戸をたどる探索（幅優先）で確かめられる。この平屋は固定なので、テストで1回確かめれば足りる

### glb の座標から、ゲームの座標へ

- ゲームのステージの座標は、glb の座標をそのまま使う（x と z、単位 m、Y が上）。拡大・回転・平行移動はしない。待機ルームは別の空間なので、重ならない
- マスとの変換: マス（列 c、行 r）の範囲は x = −6.225 + 0.3c 〜 +0.3、z = −0.275 + 0.3r 〜 +0.3。中心は +0.15。逆に、位置 (x, z) のマスは c = floor((x + 6.225) / 0.3)、r = floor((z + 0.275) / 0.3)
- 床の高さ（y）: 畳・板の間 0.6 m、玄関の土間 0.4 m、縁側 0.55 m、地面 0。サーバーは高さを持たない（いまと同じ）。クライアントは床の高さに立たせる

## 3. 既存の仕組みとの食い違い

| 既存の規則・仕組み | 平屋 | 推奨案での扱い |
| --- | --- | --- |
| 1マス 1 m（`Cell` は整数の m、リスポーンは +0.5 m） | 1マス 0.3 m が要る | ステージに「1マスの大きさ」と「原点」を持たせる |
| スロットは大 4 × 6 m・小 2 × 1 m | 和室 3.7 × 4.6 m、ダイニング 3.7 × 3.75 m、押入れ 3.7 × 1.35 m など | 固定ステージは大きさの決まりを外す |
| 部屋タイプはランダムに割り当て（和室 8〜12、押入れ 3〜5） | 和室3、押入れ1、ほかに台所・水回り | 固定ステージは割り当てをしない（部屋は決まっている）。構成の決まりも外す |
| スロットは廊下に面する | 廊下に面するのは和室Cと洗面所・トイレ。押入れ・ダイニング・キッチン・風呂は面しない | 「玄関から戸をたどって着ける」に置き換える |
| 襖はスロットごとに1つ | 和室Aは4（押入れ2、ダイニング、広縁）、和室Bは3、和室Cは4、ダイニングは3（襖2、ガラス戸1） | 1つの決まりを外す |
| 部屋どうしを直接つなぐ襖は無い | 押入れ-A、A-ダイニング、B-C、C-ダイニングの4か所（ほかに戸で、キッチン-ダイニング、風呂-洗面所） | 認める |
| 廊下・縁側・玄関はひとつながり | 東の廊下・玄関と、広縁・縁側は、部屋を通らないとつながらない | 「全領域に、襖を開ければ玄関から着ける」に置き換える |
| 縁側は1箇所（`=`）で、庭側に見えない壁 | 内側の広縁と外の縁側の2つで、掃き出し窓でつながる | 広縁を別の記号（`:`）にし、縁側だけに見えない壁を置く |
| 戸は襖だけ（`+` のマスと、その隣のスロットのマス） | 片開き戸・ガラス戸・掃き出し窓・戸の無い通り抜け・閉じた玄関の戸がある | 戸を「襖」「いつも開いている」「いつも閉じている」の3種類にし、地図とは別の一覧で持つ |
| 見通し（`sight.gleam`）は、廊下などの開けた場所（Open）と部屋（Room）の境の、スロットの襖だけを見る | 部屋どうしの襖、いつも開いている戸がある | 戸の一覧から、境ごとの「通す・通さない」を引くようにする（開いている襖と、いつも開いている戸は通す） |
| 鬼 CPU は、部屋の最初の襖の内側を目的地にする | 部屋の入口が複数 | 着ける入口のうち、近いものを目的地にする |
| 移動範囲は中心から ±5 m の仮の正方形 | 建物 11 × 12 m ＋ 縁側 | 上の矩形の集合（またはマス）にする |
| 骨格は10種からランダム | 固定の1種 | ステージの選択（ADR 0031 の roomOptions）で「平屋」を選ぶ。ランダム間取りの10種とは別のステージとして持つ |

## 4. 対応案の比較

| | 案1（推奨）: 実際の間取りをそのまま写す | 案2: ADR 0032 の規則に寄せる | 案3: 襖を開けっぱなしにする |
| --- | --- | --- | --- |
| 考え方 | 部屋ごとにスロット。襖10組を実際の位置で使い、部屋どうしの襖も認める | 部屋の入口の襖を1つに絞り、残りは開かない飾り（はめ殺し）にする。和室Cを通り道（廊下扱い）にして、廊下と広縁をつなぐ | 襖は飾りとして全部開いた姿で置き、開閉しない。部屋は見通しの区切りにならない |
| スロット（隠れ場所） | 9（和室A・B・C、ダイニング、キッチン、風呂、洗面所、トイレ、押入れ）＋通り道（廊下・広縁・縁側）でも隠れられる | 6 前後（和室A（押入れ付き）、和室B（床の間付き）、ダイニング（キッチン付き）、洗面所（風呂付き）、トイレ）。和室Cは通り道 | 9（案1と同じ）。ただし見通しが利く |
| 答え合わせで開く襖 | 10組すべて | 動く襖だけ（和室A-広縁、和室B-和室C、和室C-ダイニング、押入れの2組 の5組前後）。はめ殺しは閉じたまま | 無し（もとから開いている） |
| 探索の難しさ | 中〜高。田の字で回り込める道が複数あり、襖を開ける順番が効く。廊下から入れる襖は和室Cの1つだけなので、鬼は奥へ進むほど襖を開ける | 中。入口が1つずつで、各部屋は行き止まり。ADR 0032 の他のステージと似た探し方になる | 低（鬼に有利）。開けた家の中を見通せる |
| 被り判定への影響 | なし（位置だけで判定）。隠れ CPU を置くマスが増える | なし | なし |
| 既存コードの変更量 | 中: `stage.gleam`（1マスの大きさ・原点、戸の3種類と一覧、固定ステージの読み込み、検算の切り替え）、`sight.gleam`（戸の一覧から通す・通さない）、`oni_cpu.gleam`（入口の選び方）、`game.gleam`（移動範囲）、`room.gleam`（ステージの選択）。クライアントのステージの表示 | 小〜中: `stage.gleam`（1マスの大きさ、固定ステージの読み込み、大きさ・構成の検算の除外）、`game.gleam`（移動範囲）。見通しと鬼 CPU はほぼそのまま。はめ殺しの襖の見せ方 | 小: 襖の開閉が無い。見通しは壁だけ。移動範囲と固定ステージの読み込みだけ |
| ADR の変更量 | 新しい ADR（固定ステージ「平屋」）1本。ADR 0032 の「部屋どうしを直接つながない」「襖はスロットごとに1つ」「大きさ・構成」を、固定ステージには当てはめないと書く | 新しい ADR 1本（固定ステージの大きさ・構成の例外だけ）。はめ殺しの襖の扱いを書く | 新しい ADR 1本。ADR 0033（探索の始めに襖を閉じる・答え合わせで開く）を、このステージには当てはめないと書く |

推奨は案1。平屋を選んだ意味（襖で仕切られた田の字の部屋を、開けながら探す）が最も残り、変更は「戸を一覧で持ち、玄関からたどって確かめる」に一般化する形でまとまる。案2は規則を守れるが、はめ殺しの襖が多く、見た目と遊びが食い違う。案3は実装は軽いが、ADR 0033 の襖の遊びを捨てる。

## 5. 書き起こしたときのテスト（案）

- 地図: 行の長さがそろっている。記号が決めたものだけ。`@`・`=`・`:` がそれぞれひとつながり
- 到達: 襖を全部開けたとき、玄関から `~` 以外の全マスに着ける。全部閉じたとき、着けるのは玄関・東の廊下・洗面所・風呂・トイレだけ
- 戸: どの戸の組も、2つの異なる領域の境にある（隣り合うマスで、記号が違う）。襖は10組で、片開き戸・玄関の戸・勝手口は襖でない
- 戸と開口: 各戸の組の範囲が、`doors-fbx.tsv` の開口（中心と幅）と、0.3 m 以内で合っている。襖の候補の10組がすべて地図の戸に対応する
- 壁と断面: 地図の領域の境（戸を除く）が、y = 1.0 m の断面図の壁の線と、0.15 m 以内で合っている（断面図の壁の線の上にある境の割合で測る）
- 移動範囲: `~` 以外の各マスの中心が、床のノード（部屋床・玄関床・お風呂の床・縁側）の矩形の内側にある。移動範囲の外へ出る移動は、境で止まる
- 縁側: 縁側（`=`）と庭（`~`）の境すべてに、見えない壁の印がある。玄関の戸と勝手口からは外に出られない
- リスポーン: (4.7, 11.3) が玄関のマスにあり、家具（下駄箱）の外接箱と重ならない
- 座標: マスと glb の座標の変換が往復で一致する（マスの中心 → 位置 → マス）
- 見通し: 閉じた襖の向こうの部屋は見えない。いつも開いている戸の向こう（例: キッチンからダイニング）は見える
- 鬼 CPU: 固定ステージで、全スロットを巡れる（シミュレーションで、平屋を骨格の1つとして回し、異常が0件）
- 隠れ CPU: 置くマスがスロットの中にあり、家具の外接箱と重ならない（家具の当たりは issue-29 で持つ場合）

## 6. 決まったこと（2026-10-04）

- 案1（実際の間取りのまま、部屋どうしの襖も認める）を採用する（ADR 0039）
- 時期: マイルストーン1（10/10〜12）までは、ランダム間取りの10種で通す。平屋は、その後に固定ステージとして足す。間に合わなければ、ランダム間取りのまま出す
- 掃き出し窓（広縁と縁側の間）は、いつも開いている
- キッチンとダイニングのガラス戸は、いつも開いている
- 床の間は、見た目だけで、隠れる機能を持たない（和室Bのマスに含め、隠れ CPU を置かない）
- 玄関（土間）は、リスポーン位置であり、隠れ場所に数えない
- 家具の当たりは、今回は扱わない（通り抜けられる）
- 移動の仕組み: 0.3 m の格子で歩けるマスを持ち、壁と閉じた戸は、マスとマスの境を通れない辺として表す。襖が開いたら、その辺が通れるようになる。サーバーとクライアントの両方で、同じデータと同じ規則を使う（ADR 0039）

実装は、次の3つに分ける。

- issue-44: ステージの表現と、歩ける格子（サーバー）。戸の一覧、到達、移動の止まり方、移動範囲、襖の開閉の状態、リスポーン
- issue-45: 見通しと、鬼 CPU・隠れ CPU の、戸の一覧への一般化
- issue-46: クライアントの表示（issue-43 の素材配信で平屋の glb を読み、襖の開閉と、屋根・天井の切り替え。素材が無ければ仮の表示）

ステージの選び方は、ルーム作成時の設定（ADR 0031 のステージ選択、roomOptions）を提案している。ロビーに選択肢を出すのは issue-46 で、それまでは出さない（通っていない機能は選択画面に出さない）。
